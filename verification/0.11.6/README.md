## 修复及实际能力

- 补齐新增几何/recipe helper的编译依赖身份，避免正常build漏记真实运行模块。独立回归曾暴露遗漏，修复后通过。
- `component.topology`注册厚弧箭头真实PNG/SVG预览、示例作者与来源哈希；Storybook下载调用与预览同为`arrow-ring`，其他拓扑仍在完整组件合同中。修复了“有API但无法先看图取用”的交接缺口。
- 厚弧路径按3–6阶段与正反方向计算。独立检查直接采样输出路径，验证各曲线和箭头属于互斥角域、整块标签落在实际填充内；不把外接矩形交叉误当曲线碰撞。长标签/小容器显式失败，不缩字。自动文字颜色对当前填充保持对比度≥4.5；显式覆盖按原值保留并报告对比度。
- 三个新recipe经正常`library → compose → recipe_source → build computed`重放。增加条目、加长事实会重新测量；故意损坏缓存frame也不会被使用。超容量、非法几何/字号覆盖和文字溢出拒绝。
- `capability-platform`以实际测量的panel frame计算汇流/分流。原生PPT中3个输入分支、2个输出分支、2条bus及2条trunk绑定完整，箭头落在平台和输出节点；无图片拓扑。原先只连容器中心的歧义已修复。
- 实际完整Storybook验收先发现搜索索引遗漏设计身份（0项），补字段后又暴露说明文字误匹配（173项）。已将`presentation_role`和`selection_guidance`贯通轻量索引与前端过滤；完整已注册身份查询在library和Storybook均走精确匹配，普通词继续全文检索。真实Chromium回归使用全部内置混合目录（含170个结构模板、3个设计组合及图表/图标），`DESIGNED-COMPOSITION`准确返回3张卡并逐卡打开正确recipe请求，`structural-template`返回170项；两种普通说明词分别返回3/170项，无匹配词返回0项。没有改DOM或绕过页面CSP。旧的仅recipe测试未覆盖实际混合目录，现已替换，保留两次验收失败记录。Storybook、library及浏览器共22项通过，JS语法检查通过。
- 旧资源样例移除不同单位的独立满高单值柱，改为有明确查阅任务的索引；保留200人、12区域、80项目、4环节、3类型，不造基准或排名。
- 修正公开重建命令：先解析绝对输出目录，避免`../`路径被写入边界拒绝。
- 最终身份检索修复进入保守compiler指纹后，公开7页及3页样例均沿最终generated包正常重建，并逐项核对收据中的全部compiler_files。全包部件名称一致；7页样例51个部件逐字节一致，3页样例22个部件逐字节一致，余下8/4个部件仅生成时间与`p14:creationId`不同。预览继承依据与源PPTX哈希已写入两份样例manifest，不将继承预览说成末次重新渲染。

## 成图观察与边界

默认深蓝/蓝/青绿/灰蓝使阶段和分区有区分，又保持正文统一。第6页厚弧箭头能直接读出闭环，右侧开放说明通过标题、基线和组距区分能力与适用范围；第7页三列逐行对齐，共享底座覆盖全宽。三种新组合分别表达并列解释、有序阶段、多入一/一出多；实际图面未见明显遮挡或丢字。前两种示例文字较少，仍有较大空白，这是局部组件示例，不能当成业务稿最少页数或高信息密度的证明。
