# 使用总入口与两个内容 Skill

完整仓库的 [SKILL.md](../SKILL.md) 根据任务协调生成、修订、审计和 PPT 制作接续。两个内容 Skill 也可以各自整体安装，按下文使用。

## 确认内容后继续制作 PPT

向总入口说明需要PPT、实际材料、听众、沟通目的及输出位置。助手先形成唯一当前《汇报方案.md》，取得真实内容确认后，沿[包内制作方法](../skills/how-to-report/references/ppt-production.md)继续。已有适用确认和有效约束直接沿用。

```text
请读取 [仓库实际位置]/SKILL.md，依据 [实际资料] 制作汇报PPT。
汇报对象和目的为 [本次沟通任务]。
先交我确认内容，确认后使用自有模板继续制作，保存到 [输出目录]。
```

从[自有模板索引](../skills/how-to-report/assets/templates/README.md)选择实际关系与内容量适合的页型。逐模板AI说明提供内容/config字段、最短最长字符数、variants、tokens及用法。全局画布、标题位置、页眉页脚、颜色字体和间距由tokens约束，实例按实际输入生成。

参数绑定后运行包内SVG检查、原生PPTX导出及Theme/结构回读，按[依赖声明](../skills/how-to-report/runtime/ppt-engine/requirements.txt)准备所需环境。模板与图标来自自有资产，PPT-Master作为制作技术和方法来源。

用户要保留原PPT设计时，提供原件及允许修改范围，先核实当前编辑能力并保留原件对照。模板创建从用户素材提取结构和tokens，建立参数、variants、AI说明及逐variant检查。缺依赖或制作失败时保留当前稿、有效确认和真实续接点，修复后继续。

交付包含实际 PPTX 位置、内容对照结果及本次检查状态。渲染、结构、内容一致性和 PowerPoint 编辑分别记录实际范围。原生图表的改数要求、表格改值或形状编辑按实际需要说明，由对应编辑动作验证。详细规则见[内容交接方法](../skills/how-to-report/references/ppt-handoff.md)。

## 内容生成、分析与审计

提供已有材料、已知的汇报对象和场景，以及当前想解决的问题即可。未确定目标时可先讨论；明确目标时直接说；仅需局部修改时明确范围。新完整汇报还会确认具体参会职责、决定/否决范围、影响关系与本场判断；不知道时共同澄清，不能凭头衔赋权。已有确认沿用，不需要先编一份自己也不确定的目标表。

创建或梳理：

> 请用 how-to-report。我要在[场合]向[对象]汇报，材料是[路径]。我想解决[已知问题]。请给出具体建议页数、页序和每页可直接使用的内容，保存为[输出位置]/汇报方案.md。对会改变主线的重要未知再向我确认。

局部修改：

> 请只修改[文件/段落]中的[问题]，保留其余主线和事实。

独立审计：

> 请用 report-audit，先读[实际稿件]，再结合[要求与原资料]审查。指出有依据的问题、影响和修复方向；仅审计，不覆盖原件。

完整材料默认交付一份`汇报方案.md`。开头简短说明本次主材料共几页、讲述顺序；封面和结束页若采用则计入，备查页单列。随后逐页给出标题和可直接使用的正文、必要数据与条件。它应当足以交给用户或下游制作，不是只有讲稿，也不是“第1页讲背景”式空大纲。可参考[完整合成示例](../skills/how-to-report/assets/examples/report-proposal.md)：结合听众已知内容，交付两页具体正文；页数由这组输入决定。

给汇报者的安排与给听众的正文分别呈现，来源和未决事项按需附上。若只要口头稿、独立阅读稿或先讨论思路，直接说明即可，Skill按该形式交付。只改一句话或一页时，给出可直接替换的结果，增删或合并页面时同步页数和页序。已有文件名可以沿用。PPT 制作由总入口在实际内容确认后接续，逐页内容仍由内容主线负责。

两包整体复制即可分别使用；真实材料与输出在安装目录之外。文件/计算/结构工具按任务需要使用，短任务不要求Run或Python。重要数值仍应有实际复核；没有工具或材料时说明具体未完成项，不补造结果。

领域知识需要适用授权，同范围已有授权不反复询问。离线方法不能代替真实项目事实。用户画像只保存显式确认的偏好与经历，本次指令优先。

## 持续修改与文件组织

继续在同一会话指出“只改第2页”“补充了新数据”或“改为给首次参会者讲”，Skill沿用仍适用的目标和内容，按影响修改。新事实联动相关标题和结尾；局部措辞不无故重排全篇。历史审计结论不能自动转成新版通过。

默认只需一个文件：

```text
本次汇报/
└─ 汇报方案.md
```

复杂续接时按需增加`工作记录.md`；独立审计放`审计/`，被审版本或重要交付留在`历史/`。不提前创建空文件。已经登记或被审计绑定的版本保留原字节，新内容另存或登记新版本；审计引用可复取的准确版本。Run是可选的另一种记录契约，采用后沿用其布局，不再维护重复状态。

《汇报方案.md》先有简短安排，再有第1页至第N页的全部内容，末尾按需列待确认与来源。真正影响判断的条件留在页面正文，工作记录不保存模型私有思维过程。先分析可只交`汇报思路.md`；用户明确另要演讲稿才增加第二份交付。换会话时提供最新采用的文件及必要已确认要求，不能依赖宿主自动恢复全部历史。

内容不清楚时，可直接指出读完还不知道什么，例如“我看懂了模块名，但不知道业务人员怎样用”。Skill按困难重组实际内容；不会要求你先学会一套写作术语。局部修改直接交替换结果，示范和研究说明不例行混入听众正文。

## 真实子代理与缺件

定向挑战和独立审计必须由真实子Agent执行。主Agent按已确认职责和重要未决判断派发少量相关任务，统一查算、回应与改稿；挑战者只返回问题，不替作者交答案。不同独立职责分别委派，可分批。没有工具或上下文隔离能力时相应环节未完成，不主Agent串行假扮、不私调模型API。

审计先让独立执行者只读正文，收到初读后再给目标、原资料和必要作者解释。执行者不能继承完整创作历史而自称独立；实际已由宿主委派的审计者直接工作，不再递归委派本角色。其他独立分析可选并行或串行，主Agent维护唯一当前稿。

现有资料先读并计算。确实缺本次事实时，会说明具体角色的问题、最小补件或替代输入、支持哪项判断和不补的边界。你可以部分补充或拒绝；必要条件仍须如实保留，可用内容照常交付。专业知识用于分析，不代造组织规则、收益、价格或听众偏好。
