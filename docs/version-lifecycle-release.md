# 0.3.1：明确选版与真实复核后的结果接纳

更新：2026-10-28。包版本0.3.1；基础 Run契约0.1，知识内容0.1.1均保留。新增可选 `version_state` 扩展0.1，不要求旧 Run 迁移。

本文保留0.3.1实现范围；当前0.4.0的HTML能力见[本版说明](html-runtime-release.md)。

## 新增能力

[版本助手](../skills/how-to-report/scripts/report_versions.py)将四个动作分开：实际文件追加登记、明确选择本次采用的版本、凭真实检查记录接纳产物、只读检查当前适用性。操作和完整换版示例见[随包方法](../skills/how-to-report/references/version-lifecycle.md)。

| 情况 | 本版行为 |
|---|---|
| 登记材料V2，尚未选择 | 保留V1选择，不以最大版本号代替用户决定 |
| 明确改用V2，旧报告仍依赖V1 | 显示待复核及旧接纳失配，保留历史报告和Check |
| 真正修订报告并完成新检查 | 登记新产物及依赖、明确选择、再凭精确目标Check记录接纳 |
| 相关材料/说明/检查详情（含依赖节点引用的校核依据）改变，或选版切走再切回 | 旧接纳不能直接继续使用；变更后的上下文不能复用已接纳过的旧Check |
| 无关分支的选版改变 | 不传播为当前结果的依赖；公开全局范围说明改变仍需重新核对 |

工具不生成报告、不执行语义检查、不修改历史图的 `verified/completed` 或旧 Check 的 `pass`。接纳只表示保存的声明与本地证据仍匹配，不能证明来源真实、依赖完整、独立审计或最终可发布。

## 数据与写入边界

`run.json` 保存有序选版决定和接纳指纹；正文、快照和旧记录留在 Run 内。每次修改要求最新记录哈希，使用合作锁、独占文件和原子记录替换。冲突拒绝覆盖；中途失败保留可核查文件，并说明是否提交。该机制不锁住任意外部编辑者或整个文件系统，也不提供自动崩溃恢复。

基础 `validate_run.py` 保留原样，只检查Run0.1。`report_versions.py inspect` 分别给出结构、扩展及产物当前性；`report_run.py inspect` 在扩展存在时展示这些结果。独立审计仍可直接核对实际记录和原始材料，不依赖生成包，不执行选版或接纳写操作。

本版采用保守接纳规则：同一精确目标有任何 `fail/not_run/not_assessable` 检查就拒绝接纳。不能删旧失败记录换通过；解决后的新稿使用新版本与真实新Check。同ID的旧新版对照可合法保存在普通Run中，但本工具尚不支持混合历史依赖闭包的自动接纳；应人工审查，不将工具边界判成稿件错误。远程或空/不可读的证据也不能取得本地接纳。

## 验证与下一步

工程验证覆盖版本变化、传递依赖与无关分支、错误检查/指纹/写入边界，并包含实际打包后搬迁、`python -I`、原件移走与只读检查。实际命令和结果记录于任务 `validation/version-lifecycle-*`，以最终独立检查回执为准；这里不预填测试数量。Python3.10是最低语法目标，实际运行版本以回执为准。

没有运行新模型案例；0.2.4/0.3.0/0.3.1均没有新的模型行为证据。旧冻结包和用户产物不变，大批量模型测试仍交用户执行。工具不会自动取得可选Knowledge或画像许可。

这补上 B/D 的可执行基础，尚未完成实际宿主中的持续使用、依赖声明与正文的一致性验证、局部重算/任务执行和完整恢复流程。0.4.0已增加有界的真实16:9 HTML工具；模型页面语义和正式B0/B1/B2仍待验证。完整V1仍按范围粗估40–50%，不是质量、测试通过率或工期比例；详见[进度与剩余差距](v1-progress.md)和[开发计划](development-plan.md)。
