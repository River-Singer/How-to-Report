# 0.7.2 开发与验证计划

保留四项生成工作和独立审计。0.7.1已具备接近失败情境的规则与示范，本轮调整它们怎样作用于实际成稿，不把重复追加原则当新能力。

- 当实际稿仍是分类目录、改写只换词或部分请求更新时，按当前困难调用示例，完成当前片段的实际重组，检查听众是否得到所需回答。
- 重编现有连续改稿例，展示失败稿、具体理解缺口、取舍和候选改稿；不同内容允许不同路线，够用就停止示范。
- 修订保留尚未完成的责任、期限及条件，先按实际页序定位；没有资料不能改成事情没有发生。
- 审计核对自己的解释、影响、行动建议和替换句。区分必要、充分条件及可以作承诺，不以换词维持错误指控。

研究只提供设计依据，未直接证明LLM效果。方法按需、少量离线背景可查，不把全部文献常驻输入；不扩展Graph/Run或恢复视觉生成。

[四组输入](../evaluation/content-0.7.2/README.md)各3轮，共12轮：听众取舍及局部标题、部分更新与实际末页、不同材料的选项比较/用途变化、独立审计。公开输入全为合成；私有项目交接留在用户工作区。已知回归与开发侧迁移试测分别标示，没有匹配基线或独立保留集支持提升率。

各组用同一真实会话，逐轮释放材料。审计先正文、后来源、再作者说明；操作日志与受众输入分离。方法文件读取有宿主轨迹则记录，没有就写未知，不能由输出倒推一定没读。冻结前先立编辑参照，允许合理替代及显式修正参照。

[本版工程记录](../verification/0.7.2/README.md)只记录实际执行的检查；[0.7.1工程记录](../verification/0.7.1/README.md)保持历史身份。工程检查验证打包、引用、来源与兼容，用户模型测试检查真实内容，二者分开。
