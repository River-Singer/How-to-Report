# 0.6.0 开发与验证计划

2026-10-30用户变更目标，当前工作以[内容范围](content-scope.md)为准。旧HTML建设路线结束；以下是工程建设顺序，不是每次汇报必须经过的流程。

1. **重组内容方法。** 从当前问题进入目标探索、区分、论证、沟通方式与叙事；给汇报者的取舍说明和给听众的正文分开。保留有用动作，减去固定配额、渲染终点和不必要记录。
2. **拆清发布范围。** 视觉实现退出两个默认包；日期与数值能力保留，通用Run/版本/来源工具继续按需。当前安装包应在无浏览器环境下完整交付内容。
3. **提供可用内容示例与离线方法。** 不把长研究全文加入主入口，不以来源链接代替可用本地方法；案例只解释机制，不作为唯一成稿答案。
4. **工程复核后交用户测试。** 核对包、引用、数值和历史保护；准备4项当前内容设计以及新输出目录，批量模型生成、审计、修订由用户执行。

模型验证看相同材料在不同目标下是否实质改变主线，明确目标时是否少问，证据不足时是否既诚实又有用，角色或时长变化时是否重组内容。可选普通提示与Skill对照需同模型、同输入、同工具条件；不要用“更短”本身证明更好。

结果评审后按实际失效点迭代，不恢复固定模板，也不自动扩大测试批次。旧67项设计和历次输出保留为历史输入与证据；旧视觉门槛不再阻塞新内容方向。当前状态见[范围状态](v1-progress.md)。
