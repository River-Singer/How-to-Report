# 0.7.3 开发与验证计划

保留四项生成工作和独立审计。0.7.2已有相近规则与示范，用户产物仍出现新增事实、剩余期限丢失和更正不完整。本轮将核对放入实际改稿动作，替换重复提醒；没有读取轨迹，不能断言模型没有读过或某一机制就是错误原因。

- 生成B/D将重要新增人物归属、否定事实和排他判断与适用原句、说话人及版本对照，修改真正失真的句子。无关的防错旁白不进入听众正文。
- 部分回复先回完整原请求核对已答复和仍未解决的部分，再查新稿保留的责任、期限与依赖。用户明确变更后采用新要求，不机械保留旧条件。
- 审计以一项完整当前意见收口，问题、影响、修法、替换句和总结一致。错误替换须明确撤回；不只改影响后称修复方向不变。历史原件保留。
- 短稿初读按实际信息简述；范围存在合理读法时区分待核和确定错误，继续保留必要/充分条件和承诺模态的区别。

已有有效比较、用途切换及局部修改能力继续保留。不强制操作链、全稿命题表或额外文件；不扩展Graph/Run、数字算法或恢复视觉生成，也不再追加一套方法来源。

[四组输入](../evaluation/content-0.7.3/README.md)共10轮：听众取舍2轮、部分更新与明确改期限3轮、培训比较与用途变化2轮、独立审计3轮。公开输入全为合成；私有项目交接留在用户工作区。均为已见回归和能力保留，没有匹配基线或独立保留集支持提升率。

各组用同一真实会话，逐轮释放材料。审计先正文、后来源、再作者说明和旧意见；操作日志与受众输入分离。运行方式按实际选一个值，方法文件读取有宿主轨迹则记录，没有就写未知，不能由输出倒推一定没读。冻结前先立编辑参照，允许合理替代及显式修正参照。

[本版工程记录](../verification/0.7.3/README.md)只记录实际执行的检查；[0.7.2工程记录](../verification/0.7.2/README.md)保持历史身份。工程检查验证打包、引用、来源与兼容，用户模型测试检查真实内容，二者分开。
