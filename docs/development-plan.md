# 0.7.4 开发与验证计划

保留四项生成工作和独立审计。0.7.3用户结果保留了有用比较、用途切换、明确改期限与部分审计撤回，但仍出现状态被说重、行动与期限矛盾、误报未撤回。没有可靠读取轨迹，不能由结果断言模型没读方法，或指定某一机制为唯一原因。

- 生成时核新增状态和对象范围。未完成不等于未开展，缺少记录不等于事实未发生；只要求讲某项能力，不是确认其他能力未验证。已有否定事实也不能机械删掉。
- 部分回复后连同动作、责任、期限和条件一起读完整请求。标题和日期栏正确仍可能与正文冲突；新信息若造成冲突，应讲清待确认安排，不静默挪期。条件估计不等于保证，资源答复也不自动成为原定后备方案的新触发规则。
- 审计按当前原文处置整项意见：已明确建议时，不把缺重复标签列为缺陷。范围与归属如确有问题另行判断；不能用新的理由保留错误指控。更正覆盖解释、影响、修法、替换句和总结。
- 短稿初读按实际信息简述，不重复几套摘要。继续保留必要/充分条件、承诺模态、范围待核及有据否定事实的区别。

既有有效能力继续保留。不强制操作链、全稿命题表或额外文件；不扩展Graph/Run、数字算法或恢复视觉生成，也不再追加一套方法来源。

[四组输入](../evaluation/content-0.7.4/README.md)共9轮：听众取舍2轮、部分更新2轮、培训比较与用途变化2轮、独立审计3轮。上一批已正确完成的明确改期限第三轮本轮不重复。公开输入全为合成；私有项目交接留在用户工作区。均为已见回归和能力保留，没有匹配基线或独立保留集支持提升率。

各组用同一真实会话，逐轮释放材料。审计先正文、后来源、再作者说明和外部旧意见；操作日志与受众输入分离。运行方式按实际选一个值，方法文件读取有宿主轨迹则记录，没有就写未知，不用模型自报代替日志。冻结前先立编辑参照，允许合理替代及显式修正参照。

[本版工程记录](../verification/0.7.4/README.md)只记录实际执行的检查；[0.7.3工程记录](../verification/0.7.3/README.md)保持历史身份。工程检查验证打包、引用、来源与兼容，用户模型测试检查真实内容，二者分开。
