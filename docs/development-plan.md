# 0.9.1 开发与验证计划

本轮保持A/B/C/D和Markdown交付，补强可复算计算与最终推荐、来源含义以及多轮更新后的正文收敛。Run0.1不变，计算Spec0.1兼容，Spec0.2增加有符号差额和人时换算。沿用真实利益相关者确认、仅问句定向挑战、具体求助和分阶段独立审计，不增设新角色或必交台账。

方法库按判断问题选择，费用、资源与技术数据方法和市场、产品营销、销售、公关方法共同支持实际分析。本人价值表达从受众需要、真实判断/行动与合作归属构思，不能只有夸大禁令；用户否认个人目的后停止沿用。知识方法不能填补未知项目事实。

[本版输入](../evaluation/content-0.9.1/README.md)沿用上一版18组41轮的全部自然任务、事实字节和分轮暴露。重点复核数值能否贯通推荐、来源含义、多轮反证与余项期限、以及挑战后是否形成面向听众的有用正文。旧批次和产物不变，参考判据不进入生成上下文。

发布顺序是源码稳定→构建两包→检查包闭包/离线来源/常规测试/输入隔离→独立检查修复→必要的重建重验→冻结最终用户批次。冻结后不能静默改变包。工程测试覆盖实际结构、路径、映射、哈希、无覆盖及来源隔离，不用关键词或方法名证明语义行为。

实际结果见[0.9.1工程记录](../verification/0.9.1/README.md)。运行者分别记录真实dispatch/return、角色来源、上下文分批暴露、实际工具权限与原始返回路径，以及计算输入、结果、回放位置；包身份不证明实际加载，Run声明不证明真实Agent身份。确定未执行写not_run，缺证据写unknown，自述与轨迹冲突保留两端。

模型测试全由用户执行，当前不启动本机Claude、API或子代理批量生成/审计。18组41轮是已知回归和新合成探针，不是独立保留集或受控效果实验；工程通过不能证明模型行为改善。
