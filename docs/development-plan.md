# 0.6.1 开发与验证计划

2026-10-30用户变更目标，2026-11-01结合资料研究与已有案例复核细化内容方法。当前工作以[内容范围](content-scope.md)为准。旧HTML建设路线结束；以下是本轮建设顺序，不是每次汇报必须经过的流程。

1. **细化实际取舍。** 区分目标歧义与事实缺口，让已确认结果影响内容；信息不全时形成有限但有用的判断。缩短重复规则，用少量对照例说明条件、范围、关系和短编辑的取舍。
2. **提高复核精度。** 审计先读正文，再看任务与来源，最后看作者说明；同时检查漏报与误报。沿用现有日期、数值、Run与经验工具，不为表达问题新增状态字段。
3. **补齐离线背景。** 少量按需摘要解释澄清、当前知识下的选择、适用条件和专家经验；沿用同URL来源，不把全部研究变成必读。
4. **工程复核后交用户测试。** 保留旧设计与历史输出，准备[6案新设计](../evaluation/content-0.6.1/README.md)及私有项目交接。普通提示、冻结0.6.0、冻结0.6.1使用可比条件；批量生成、审计、修订由用户执行。

模型验证看相同材料在不同目标下是否实质改变主线，明确目标时是否少问，证据不足时是否既诚实又有用，角色或时长变化时是否重组内容。可选普通提示与Skill对照需同模型、同输入、同工具条件；不要用“更短”本身证明更好。

结果评审后按实际失效点迭代，不恢复固定模板，也不自动扩大测试批次。旧67项设计和历次输出保留为历史输入与证据；旧视觉门槛不再阻塞新内容方向。当前状态见[范围状态](v1-progress.md)。
