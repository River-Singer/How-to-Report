# 0.7.1 开发与验证计划

沿用0.7.0的一条生成工作流和一条独立审计工作流，针对已交案例中可定位的差距修订实际编辑动作与示例。

- 材料提炼围绕听众需要理解的具体过程、比较或关系；选择支撑中心意思的细节，避免职责、功能、痛点并列堆积。
- 核对来源角色和版本；新信息到来时重新检查原判断、预测和未完成的请求，不止修改状态标签。
- 标题提炼中心意思，正文承担细节；作者的写作禁令不代替听众要知道的业务内容。
- 审计复述、缺陷判断和替换句分别核对来源。明确撤回自己的误读；把可选润色与实质缺陷分开。

不扩展Graph、Run或数据算法，不恢复视觉生成。历史材料、包与结果保留原样。当前两包用同一共享源生成，工程检查验证包、引用、离线来源和工具兼容。

[本版四案输入](../evaluation/content-0.7.1/README.md)共11轮：业务介绍3轮、证据更新3轮、局部改写2轮、独立审计3阶段。仅候选版，由用户执行；公开输入为合成材料，私有项目材料不进入仓库。已见素材的定向回归不能当未见泛化，也没有匹配基线支持版本提升率。

每组保持一个真实会话，不能逐轮新建agent后宣称同会话。最后主材料页与备查区分；审计初读只见正文，结果保存审计文件，不再套生成方案的保存提示。冻结前保存独立编辑参照，审阅实际产物时允许多种合理表达，并记录参照自身更正。

[0.7.1工程记录](../verification/0.7.1/README.md)已保存本轮检查结果：223项单测通过、1项跳过，包与离线来源检查通过；四组11轮交接已冻结。模型效果待用户运行。[0.7.0工程记录](../verification/0.7.0/README.md)仍只属于旧包；方法文字和工程检查不代替内容效果。
