# 0.7.1 当前产品范围

内容方向确定于2026-10-30，方法细化于2026-11-01，统一工作流于2026-11-02实施。本范围取代0.5.x的HTML生成与视觉准出要求；旧发布和验证记录原样保留。本文件说明设计与实现边界，不是模型效果结论。

## 希望帮助用户完成什么

让用户确定这次希望听众理解、判断或采取什么行动，找出支持这一结果的重要内容和证据，形成可用于制作汇报材料的方案：明确本次做多少页、每页有哪些可直接使用的内容，以及前后怎样讲清楚。用户明确要口头稿或独立阅读稿时，交付相应正文。

主题不等于结果。候选结果只有会改变证据、主次、叙事或结尾时才值得区分；用户已明确的目标不重问，否定的个人诉求不暗中优化。参与者的知识、权责、依赖和利益可提供线索，但不能据此读心或假设每场沟通都有冲突。目标没有证据支持或超出听众权限时，应提出可行的较小结果与补件需要。

探索围绕真实疑点展开：改变条件后是否需要不同判断？同义重述合并，相关但有独立信息的方向可以保留；缺事实时请求材料，不继续堆维度。用户明确只改一句话时，不因此重启整份分析。

目标歧义、事实缺口和专业知识不足分别处理。新证据通常先改变判断、条件或方案；只有原目标的可达性、会议任务、受众或用户意愿发生实质变化，才重谈目标。AI与委托者已谈明白的背景，不能当作听众已经知道。

信息不完整时，仍可作有依据的局部判断、条件建议，或指出最值得先取得的资料。试点只有一个、未取得收益台账，也可以解释用途并比较适用条件；这些判断不能自动升级成普适结论、量化收益或推广硬门槛。

## 交付

完整材料默认一份《汇报方案.md》：汇报安排说明具体主材料页数与页序，逐页给出标题、可用正文和必要数据与条件。封面、结束页若采用则计入主材料，备查页另列；作者说明与来源清单不自动计页。不能只交讲稿或“这一页讲什么”的空大纲。分页属于内容组织，详细交付规则见[生成与修订方法](../skills/how-to-report/references/reporting-method.md)。

普通短更新、明确的口头稿、独立阅读稿和局部修改按实际形式交付；先分析不强行生成材料。不固定通用页数、每页要点数或版式。多轮修改中增删合并页面，应同步总页数、页序和相关内容；只改一页则保持其他内容。已有文件名沿用，避免两个内容重复的当前稿。

区分委托者、真实汇报者和听众，AI承担幕后分析与编辑职责。正文里“我／我们”的事实归属必须有依据；不能把“本页旨在”“建议突出”或审计日志当作发言内容。

必要条件贴近对应判断，来源和检查细节按需提供。既要讲清真实能力与用途，也要避免虚构收益、因果、承诺；未取得验收记录不等于没有验收。

内容的讲述顺序与事实关系分别检查，保留有用的并行、反馈、依赖和分支。简化可以删无关细节，不能只剩通用口号。按疑点查看[短对照示例](../skills/how-to-report/references/content-decisions.md)，无需依次套用。

## 当前责任边界

保留内容审计、真实数值复核、日期和状态辨别、可选来源/版本记录、显式确认的用户偏好。Graph是按需保持关系的支撑，不要求每图文件、专属Agent或完整JSON。

停止HTML、SVG、PPTX、渲染器、组件布局、配色、坐标、像素、截图和导出验收。下游可以自主绘图与制作，Skill可解释需要比较或理解什么关系，但不规定表达技术。缺浏览器不影响内容交付。

独立`report-audit`接受普通Markdown及可读内容，不以缺PagePlan或未做视觉验收判内容失败。先只读正文，再对照任务与原资料，最后看作者说明；生成自评不充当独立证据。审计既查漏报，也防止将职责、项目方观点或源文歧义误判为更强断言。

## 验收原则

改变目标、听众身份、证据或时长，内容应作出相应且有理由的变化。允许多个合理答案，不按固定标题、页数、维度数或方法名评分。工程通过与用户模型验证分开；测试没有执行就保持未执行。对照普通提示时保持模型、输入、工具和预算条件可比，并同时看无用往返与事实退化。

[本版四案设计](../evaluation/content-0.7.1/README.md)为候选版定向回归，共11轮；已见合成输入保留其身份，批量模型测试由用户运行。组内需实际同会话续接，中断则记录交接；审计只按阶段开放材料。0.7.0已交结果的同会话能力未获验证，不据单次产物认定全面优于旧版；历史输入与输出保持原身份。
