# 0.6.0 当前产品范围

决策日期：2026-10-30。本范围取代0.5.x的HTML生成与视觉准出要求；旧发布和验证记录原样保留。本文件说明设计与实现边界，不是模型效果结论。

## 希望帮助用户完成什么

让用户确定这次希望听众理解、判断或采取什么行动，找出支持这一结果的重要内容和证据，用适合场合的方式组织，并拿到可以直接说出口或交付阅读的正文。

主题不等于结果。候选结果只有会改变证据、主次、叙事或结尾时才值得区分；用户已明确的目标不重问，否定的个人诉求不暗中优化。参与者的知识、权责、依赖和利益可提供线索，但不能据此读心或假设每场沟通都有冲突。目标没有证据支持或超出听众权限时，应提出可行的较小结果与补件需要。

探索围绕真实疑点展开：改变条件后是否需要不同判断？同义重述合并，相关但有独立信息的方向可以保留；缺事实时请求材料，不继续堆维度。用户明确只改一句话时，不因此重启整份分析。

## 交付

默认一份《汇报方案.md》。简短说明采用的方向和取舍，随后给出听众可直接阅读或听取的内容；需要时附关键未决事项与简明来源。完整模板不是必填表，普通更新不要求页数；幻灯片任务的分页只是内容组织。

区分委托者、真实汇报者和听众，AI承担幕后分析与编辑职责。正文里“我／我们”的事实归属必须有依据；不能把“本页旨在”“建议突出”或审计日志当作发言内容。

必要条件贴近对应判断，来源和检查细节按需提供。既要讲清真实能力与用途，也要避免虚构收益、因果、承诺；未取得验收记录不等于没有验收。

## 当前责任边界

保留内容审计、真实数值复核、日期和状态辨别、可选来源/版本记录、显式确认的用户偏好。Graph是按需保持关系的支撑，不要求每图文件、专属Agent或完整JSON。

停止HTML、SVG、PPTX、渲染器、组件布局、配色、坐标、像素、截图和导出验收。下游可以自主绘图与制作，Skill可解释需要比较或理解什么关系，但不规定表达技术。缺浏览器不影响内容交付。

独立`report-audit`接受普通Markdown及可读内容，不以缺PagePlan或未做视觉验收判内容失败。审计先读实际产物，再看生成安排与原资料；生成自评不充当独立证据。

## 验收原则

改变目标、听众身份、证据或时长，内容应作出相应且有理由的变化。允许多个合理答案，不按固定标题、页数、维度数或方法名评分。工程通过与用户模型验证分开；测试没有执行就保持未执行。对照普通提示时保持模型、输入、工具和预算条件可比，并同时看无用往返与事实退化。
