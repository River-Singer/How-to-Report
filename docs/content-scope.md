# 0.10.0 当前产品范围

内容方向确定于2026-10-30，方法细化于2026-11-01，统一工作流于2026-11-02实施。0.10.0 增加总入口在内容确认后接续完整 PPT-Master 的职责。本文件说明当前设计与实现边界，模型效果由相应运行记录支持。

## 希望帮助用户完成什么

让用户确定这次希望听众理解、判断或采取什么行动，找出支持这一结果的重要内容和证据，形成可用于制作汇报材料的方案：明确本次做多少页、每页有哪些可直接使用的内容，以及前后怎样讲清楚。用户明确要口头稿或独立阅读稿时，交付相应正文。

主题不等于结果。候选结果只有会改变证据、主次、叙事或结尾时才值得区分；用户已明确的目标不重问，否定的个人诉求不暗中优化。新完整汇报必须确认真实参会者的受托职责、决定权、否决范围、影响和本场判断；不能只接受职位名单，也不能读心或假定每场沟通都有冲突。目标没有证据支持或超出听众权限时，应提出可行的较小结果与补件需要。

完整判断类材料在收敛前主动检验是否遗漏会改变听众判断的重要区别。探索围绕真实疑点展开：改变条件后是否需要不同判断？同义重述合并，相关但有独立信息的方向可以保留；缺事实时请求材料，不继续堆维度。用户明确只改一句话时，不因此重启整份分析。

目标歧义、事实缺口和专业知识不足分别处理。新证据通常先改变判断、条件或方案；只有原目标的可达性、会议任务、受众或用户意愿发生实质变化，才重谈目标。AI与委托者已谈明白的背景，不能当作听众已经知道。

信息不完整时，仍可作有依据的局部判断、条件建议，或指出最值得先取得的资料。试点只有一个、未取得收益台账，也可以解释用途并比较适用条件；这些判断不能自动升级成普适结论、量化收益或推广硬门槛。

用户希望体现自身价值时，沿真实判断、行动及协作分工呈现贡献；听众利益由本场任务和资料支持，不从职级推测。候选价值进入主线取舍，缺收益数字不阻止解释已有业务用途。选定判断后重新安排正文与时间，合并重复解释；具体依据和必要背景保留，已有目录不决定全部内容都要留下。

选出有用判断之后，继续补足听众理解它所需的关系：从当前疑问追到具体对象、过程、差异、实例和依据。完整评审可以形成多页共同解释一个判断；短更新则只保留本场需要的部分。讲透不等于堆字，也不等于证明已实现效果。关键关系缺资料时请求具体材料，预算用完时调整范围，均不能宣称已经全面讲清。

概要与解释采用有条件的分工：主要意思帮助定向，正文增加理解和支持。整场、页面和子单元不必同样排布；保留讨论问题、过程顺序和正式栏目，不强制粗标题、固定点数或肯定结论。一项比较包含多个对象仍可是一件事，跨层级概览与展开也不自动构成重复。

## 交付

完整材料默认一份《汇报方案.md》：汇报安排说明具体主材料页数与页序，逐页给出标题、可用正文和必要数据与条件。封面、结束页若采用则计入主材料，备查页另列；作者说明与来源清单不自动计页。不能只交讲稿或“这一页讲什么”的空大纲。分页属于内容组织，详细交付规则见[生成与修订方法](../skills/how-to-report/references/reporting-method.md)。

普通短更新、明确的口头稿、独立阅读稿和局部修改按实际形式交付；先分析不强行生成材料。不固定通用页数、每页要点数或版式。多轮修改中增删合并页面，应同步总页数、页序和相关内容；只改一页则保持其他内容。已有文件名沿用，避免两个内容重复的当前稿。

区分委托者、真实汇报者和听众，AI承担幕后分析与编辑职责。正文里“我／我们”的事实归属必须有依据；不能把“本页旨在”“建议突出”或审计日志当作发言内容。

必要条件贴近对应判断，来源和检查细节按需提供。既要讲清真实能力与用途，也要避免虚构收益、因果、承诺；未取得验收记录不等于没有验收。

用户从总入口请求 PPT 时，当前内容及适用的确认属性确定后，由总入口连续进入完整 PPT-Master。交接引用唯一当前稿和必要来源，记录数字、单位、关键条件、用户锁定的内容与对象编辑要求。制作确认按所选上游路线实际完成，最终交付绑定本次真实 PPTX 和各项实际检查状态。

内容的讲述顺序与事实关系分别检查，保留有用的并行、反馈、依赖和分支。简化可以删无关细节，不能只剩通用口号；最终建议没变，也不代表解释可以省略。按疑点查看[内容取舍示例](../skills/how-to-report/references/content-decisions.md)或[同源短长对照](../skills/how-to-report/assets/examples/report-depth-proposals.md)，无需依次套用。

真正决定当前目标的缺事实，在先读算后必须向用户明确求助，说明最小输入/替代、用途和不补的边界；不能降成可选深化。完整稿交付后，有价值但缺输入的可选方向可简要写给作者：最小补件是什么，能深化哪段内容或帮助哪项判断。先使用已有资料，不承诺补件必得有利结论；反证、部分资料或不提供都按实际情况继续。当前主张缺必要依据须先修，不借可选说明保留无据结论；不新增必交文件、固定条数或每轮例行清单。

## 当前责任边界

保留内容审计、真实数值复核、日期和状态辨别、可选来源/版本记录、显式确认的用户偏好。Graph是按需保持关系的支撑，不要求每图文件、专属Agent或完整JSON。审计与定向挑战必须真实委派，缺能力时明确未执行，不主代理串行假扮或私调API。其他分析按能力串行或并行；主代理统一取舍和写稿，不新增调度器或跨平台实测承诺。

HTR 负责沟通任务、来源、内容与独立审计。总入口协调外部 PPT-Master，由其负责 PPT 设计、模板、对象、制作程序及导出检查。HTR 可说明本次需要表达的比较、关系和共现条件，交接按用户实际确认的属性生效。普通内容任务按既有范围交付。

完整外部入口由宿主已有能力发现，或使用用户已提供的实际路径。缺入口、依赖失败或制作中断时，保存内容、有效确认、已有产物和待接续信息，说明真实失败位置及所需能力。内容发生实质变化时更新受影响交接与制作版本，对应检查绑定实际产物。原稿保留式编辑及可复用模板按下游各自正式路线处理。

独立`report-audit`接受普通Markdown及可读内容，不以缺PagePlan或未做视觉验收判内容失败。协调者分阶段向独立审计执行者释放内容：先只读正文，收到初读后再对照任务与原资料，最后看必要作者说明；生成自评不充当独立证据。审计既查漏报，也防止将职责、项目方观点或源文歧义误判为更强断言。

## 验收原则

改变目标、听众身份、证据或时长，内容应作出相应且有理由的变化。允许多个合理答案，不按固定标题、页数、维度数或方法名评分。工程通过与用户模型验证分开；测试没有执行就保持未执行。对照普通提示时保持模型、输入、工具和预算条件可比，并同时看无用往返与事实退化。

[0.9.1 的18场景41轮设计](../evaluation/content-0.9.1/README.md)记录比赛、业务/技术领导、总负责人、同行、进度、周/月报、迁移和独立审计等13类旧场景，以及支持、反证、部分和拒补续轮。双项目多职责、市场/产品营销、销售、公关与本人价值各有对应内容任务。该设计继续用于其原内容回归范围。

专业知识共有25张领域卡与4项逻辑方法，按真实判断选择；市场证据、产品替代、传播结果与购买条件不能混成单一漏斗。个人价值积极呈现真实判断、行动、作用与合作归属，撤销个人诉求后停止沿用。方法有操作、输入、适用/缺件边界和本地来源，文件数与名词出现不证明会用。

0.10.0 的首轮 PPT 单例使用四份已有合成成本试点资料，观察总入口、内容确认、完整制作接续与最终对象。输入和准确包身份在新交接目录冻结，模型由用户运行。实际 host dispatch/return、上下文暴露、制作确认与工具结果分别登记，未取得的证据记录为未知。模板沉淀在首轮联通结果复核后接续，用实际复用结果界定适用范围。

0.9.1 加强的计算—比较—推荐处理继续适用。生成包的 Python 工具提供 Spec0.1 与 Spec0.2 的相应运算，支持明确两项的有符号差额及人时换算。业务口径、实际执行和方案取舍各有依据。收到反证或部分回复时重检受影响判断，保留仍有效的余项期限，忠实保留来源给定状态。
