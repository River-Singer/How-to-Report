# 首批 Knowledge 预载计划

更新：2026-10-26。状态：**首批12张卡及目录已进入 0.2.0 试用；已补充 0.2.1 离线来源包**。七组方向来自共享对话 R37 与原 PRD；卡片拆分及约 12 张的规模是本轮工程建议。

## 1. 原需求与当前缺口

用户在 R37 明确举出管理/PMP、经济、金融、IT、营销、公关；原对话的后续建议与 PRD 进一步纳入统计数据，优先精炼前五组，产品营销和沟通公关轻量起步。R38 确认先判断需要哪些额外知识、征得同意后调用，拒绝则不用；先完成骨架。

原 PRD 已有范围，上一版开发计划却只写了按需方法和“全行业知识库后置”，没有把首批专业领域落实到卡片与验收。这是本轮补齐的计划缺口。跨学科/职能专业知识不同于覆盖所有垂直行业；不能以不做全行业百科为由省略首批知识。

现已在 `skill-src/shared/knowledge/` 编写七组12张领域卡及有限元信息目录，最初卡片版本0.1.0随包0.2.0试用；离线版卡片/目录0.1.1随包0.2.1分发。来源、实际阅读范围与迁移边界见[本批来源记录](research/knowledge-release-sources.md)，实际构建与试用见[第一版结果](first-version-results.md)。资料已收集、原文已研读、卡片已编写、已发布、已验证是不同状态。

## 2. 分层与加载

| 层 | 内容 | 使用方式 |
|---|---|---|
| 核心运行规则 | 目标、事实状态、来源版本、权限、真实执行与审计边界 | 保持精简，随入口使用 |
| 通用认知方法 | 问题重构、解释探索、论证、证据需求、内容/叙事、视觉 | 按当前缺口读取相关 Reference；不能把新的可选领域卡改名为核心来绕过许可 |
| 可选领域 Knowledge | 下表七组精炼专业卡 | 先看有限目录元信息，说明用途；在明确授权范围内读取正文 |
| 本地来源文本 | 当前知识卡引用资料的可保存原文、局部文本或明确标记的原创摘要 | 随包保存，按同范围许可读取相关部分；原网址仅溯源，运行不依赖联网 |
| 工具参考 | 计算、图表、浏览器等的真实能力和接口 | 需要相关工具时读取，实施时核验版本 |
| 原始研究库 | 书目、阅读层级、争议、原文研究记录 | 供开发维护定向研究，不全量塞入运行上下文 |

**预载表示预先准备在安装包内，便于按需取得；不表示每次激活都把正文全部读入上下文。** 目录只包含名称、版本、适用问题、来源与加载范围，不将长篇专业结论伪装成元信息。已有同范围同意继续有效；拒绝、未答复或撤销时不读取该范围正文。允许使用本地知识与允许外传材料、操作外部系统分别判断。

## 3. 第一批具体内容

以下12张卡已编写；每张聚焦一种判断任务。目录与正文分别加载，不能以卡片数量代替专业准确性或行为效果。

| 领域 | 首批卡片建议 | 要补的专业判断 |
|---|---|---|
| 项目管理 | **PM-01 活动、交付、验收与偏差**；**PM-02 关键依赖、风险与决策事项** | 怎样从做过的事情判断真实进度；哪些依赖和风险影响目标；负责人需要决定什么。没有完整进度网络时不认证关键路径 |
| 经济/商业 | **BUS-01 产出—结果—价值实现链**；**BUS-02 方案比较、机会成本与实现条件** | 从功能提出有条件的价值机制；比较替代方案和维持现状；保留非货币化与阶段意义，不强迫所有项目讲 ROI |
| 财务/金融 | **FIN-01 工时、容量、费用与现金边界**；**FIN-02 成本收益/TCO/ROI 的假设与敏感性** | 分清实际、预测、可释放容量与已实现财务结果；明确范围、期限、增量投入与持续成本，提出可复算需求。NPV 等更深方法按实际需求及来源准备度后续补充 |
| IT/软件工程 | **SWE-01 交付表现、生产率与业务结果**；**SWE-02 技术能力、可靠性与可维护性的证据** | 技术指标衡量什么层级；演示、测试和生产观测各支持什么；怎样解释架构权衡、技术债与验证范围 |
| 统计/数据 | **DATA-01 比较口径与聚合**；**DATA-02 不确定性、对照与因果主张** | 核对粒度、单位、分母、样本、时间、缺失和重复；区分描述、比较、预测与因果，寻找能区分解释的观察 |
| 产品/营销（轻量） | **MKT-01 用户问题、采用与指标链** | 区分功能、触达、尝试、采用、留存与交易；识别用户价值假设及需要验证的行为，不自动扩成市场战略 |
| 沟通/公关（轻量） | **COM-01 利益相关者、消息主张与风险回应** | 将主张、依据、限定与潜在问题对应起来；安排解释和 Q&A，避免角色刻板印象、隐去风险或无依据保证 |

项目管理、经济商业、财务卡分别保留专业职责，但可共用相同概念定义，避免三次重复计算一项收益。产品/营销、公关首批各一张轻量卡，不自动启动完整专业工作流。

## 4. Knowledge 怎样进入多 Graph

领域知识用于发现问题、形成解释候选、反推证明义务和检查方法适用性。它不是企业事实，不能凭文献说“某机制可能存在”就认定本项目已经产生该机制或收益。

- Hypothesis：提出新的问题表示、机制或竞争解释；允许未证实候选。
- Evidence / Argument / Obligation：指出该类主张需要什么依据、前提与反例；已有材料支持到何种强度。
- Task：确实需要检索、测量、计算或复核时才创建工作；业务项目依赖与 Agent 工作前置仍须区分。
- Content / Narrative / PagePlan：帮助选择值得回答的问题、内容关系和表达边界，不从知识领域目录直接生成汇报章节。
- 版本依赖：必要时登记实际使用的卡片版本及来源，方法改版后能定位受影响结果；卡片不替代项目输入证据。

**七个领域不是七个固定的“正交维度”。** 同一领域可提供不同机制，跨领域也可能重复同一个观点。知识是生成候选的材料，解释增量、反例和任务目标决定如何筛选，详见[解释探索设计](insight-discovery-design.md)。

共享源可以继续由打包器物化进两个独立包。生成与审计共享术语和方法来源，各自产生候选/判断与独立挑战；不共享某次生成过程的答案或自评。当前先明确内容和准出标准，不预建空知识目录或另起知识图数据库。

## 5. 每卡要有的内容与准出

每卡应能回答：何时用、何时不用；关键概念有什么区别；需要哪些输入；做什么可执行动作；产生什么可审阅结果；如何挑战结果；何时停止；原文依据、版本及实际阅读范围是什么。正文使用原创概括和操作说明，原文与本项目推导分开。

进入发布包前至少验证：

1. 关键专业断言能定位到已实际阅读的适用原文，不能仅凭标题/摘要编出完整操作流程。
2. 生成侧能因此提出有意义的新问题或证据需求，审计侧能识别遗漏、过强主张及误用。
3. 用不同表面材料、反例和缺证情形试用，结果随材料变化；没有把既有示例答案写进卡。
4. 当前目标优先；技术解释、阶段复盘不被强制改成财务收益汇报。
5. 许可前只读元信息、拒绝后可继续核心工作；不重复询问已有同范围同意。
6. 简单任务可不用卡，记录必要的阅读/执行成本；不奖励卡片调用量、观点数或知识领域数。

## 6. 来源准备度与建设顺序

通用方法已有九组不同阅读层级的研究。领域方面，本轮补读 DORA 指标/历史两份官方正文、SPACE 作者摘要，以及 Teal Book 收益管理相关章节；详情见[进一步发现](research/knowledge-findings.md)。SPACE 正文未成功读取，摘要只足以支持其明确表达的原则，不足以写完整实施卡。

首批实现已补核 Teal Book、Green Book 2026、NIST、GOV.UK 服务/数据质量指导、Google SRE 与 CDC 的必要原文段落，并保留阅读范围。没有宣称精读 PMBOK、Kimball 或完整因果推断体系。政府公共服务/卫生沟通语境只迁移所注明的有限原则，不能直接替代企业财务制度或完整营销/公关方法。更深方法仍需具体任务触发并补充研究。

| 批次 | 工作 | 准出 |
|---|---|---|
| K0：纳入 M0 收尾 | 冻结首批卡片范围；补缺原文、来源与版本记录；定义轻量目录和卡片组织方式 | 每卡已有可执行研究问题，状态真实；授权与核心方法边界清楚 |
| K1：纳入 M1 闭环 | 优先编写 DATA-01、FIN-01、BUS-01、SWE-01、PM-01，再补其余卡及两个轻量域；来源不足先补研究 | 原 PRD 七域有精炼可用内容或明确未完成项；不能把空卡算完成。两包独立加载及双面行为检查有实际证据 |
| K2：随 M2–M4 深化 | 依据真实失败扩充论证、预测、收益追踪、技术验证、统计/产品分析等深度；接入解释探索与真实计算/页面 | 新卡解决已识别缺口，保持可迁移和按需使用，不自动膨胀范围 |

这补充了[开发计划](development-plan.md)。首批卡已进入实际实现，前向试用覆盖范围与尚未验证项以[第一版结果](first-version-results.md)为准；没有正式质量增益结论，也未完成每张卡在不同任务下的全面回归。

离线来源的交付范围、SPACE例外和维护方式见[离线Knowledge说明](offline-knowledge.md)。
