# How-to-Report 0.8.3：统一工作流与双入口

当前边界见[范围说明](content-scope.md)。核心工作由宿主模型按需执行，脚本提供具体的计算和记录能力，不是自动理解意图的后台平台。

## 入口与交付

`how-to-report`支持create、revise、analyze-first，从用户当前需求进入：讨论目标、整理主线、直接成稿或局部修改。完整材料默认交付一份Markdown汇报方案，明确页数、页序及每页可用内容；明确的口头稿、阅读稿、先分析和局部修改按对应请求交付。`report-audit`从实际稿件和原要求独立审查，不要求生成侧的完整工作记录。

生成入口首先指向唯一[生成主工作流](../skills/how-to-report/references/reporting-method.md)，由它决定进入、转换、停止和局部返回：

| 工作问题 | 主要结果 | 难点支撑 |
|---|---|---|
| 这次要讲清什么 | 能指导选材和解释深浅的听众问题 | 目标发现 |
| 材料能支持什么有用判断 | 候选价值、证据与区别的比较；沿必要子问题补足具体解释 | 材料提炼、解释探索、论证 |
| 怎样让听众理解 | 按内容关系组织段落、页组与完整正文，再据任务取舍 | 会议表达、观众编辑 |
| 成稿实际表达了什么 | 能否理解、核查和使用；概要与正文的含义是否一致 | 数字、来源与版本工具 |

这四项是职责，不是每次都要过的审批阶段。目标明确就沿用；新事实先更新相关判断，措辞问题局部改写，只有任务/受众/目标需要重定时才返回目标。多轮沿用当前方案与已确认、否决的要求；增删页同步页数及引用。跨会话依靠实际稿件和必要交接，不承诺永久记忆。

[独立审计](../skills/report-audit/references/audit-method.md)遵循另一条主线：听众正文初读→任务/来源对照→拟报问题反证→结论和修复。它可以更正自己的初读，也要核对问题解释、影响说明、行动建议及替换句新增的含义。更正时整项当前意见一起更新，明确撤回错误替换，保留历史原件。作者安排与正文同文件时先定位正文，不能整份先读再冒称盲读。

叙事职责已并入meeting-expression；旧narrative-page-behavior从当前源码和新包退出。生成/审计主方法保留原位置，共享含义标准只定义一次；历史包原样保留。公开教学用合成材料展示从记录到逐页内容的连续过程，不引用私有客户事实。

遇到分类堆叠、换词后仍不清楚或部分请求更新时，主线定向调用连续改稿示范，修改当前片段后再检查它是否回答听众的问题。在B/D将重要新增归属、否定或排他判断对回适用原句；部分回复回到完整原请求核余项，明确的新要求覆盖冲突旧要求。示范提供取舍方法，够用即止；不要求每次通读研究、复制同一句式或输出教练记录。

0.8.2 将厚度纳入这条主线：重要主张还有什么必要关系没讲清，就回资料补具体过程、比较、实例或证据，再组织成正文。通常概要给方向、解释补理解；整场、页面和子单元可以分工，但不强制每层先下结论、每段粗标题或固定点数。一个复杂判断可以由页组完成，关系也可交叉；不新增厚度Graph、Agent或中间文件。解释了机制与证明了效果分别核对。

0.8.3把这些职责落实到当前句子和行动：重要新断言对回原对象、角色、版本与状态，再写自然正文；收到部分回复先修仍有效的行动余项，再同步概要和结尾。推荐中的一条理由无据，可以删掉该理由而保留独立成立的选择。讲解、备查和作者说明中的相同断言也在受影响范围内；不新增必填账本或独立流程。

[同源短长教学](../skills/how-to-report/assets/examples/report-depth-proposals.md)与既有删合示例配对：前者展示怎样充分展开，后者展示怎样按本场任务收束。两者均为公开合成材料，页数不是通用标准。

## 推理依赖与可选并行

B 是工作流的推理中心：材料表示支持候选判断，证据与条件限定判断，新的有用区别可能改变判断，比较后才进入叙事。保住含义的反例检验与发现增量的情形比较承担不同职责。完整判断类汇报主动检查后者，不按维度数量凑内容。

目标—主张、资料—主张、条件—判断、人物—贡献、页面—判断分别保留具体含义。资料改变时沿这些关系修订受影响的标题、行动与结尾；局部改句不重启全篇。工作记录保存可审阅的结论、依据、关键假设和取舍，不要求公开内部推演。

宿主支持真实子代理且任务可拆时，独立子问题可并行；主代理统一沟通、裁决与写稿。证据核对和遗漏区别可以分工，不让每个代理各写一套汇报。无工具串行完成，内部角色模拟不冒充独立审计。执行约定由[host-capabilities](../skills/how-to-report/references/host-capabilities.md)负责，无新增API或运行服务。

## 多Graph保留什么

| 关系视图 | 作用 |
|---|---|
| Goal / Audience / Context | 正式要求、候选结果、听众知识与权责、用户取舍 |
| Hypothesis | 不同解释、条件、反例和能区分答案的观察 |
| Evidence / Argument / Obligation | 什么资料支持到什么程度，推理缺哪项前提 |
| Content / Narrative | 需要回答的问题、理解前提、内容共同含义与顺序 |
| Task | 为解决实际未知而进行的工作、输入、完成标准 |
| 版本依赖 | 采用哪个资料版本，变化后哪些内容需要复核 |

这些视图可以在短笔记中表达。没有必要给普通句子建节点，也不要求每图单独文件或服务。叙事关系允许交叉和循环；执行前置须无循环；版本使用依赖用于定位影响。三类关系不能混用，Graph结构通过不能证明主张真实。

采用目标、事实核验、工作完成和实际沟通效果仍是不同状态。新证据通常先改变论点、条件或方案；原目标可达性、会议任务、受众或用户意愿实质变化时才重谈目标，不允许模型暗中替换用户选择。确认偏好不能代替本次目标。

## 可靠性工具与包边界

Run0.1、来源精确版本、显式版本选择、计算凭据和私有画像按需使用；普通成稿不要求初始化Run。计算依赖真实输入与方法，日期工具区分基线、实际、预测和验收，不自动决定业务结论。审计可登记自己的Run，初始检查保持未执行。

两包以`skill-src/shared`为单一共享源，构建到`skills/`，可分别搬迁和安装。核心方法和采纳知识具备本地文字；原网址仅溯源，授权范围仍适用。真实材料、Run、输出与用户画像在安装包之外。

HTML、SVG布局、页面映射、浏览器检查和PagePlan转换退出默认包，见[历史归档](../legacy/visual-0.5.3/README.md)。历史Run中的`page_plan`类型可继续保留为兼容记录，不强迫旧资料迁移，也不成为新交付依赖。

## 质量证据

程序验证文件、引用、状态、日期和计算等确定性边界。内容能力必须看实际结果：是否有用地澄清、发现重要区别、充分解释一个判断、讲清依据与取舍、形成自然正文。[当前评测](../evaluation/content-0.8.3/README.md)保留V10的13场景25轮、全部任务与分阶段来源，继续观察解释深度与多轮保真。0.8.2产物已复核且保留；0.8.3由用户另跑V11，现有方法与单元测试不代表模型效果已通过。
