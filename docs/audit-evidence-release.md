# 0.2.4：审计意见与计算证据的准确交付

更新：2026-10-28。包版本0.2.4，Run契约0.1，知识卡、目录与来源归档0.1.1。本版调整现有方法与可选模板；没有增加图类型、必填机器字段或新的执行命令。

本文保留0.2.4的方法改动与验证边界。当前包0.4.0的HTML工具见[发布说明](html-runtime-release.md)；下列资源链接打开仓库当前包，历史结果仍按原版本解释。

## 本版处理什么

0.2.3的四案试用已能复现原数字、检出构造错标并保留历史缺件边界，但出现了三类交付问题：整理后的计算表仍被叫作原始输出，可选措辞意见仍列成有效缺陷，引用消息号与来源文件没有对应。0.2.4将这些差别落到实际交付方法中。

| 调整 | 随包入口 | 应有的交付行为 |
|---|---|---|
| 意见性质与优先级分开 | [审计判定](../skills/report-audit/references/audit-judgment.md)、[审计模板](../skills/report-audit/assets/audit-run/audit.md) | 分清已证实缺陷、必要证据缺口和可选建议；P2标签不自行决定必须修复或有条件通过。保留真正的轻微算术、归属和定位错误。 |
| 核对实际主张及限定 | [独立审计方法](../skills/report-audit/references/audit-method.md) | 判断设计原则、建议与已实施事实时读足上下文；不能仅由页面改词推出早期事实被撤回，也不能漏掉真正的后续纠正。 |
| 来源与定位成对核查 | [审计判定](../skills/report-audit/references/audit-judgment.md) | 对实际依赖的引用同时核对文件/版本、消息或段落、必要的发言者；定位错与主张无依据分别处理。 |
| 原始结果与整理分析分开 | [数值证据](../skills/how-to-report/references/numeric-evidence.md)、[计算说明](../skills/how-to-report/assets/review/calculation-note.md) | 声称原始执行输出时保留真实输出；汇总、改格式或重算后的内容标为整理分析，不冒充历史stdout。缺原件时区分当前独立计算与未证实的历史执行。 |
| 舍入与差值口径明确 | 同上 | 说明会影响结论的半值规则、取整层级和比较量；语言默认舍入不一定是日常四舍五入。找到兼容算法不等于证明作者历史上用了它。 |

简单人工算式仍可直接写明输入、公式、结果与限制，不强制创建脚本、长表或整套图。两包继续离线独立使用，计算方法和可选Knowledge的授权边界分开；这些规则不会自动执行来源代码或扩大读取权限。

## 已有证据与尚未证明的部分

- **0.2.1历史试用**：模拟认知案例及MASTer四轮修订保留原版本与结果，不转算为当前包效果。
- **0.2.2流程证据**：八案审计及七案记录更正已验收；结构与回执成立，语义判断另行复核。
- **0.2.3定向试用**：四案25个交付文件已复核，四案自身结构检查和回执绑定均通过。主要观察成立，但上表所述审计记录/分类问题仍需局部修正；详见[0.2.3记录](audit-precision-release.md)。
- **0.2.4当前边界**：发布工程检查与方法文本审查分别报告，不把包完整性、模板可用或数值示例复算当作模型质量证据。本版尚未运行模型案例，尚未验证这些调整能稳定避免残余问题。

本轮不另开整批案例，不修改冻结master-v1/v2/v3及用户审计结果。以后需要批量实例测试时，开发侧先准备冻结输入、Skill、提示词、输出目录和验收关注点，再交用户执行。旧记录的局部补算与更正不要求重新生成成熟报告。

当前开发证据存于任务工作区`validation/audit-evidence-*`，不作为运行包依赖。完整报告渲染、宿主原生安装和跨宿主验证、正式质量对照及完整V1路线图仍在[开发计划](development-plan.md)中。
