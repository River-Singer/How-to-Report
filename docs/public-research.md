# How-to-Report：公开资料定向研究与 V1 取舍

更新：2026-10-26。来源为用户指定的39轮共享对话、开发交付包和本轮公开原文研究。本文是研究结论与实现建议，不是产品效果报告，也不新增已经批准的技术选型。

## 1. 资料在哪里，读到了什么程度

- [公开资料索引](research/public-sources.md)：按主题查看出处、对话轮次、研读状态和研究笔记。
- [结构化索引](research/public-sources.json)：保留原始URL、消息ID、引用ID、合并别名、访问/阅读状态及补充查证来源。
- [专业方法研究](research/public-methods.md)：受众、开放探索、论证充分性、内容组织。
- [语义与视觉研究](research/public-visuals.md)：分析任务、多视图、视觉编码与版面约束。
- [Skills、评测与计算研究](research/public-execution-evals.md)：渐进加载、宿主能力、独立审计、真实计算。
- [需求对齐与已确认决定](requirements-alignment.md)：产品范围、轻量画像、策略确认图及实施分期。

清理后的索引收录 **171个资料链接**，不是171篇独立论文。4个重复/误提取条目保留合并记录，9个图片缓存地址从研究资料中排除。185个正文引用ID中168个可由公开消息元数据映射，另17个保持未绑定；同一消息附带的公开URL另行收录，不按顺序猜配。

阅读状态区分“仅收集”“定向章节已读”“全文/规范主体已读”“仅摘要可读”“访问未成功”。读过某库的一篇子文档，不意味着该库仓库、全部API或全部关联论文均已核验。补充查证使用单独记录，不伪造历史引用。

此前完成9个专业方法专题、8组视觉资料和8份Skills/评测/计算官方材料的定向研究。视觉组中的IBCS只核验版本说明；这些数量不可直接相加当作25篇全文精读。后续针对Knowledge、解释探索与目标发现，补读DORA两页、SPACE作者摘要、收益管理章节及Dorst/Cross相关正文，并新增Gentner、Keeney两项补充原始文献。当前原索引中138个链接仍仅收集；另有14个实际读取地址用于同篇作者副本或补充研究，不等于14篇独立新论文。逐项范围以索引为准。

原始对话提取、论文/文档读取快照和更细的本地材料记录保留在父工作区 `.trellis/tasks/10-25-how-to-report-v1-brainstorm/research/`。本目录提供研究笔记与书目快照，不随产品仓库复制完整第三方书籍、论文或原始会话页面。

## 2. 研究要解决的具体问题

| 问题 | 对产品的作用 | 判断是否有用的方式 |
|---|---|---|
| 怎样从材料发现新的、有依据的解释？ | 改变问题表示、识别异常、提出竞争解释，按需要补充证据 | 新方向是否改变理解或行动；是否只是原话改写；是否有区分解释的证据 |
| 主张需要什么证据，何时应主动追问？ | 从主张类型、强度和适用条件反推证明义务 | 请求是否具体且会影响判断；拿不到时能否保留诚实的较弱表述 |
| 怎样把探索收敛为完整内容？ | 以问题组织模块，辨别支持、解释、限制与叙事关系 | 下层判断全成立时，上层是否仍可能不成立；是否遗漏必要条件 |
| 怎样组合图形而不改变含义？ | 依据共同观察需要选择同屏/分步及视觉编码 | 读者能否正确比较；图中是否额外暗示因果、相等、精确程度或完整覆盖 |
| 哪些工作交给Skill，哪些交给工具？ | 专业判断按需加载，执行与检查留下可见证据 | 是否真的调用了资源和工具；工具缺失时是否诚实降级 |
| 怎么知道比直接问模型更好？ | 固定比较条件，结合确定性检查和独立判断 | 是否有真实产物、执行记录、失败案例和质量/成本数据 |

这些问题决定研究顺序；资料数量和方法名称数量不作为完成度指标。

## 3. 对 V1 的四层建议

| 层 | 放入什么 | 怎样约束规模 |
|---|---|---|
| 核心规则 | 当前用户目标优先；重要主张与证据相称；来源/版本可追溯；保留重要风险、反证和未知；按实际能力说明验证状态 | 只保留影响真实性、授权、可追溯性和任务完成的共同规则 |
| 按需方法 | 受众分析、探索与反例、论证挑战、内容模块、叙事依赖、图形组合、语义反向审查 | 每个方法写清触发条件、操作、产物、失败方式和停止条件；不把案例答案或固定观点数写入方法 |
| 可执行工具 | 数值计算、输入形状校验、引用完整性、版本变化检查、图表渲染、页面几何检查 | 先实现高价值、易出错且可检验的操作；具体库由实际宿主和小规模验证决定 |
| 后置能力 | 完整任务调度平台、跨任务自动画像、全行业知识库、全图表实现、复杂恢复系统 | 保留替换边界；没有明确使用场景和验收证据时不提前建设 |

这与已经确认的轻量双Skill方向一致。长篇主提示词会增加无关加载与方法混用的风险；完整Agent平台会引入当前任务之外的运行维护要求。先采用精简入口、按需Reference、少量可靠工具，不把研究目录直接作为运行时全量知识包。[Agent Skills规范](https://agentskills.io/specification)、[OpenAI技能编写指导](https://github.com/openai/skills/blob/main/skills/.system/skill-creator/SKILL.md)

## 4. 原文核验带来的具体校正

### 洞察应有解释增量，不能只换成漂亮分类

Braun/Clarke的反思式主题分析区分“同话题归组”与“围绕中心概念形成共享意义”。这为检验洞察提供了有用参照，但不能把文本解释方法用于替代数值因果分析，也不要求所有事实汇报都追求潜在深意。[作者方法FAQ](https://www.thematicanalysis.net/faqs/)

**项目建议：**一个候选洞察应能说清完整判断、材料如何共同支持它、相比原有分类多解释了什么、哪些反例需要修正它。进一步请求能区分竞争解释的证据，是本项目的应用推导。不能通过多发明抽象名词、更多维度或套用MASTer结论证明发现了价值。

### 论证清单与页面标题都是辅助手段

论证方案可帮助发现缺少的前提，但Hernández对固定关键问题清单的批评表明，清单也可能遗漏真正争议或制造无用追问。Assertion–Evidence实验则同时改变了标题、文字密度、图示与呈现方式，不能把效果单独归因于“标题改成一句判断”。[论证方案批评](https://link.springer.com/article/10.1007/s10503-023-09613-w)、[Assertion–Evidence原论文](https://www.writing.engr.psu.edu/ae_comprehension.pdf)

**项目建议：**方法调用要指出本任务的具体缺口及需要改变的结果。验收应检查有效证据请求、材料支撑、读者理解与错误关系识别；不能只检查Toulmin字段齐全、标题像结论或方法卡全部勾选。

### 论点贡献需要判断，不能写成“越少越好”

对话引用的论点强度研究在不同实验中观察到增强与削弱两类结果；弱论点的顺序、强弱对比、受众涉入等条件影响解释。它可以启发我们审查新增论点的相关性与贡献，但不能据此设定通用数量阈值、线性权重或固定删除规则。必要的风险、反证和限制也不能因“不够有说服力”而删除。[原论文](https://www.nature.com/articles/s41598-024-73348-1)

**项目建议：**分别检查一个论点是否新增解释、证据、条件或行动含义，以及它与已有论点是否共享同一份支持。不能只按词语不同或论点个数判断增量。

### 结构化与正确性分别验证

引用存在、计算成功、页面渲染成功，各自只证明相应操作完成。它们不能互相代替，也不能单独证明主张成立。独立审计需要从原资料和实际产物重建含义，检查遗漏和越界；独立上下文可以减少特定污染，却不保证模型没有共同偏差。[评测方法研究](research/public-execution-evals.md)

**项目建议：**同时保留可程序检查的证据与可定位的专业判断。审计不能仅复述生成者的计划或接受自评结论。没有独立上下文、实际计算或真实渲染时，报告应说明缺少哪一种验证。

### 数值类型与复跑都不是业务正确性的保证

DuckDB官方文档说明，无显式排序的结果顺序和多线程浮点计算可能存在差异，DECIMAL除法也仍可能产生近似浮点结果。这是需要记录精度、排序与运行条件的具体例子，不是要求本项目必须选择DuckDB。[非确定性说明](https://duckdb.org/docs/2.0/operations_manual/non-deterministic_behavior)、[数值类型说明](https://duckdb.org/docs/2.0/sql/data_types/numeric)

**项目建议：**计算凭证同时记录输入版本、粒度、过滤/缺失口径、公式、实际代码、引擎版本、输出与校验。复跑相同结果不能证明分母、对照组或因果解释正确。现有成本分解案例还必须明确交互项归属，不能把一种分解约定当作唯一正确答案。

### 成熟图库可以负责绘制，跨图含义仍要审查

Vega-Lite官方文档明确区分“能合并尺度”与“合并是否有合理含义”；多图成功编译不代表数据可比较。AntV Infographic的默认有向关系、重复ID覆盖和部分语法归一化，也可能让上游关系在转换时丢失区别。[Vega-Lite组合](https://vega.github.io/vega-lite/docs/composition.html)、[AntV语法](https://infographic.antv.vision/learn/infographic-syntax)

**项目建议：**图表适配前保留单位、粒度、筛选范围、关系方向、缺失含义；适配后回报实际尺度与编码。必要语义无法映射时应明确调整表现形式。先用真实任务选择一个主要定量图库；ECharts、Vega-Lite和AntV目前都是候选，不是同时引入的依赖清单。

跨图一致性也不应机械化：Qu/Hullman的研究允许有理由的尺度例外，且研究对象是少量有经验的制图者，并未直接证明观众理解改善。不同单位或特意展示局部差异时，可使用独立尺度，但要明确标注并检查误读。[原作者论文](https://volitionalai.uw.edu/paper/2018-Consistency-InfoVis.pdf)

### 页面比例与图表生命周期需要各自验证

ECharts要求初始化时具有有效容器尺寸，并在尺寸或挂载状态变化后处理实例；CSS的首选长宽比也不能保证内容不溢出。因此，舞台仍为16:9、DOM不越界、图表非空、文字可辨识是不同检查。[ECharts尺寸文档](https://echarts.apache.org/handbook/en/concepts/chart-size/)、[MDN比例说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Box_sizing/Aspect_ratios)

**项目建议：**现有原型先修复缺失值转零、重复截断标签和画布配置不一致，再考虑复用；真实浏览器覆盖进入页面、缩放、离开和再次进入，并核对重要证据与限制仍然可见。

### 标准和素材复用需要保留版本与适用范围

IBCS官方现行页面介绍2.0版本，本轮只核验了公开版本说明，未取得详细新条文。FT示例仓库的软件许可也不覆盖FT内容和品牌。研究可用于借鉴判断与代码机制，但目前不能承诺完整符合IBCS/ISO，也不能直接把全部海报素材作为产品资源发布。[IBCS版本说明](https://www.ibcs.com/ibcs-version-2-0/)、[FT示例仓库](https://github.com/ft-interactive/visual-vocabulary)

## 5. 怎样把研究写成可用方法

每张方法卡回答以下问题，不要求输出固定业务字段：

1. **什么缺口值得调用它？** 例如观点重复、缺少解释、比较口径不一致，或页面无法支持共同观察。
2. **需要哪些输入？** 已知条件、来源、未知和当前限制。
3. **具体做什么推理动作？** 给出少量能执行的问题或操作，保留情境判断。
4. **会产出什么可审阅结果？** 候选解释、证据请求、关系判断、内容修改或页面方案。
5. **什么时候不适用或容易误用？** 指出方法不能证明什么。
6. **如何挑战结果？** 反例、替代解释、原始来源核对、数值复核或读者理解测试。
7. **何时可以停止？** 已解决当前缺口，或剩余未知不值得继续扩展；关键限制仍须保留。

方法卡要附原始来源和本项目推导边界。示例用于演示操作，换一个领域后仍应成立；MASTer的内容不能成为所有汇报的默认观点。

## 6. 首批验收探针

以下是研究推导的待实现行为检查，不是已经执行的测试，也不直接充当最终盲测集。

| 探针 | 应观察到的行为 | 应捕获的失败 |
|---|---|---|
| 同材料，分别向技术评审和业务负责人汇报 | 选择不同问题与组织方式，保持事实和证据状态一致 | 套用角色刻板印象，或为迎合受众改变事实 |
| 有交付周期记录，缺少投入工时和合理对照 | 能说明已知交付事实，主动请求支持提效主张的关键证据 | 把发布频率直接说成生产率、成本节省或因果效果 |
| 两个近义观点与一个不利反例 | 合并重复，保留有意义差异和重要反例 | 为追求简洁删掉风险，或重复计票同源证据 |
| 主题分类齐全，但缺少可检验解释 | 产生候选解释及能区分它们的下一条证据 | 把整齐分类、抽象名词或更多维度当作新洞察 |
| 同屏的两张图口径或样本不同 | 说明差异，调整比较或补充必要条件 | 颜色、比例和布局制造可直接比较的错觉 |
| 数据包含缺失、真实零值、重复标签与小额除法 | 保持缺失语义与可区分标签，明确精度/舍入 | 缺失变零，标签截成相同文字，数字看似精确却无法复算 |
| 中途换新材料或改变主线 | 标记受影响内容并局部复核，无关结果可复用 | 全量重做，或继续发布旧口径结果 |
| 本次要求与历史画像冲突 | 遵循当前要求，画像可查看修正 | 把临时决定推广为永久偏好，或把推测写成经历 |
| 没有浏览器或独立审计上下文 | 完成可执行部分并准确说明未验证项 | 用配置检查代替真实渲染，用同一上下文自评宣称独立 |

B0/B1/B2比较从M0就固定输入、工具、模型条件、评价方式及预算口径，保存每次实际产物与记录。需要同时报告质量和成本；B2增加的审计成本不能隐藏。开发者已经接触的案例只能用于开发/回归，正式盲测另行准备并冻结。[OpenAI评测说明](https://developers.openai.com/blog/eval-skills)、[Anthropic技能评测实现](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)

## 7. 本轮之后的工作边界

在已有工程骨架上，目标发现/解释探索方法、配对开发探针与首批领域卡已进入0.2.1试用；卡片直接引用的18个来源已提供本地文字表示，见[离线范围](offline-knowledge.md)。M0正式评测条件、必要宿主确认及更深方法/计算/页面仍由实际需求与失败推动；具体依赖以更新后的开发计划为准。

本研究之后已完成双Skill工程骨架、最小契约及有限行为试用，见[验证记录](skeleton-validation.md)；尚未完成完整V1、生产图表引擎或B0/B1/B2实验。原创建试用给定了明确目标，不能证明目标发现与解释探索能力已经验证。

进一步补齐的认知设计包括[目标发现](goal-discovery-design.md)、[问题表示与解释基底](insight-discovery-design.md)、[首批领域Knowledge](knowledge-plan.md)；[新增定向发现](research/knowledge-findings.md)保留原文与工程推导边界。这些设计已形成首批可执行方法及有界试用，见[第一版结果](first-version-results.md)；效果不由更多文献或图名自动成立。
