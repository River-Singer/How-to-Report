## 试什么

- 从正式要求、受众权责和已有材料发现此次沟通目标；区分明确要求、诉求假设与新的目标建议。
- 改变问题表示，比较竞争解释，检查跨因素关系，并说明什么证据能区分候选。
- 形成可阅读的策略、Content Blueprint 和所请求的草稿；目标变化时重审内容职责。
- 独立检查外来汇报的事实、论证和遗漏，不要求先运行生成 Skill，也不在仅审计时修改原件。

这是一版自然语言 Skill 加最小结构工具，未包含完整 HTML 渲染器、自动图调度平台或跨任务自动画像采集。

## 用自己的材料试跑

在能读取本地文件的宿主中，指向生成目录里的 SKILL.md，并提供资料路径或直接提供材料。源码目录 skill-src 的叶目录没有物化共享资源，不作为安装单元。原生安装和自动发现需遵循所用宿主的规则，本次路径调用验证不代表跨宿主兼容性认证。

可采用这样的请求，替换方括号里的内容：

> 请使用 how-to-report 的 SKILL.md。我的材料是[材料位置]，汇报对象和场景是[已知信息]，目前只知道[现状或疑问]。请先发现值得讨论的目标和主线，说明依据、关键未知及取舍，形成内容蓝图；不要预先假定我要争取预算或证明收益。对会改变主线而材料无法回答的问题，再提出必要澄清。

如果目标已经明确，直接给出即可，不需要故意变模糊。只需短修改时明确文件、范围和要改变的内容，Skill 应保持任务轻量。

独立审计请求可写为：

> 请使用 report-audit 的 SKILL.md，依据[原资料]审查[实际报告]是否满足[要求]，列出可定位的问题、依据及未能核验的部分。此次只审计，不修改原件。

正式审计保存自己的 Run，并在交付前校验该审计目录；详见[审计 Run 操作](../skills/report-audit/references/audit-run.md)。有 Python 时用 `audit_run.py init` 从实际报告创建未完成记录，审查完成后用 `check` 自检。没有执行能力时使用随包模板人工核对，明确自动校验未运行。内容结论、工作完成和结构通过分别报告，不能只展示被审生成目录的通过结果。

若报告含精确数字或时长，可按[数值证据方法](../skills/how-to-report/references/numeric-evidence.md)附[计算说明](../skills/how-to-report/assets/review/calculation-note.md)，写明范围、单位、规则、公式及实际执行情况。跨版本审计或材料包不完整时，可用[材料清单](../skills/how-to-report/assets/review/evidence-inventory.md)说明此次已附和未附的材料及其对判断的影响；详见[证据交接](../skills/how-to-report/references/evidence-handoff.md)。这些说明按缺口使用，不要求每次短改都建立额外材料。

审计按[判定方法](../skills/report-audit/references/audit-judgment.md)核对当前主张、适用要求、版本和反证；词面变化或未附历史材料本身不能直接判为稿件缺陷。修订结论后，同步更新当前状态、方法与范围，把旧判定留在历史中。

## 领域知识怎样使用

[知识目录](../skills/how-to-report/knowledge/index.md)是有限元信息；卡片正文按问题和明确许可读取。可以只允许某张卡、拒绝某个领域或不使用额外知识。已有同范围许可继续有效。授权本地方法卡不等于授权把业务材料发往外部服务。

领域卡帮助提出问题和检查方法，不能充当你的业务证据；按知识领域直接排章节，也不能代替内容设计。

0.2.1 按无联网/搜索能力的 Agent 使用条件准备：知识卡引用本地文字来源，原网址仅供维护与溯源。可获得且允许保存的原文、局部抽取和原创摘要分别标记；需要时只读取当前问题相关段落，不把整部资料默认塞入上下文。缺少项目事实时列出缺口并请求用户提供，不编造检索或把通用文献当业务事实。

## 看结果时关注什么

判断目标建议是否有材料依据、是否符合实际权责，能否解释它会如何改变内容；检查候选解释是否真有区别、有什么反例、还缺什么证据；最后看草稿是否保留了重要限制和真正回答了受众问题。

目标或受众改变后，可以要求保留初版再修订，对照主线、必答问题、证据需求和草稿的实际变化。报告完成、事实核验通过、用户采用目标和实际沟通成功分别判断，不能用一个“通过”状态代替。

首批示例均为明确标记的模拟开发案例。它们展示可检查的产物和已发现的局限，不构成正式 B0/B1/B2、未见 Holdout 或普遍质量增益证明。
