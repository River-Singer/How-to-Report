# 制作前的演示设计评估

完整新稿、实质改页任务、合页/拆页/改序、替换表达方式或重组素材时，在参数绑定和批量成图前执行。本方法是现有C到PPT制作的交接步骤，复用当前brief、页面安排或作者工程；不另建一套内容规划，不机械产出三套方案，也不增加用户确认门槛。沿有效自主授权作出选择，只有超出授权的实质决定才交回协调者。

流程是：B/C形成有据内容与理解路线 → 本页表达与选型评估 → 现有工具校验和computed测排 → 目标成图 → 最终叙事与视觉审核。理解评估决定为什么这样讲；设计评估决定用什么可见关系承载；引擎按真实内容测量、计算几何。各层不能互相代证。

## 先把内容变成可制作的页面任务

从C采用的路线确认每页让听众理解什么、前文已给什么、本页增加什么、接向哪里。复用`page.job`或已有页面安排写清必要内容和主次，辨明数据解释、明细查阅核对、事件顺序、机制解释、能力介绍、案例证明等真实表达任务。按[数据表示选择](ppt-data-display.md)先定解释还是查阅，不因有数字就强制选图，也不要求明细表先穷尽图种。不能先选一个好看的组件，再改写本页任务去适应它。

有数据分析需要时，先核B是否已经完成必要加工：单位/期间/总体与子群、分母、比较基准、差异、范围和可支持的解释。仍不能解释的原因按具体影响限缩，不用“先画出来再说”跳过分析。纯功能介绍或机制说明可明确“无需定量分析”；没有指标不构成强造图表的理由。数字精确但问题没回答，回B；路线未成立，回C。

素材按实际作用分配：数据从可核来源绑定；真实界面/工作成果可直接用原图，查看后决定完整保留、裁切或局部放大；必要图缺失时在已有授权内设明显矩形占位，并把补图类型和用途交作者。缺图不能冒充证据或用无关装饰填空。必要解释文字保留其段落关系，不把介绍型材料一律压成短标签。

## 按关系查真实组件，再决定页面结构

实际查询library、chart-assets或原生catalog，打开候选的合同及可用预览。记录选中的真实ID、入口、数量/输入域和可编辑范围；名字相近不等于数据适配，`executable`也不证明效果已适合本次内容。首次结果不足时沿分页继续，不能把首屏当全部库。

日期加事件形成先后序列时，先查时间轴/里程碑。等距事件轴只表达顺序，不能暗示真实时间间隔；依时长定位需要真实时间尺度支持。四列散字即使能省高度，也没有自动获得时间推进的表达。采用其他结构必须说明它比时间轴多保留了什么、改善了什么；不能以“排得下”作为全部理由。没有合适紧凑variant时先查看支持相同关系的已注册组件及现有容器，不编造variant或手填最终坐标。

仅对有实质疑问的选择看一个最有希望的备选：比较语义、文字/节点容量、可读性和制作支持。关系明确且合同适配时直接采用，不要求每页强列三套、强行渲染全库。没有适合的原生组件时，已有原图可承担原貌展示；必须新增能力才另开引擎合同，不能让模型临时画自由SVG兜底。

沿[栅格设计选择](ppt-grid-design.md)确定主内容/侧栏、等权对照、重复小图、全宽上下带或纵向解释行，声明分组及页内读序；再映射实际row/column/grid或完整模板。统一文字角色、对齐线、组内/组间距及同类图形语法，沿[文字标准](ppt-text-standard.md)和全局palette。对于多段介绍，先按[长文本结构化](ppt-explanatory-content.md)保留完整意思单元，再沿[16种栅格模式](ppt-grid-patterns.md)比较解释行或分栏；目前不假定已有自动跨栏续排、keep-with-next、孤行控制或所有组件的内在测量。

## 用预算和廉价检查结束评估

在已有记录保留足以执行的短说明：当前页任务和读序、所需分析及素材是否就绪、实际采用的组件/容器及关键取舍、文字角色与空间预算、失败时调整什么、最终需看什么。不要求独立文件或固定schema；不能只写“简洁大气、图文并茂”。尺寸预算是容器约束，不是AI算出的最终对象frame。

先检查输入合同、真实素材路径/占位身份、profile和受支持布局字段，再使用正常validate及不带PPTX导出的computed build做测排。测排仍会生成中间页面，它的用途是尽早暴露长标签、过窄栏、容量冲突和不支持能力，不是语义或最终视觉验收。仅字段验证通过不能宣称文字已测量，真正高度以实际build报告为准。

默认只完成一次设计核对，出现明确失败时对受影响处最多比较两个有希望的结构，先试廉价计算；不为了选型无界生成整套PPT。容量失败先去重复、共享标签或改分组/栅格，保持14pt正文及9pt最小角色；仍不够且授权允许再拆页并重审承接。不能为了保页删除必要意思、取消时间关系、缩字或把长解释转成小字图片。

未解决的分析、关系或不支持输入阻止相应页进入正式成图；独立成立的页可继续。授权草稿和缺图占位按已知边界交付，不把待补标成设计完成。可以开始成图只表示所选方案有依据、有实际入口且初步容量可行；好看、叙事成立、实际PowerPoint可读仍由最终审核确认。纯颜色或错字修改保留未受影响的设计判断，字数/字体改变影响容量时只重测相关部分。

## 可执行示例：四个里程碑的紧凑顺序带

这是合成接口样例，不含真实业务结论。[作者工程](../assets/design-system/examples/design-preflight-timeline.json)保留了一个简短设计说明，正文为四个日期与事件。正常调用：

```text
python <Skill>/scripts/report_engine.py library --query timeline --executable true
python <Skill>/scripts/report_engine.py library template.timeline/horizontal-4
python <Skill>/scripts/report_engine.py library component.topology
python <Skill>/scripts/report_engine.py components topology
python <Skill>/scripts/report_engine.py validate --input <Skill>/assets/design-system/examples/design-preflight-timeline.json
python <Skill>/scripts/report_engine.py build --input <Skill>/assets/design-system/examples/design-preflight-timeline.json --output <new-project> --geometry-policy computed
```

选型过程：真实四点整页模板是`template.timeline/horizontal-4`，但它不是局部紧凑variant；`vertical-3`容量为三点，不可偷删第四事件。`chart.vertical-timeline`当前输入要求start/end/value，不能给只有日期事件的材料编造持续时间或数量。示例改用已注册`component.topology`的layered右向线性链，明确三条边仅表示时间先后，关闭箭头，保留全部日期事件。节点及原生连线由引擎计算，等距不代表时长；这是同一组件的参数实例，不宣称新增了timeline组件或compact variant。

外层column按标题→顺序带→必要范围说明阅读，顺序带预算112px、节点宽度220px、统一body角色；这些是可重算约束，不是最终坐标。实际长标签需重测，不能把样例容量直接套成所有事件都能放下。若必须让日期与事件使用不同字阶、在节点下展开长说明或按真实日期间隔定位，先查可用完整模板或另行实现受测试的专用组件，不在此示例接口上谎称已支持。导出后仍核日期对应、节点顺序、文字和连接线。
