# 从沟通问题到汇报内容

最终产物是用户可用的 Markdown 内容。按当前缺口选择下面的动作，允许往返、合并和跳过；不把读完所有方法或建立全部图当作开始写作的条件。

## 先确定这次在帮谁解决什么

从请求、议程、评价标准和已有材料判断：实际由谁向谁说，听众已知什么、需要形成什么判断或行动。委托制作的人可能只是助理；不能因为材料由其提供，就让正式正文说“根据用户原话”，或把项目组行动改成其个人成绩。

目标清楚时沿用。存在会改变主线的不同结果时，用[目标发现](goal-discovery.md)比较实际差异，先利用材料，再问最关键的未知。若目标依赖的事实不成立、权限不够或条件不足，提出可行的较弱结果及补件，不替用户保证对方会批准。局部修订无需重开目标探索。

## 找到有用的区别与支持

材料只有流水账、矛盾或空泛概括时，用[解释探索](insight-discovery.md)恢复事实锚点，改变看问题的关系、粒度或边界，判断是否出现会改变理解或行动的新区别。保留竞争解释和重要交互；无实质盲区时不继续发散。新角度缺事实就取证，不靠再造概念补齐。

区分“资料如此记载”“观察到变化”“优于可比基线”“某因素导致变化”“未来可能实现”。主张每提升一层，检查是否有相应支持。重要用途可以讲清，不因缺收益数据退成无意义清单；但不能把用途变为已实现效果。

为影响主线的缺口说明：哪项判断受影响、最小需要什么资料、可向哪里取得、拿不到时仍能怎样表达。方法卡按[具体推理问题](reasoning-methods.md)使用，不逐卡通关。数值按[复算方法](numeric-evidence.md)核对版本、区域、单位、公式和舍入；已确认CSV定义时可用[显式计算](report-calculation.md)。工具输出不是业务定义或因果成立的证明。

## 选择怎样完成这场沟通

选择的是听众参与和理解的方式：快速同步、共同讨论、逐项决策、原因复盘、方案比较或操作说明。用户已指定形式时先尊重；只有该形式明显妨碍已确认目标时，说明原因并提出可选改法。

从听众已有知识、权限、可用时间、是否会提问和是否独立阅读，决定先交代什么、哪些要直接比较、需要多少解释。协调会可先让对方看到要决定的事项及依据；对背景陌生的听众可能先需要共同事实；复盘需要事件与机制的支持。它们是基于本次材料的选择，不是固定文种目录。

有实质分歧才比较候选路线：起点、必答问题、证据负担、主要取舍和结束状态是否不同？换一种模型名或标题不算新路线。时间与预期疑问按[会议表达](meeting-expression.md)处理。

## 组织叙事，写出正文

从最终希望形成的判断反查前提；按共同回答的问题分组，再安排听众理解的顺序。复杂长句与零散记录用[语义组织](semantic-structuring.md)辨认真实关系：顺序、依赖、因果与影响不能互换；原文声称与推断分开。局部并列不决定全篇路线。区分背景、证据与目标相关性：过渡语只能连接已有关系，不能补出缺失论据。

采用[叙事与内容检查](narrative-page-behavior.md)串读关键判断，并从结尾逐项回查支持。一个内容单元要让听众理解什么，决定其事实、解释和条件，而非由模板分配模块。需要分页时按内容关系和讨论节奏建议页数；直接比较的内容尽量共同组织，多个独立问题可以分开。不强制“一分钟一页”、每页三点或结论式标题。

按[观众成稿编辑](audience-copy.md)写出实际能说的话。先提炼下层事实共同说明的判断，再写具体对象、动作、状态和意义。保留有据的工具分工与用途，不缩成“采用合适方法”；也不补造未知负责人、日期或成绩。

默认的一份 `汇报方案.md` 可包含简明安排、直接正文及必要待确认/来源。安排写给委托者，正文写给实际听众。短任务不用凑齐这些部分；`analyze-first` 可停在明确的方向取舍；仅润色时交付修订即可。[完整合成样例](../assets/examples/report-proposal.md)展示分区及条件，不要求照抄结构。

## 交付前按实际内容检查

暂时不看制作说明，只读正文：能否说清发生了什么、为什么与本次沟通有关、哪些仍有条件、需要什么行动？随后对照原要求、事实与来源，补回重要遗漏，撤回无依据的概括。只读标题辅助检查主线，不代替论证检查；模型复述不代替真实听众反馈。

关键条件贴近其判断。重复的“不能证明”“不代表”通常应通过收窄主张或明确对象解决；制作命令和核验日志留在工作记录，不能搬进讲稿。来源用材料名称和定位供核对，不自动铺出每个内部ID。交接范围按[最小证据交接](evidence-handoff.md)，需要时用[计算说明](../assets/review/calculation-note.md)和[证据清单](../assets/review/evidence-inventory.md)，不要求附全部旧稿。

内容交付后停止，不自动启动页面生成或视觉验收。下游可自主制作，只需保持事实、关系、条件与真实发言身份；本 Skill 不替下游承诺视觉效果。

## 局部修订与必要留存

锁定用户授权的目标、范围和原稿。措辞修改保持数字、责任和主线；新事实只复核相关判断；目标或受众实质变化才重新检查取舍和叙事。改动后核对新措辞是否扩大结论或删去条件，相关正文与必要附件同步更新。旧版检查不能直接贴到新版。

普通对话或一份MD无需先建Run。需要持久追溯、复杂版本或续接时按[Run操作](report-run.md)和[版本接纳](version-lifecycle.md)保存真实记录，语义关系与版本依赖见[多图模型](graph-model.md)、[工作区契约](workspace-contract.md)。记录只保存可审阅决定、证据与理由摘要。初始化不代表读过材料，结构校验不代替内容审查。

仅按用户明确要求使用[确认画像](report-profile.md)和[私有经验](report-experience.md)。历史偏好和案例可提示问题，不覆盖本次目标或项目来源，不自动写入长期条目。
