# 生成、分析与修订方法

按当前工作缺口选择以下动作。它们可以往返或省略，不是固定工作流。跨图对象的含义见 [多图模型](graph-model.md)，保存规则见 [工作区契约](workspace-contract.md)。

## 建立或续接工作记录

需要文件留存时，按 [生成 Run 的建立与续接](report-run.md) 使用新目录或接续已有 Run。接续先只读检查，再读取本次需要的记录、已登记材料和用户新要求，确认仍适用的目标、范围与未决项。文件已登记不代表已经读懂；历史完成或结构通过也不代表材料仍是当前口径。简单对话无需为留痕强制调用脚本或填满所有 Graph。用户启用并确认长期条目时，按 [画像操作](report-profile.md) 在Run和安装目录外显式保存/查看/修正；本次临时要求直接优先，不必改永久条目。

## 目标与候选策略

目标含糊或前提改变时用 [目标发现](goal-discovery.md)，从材料正推可能效果、从受众需要反推判断与依据。沿用已确认且仍适用的选择；需要主次取舍时呈现简洁策略图，使选择实际改变必答问题、补证和内容。局部修订不必重新选择目标。

## 从材料发现解释

现有表示不足时用 [解释探索](insight-discovery.md)：保留事实锚点，选择表示变换，辨别候选的重复、竞争、机制链与交互，再作解释、论证、沟通三层收敛。专业知识只能在有效许可内按需读取，不能替代本次项目证据。没有实质盲区时直接组织已有内容。

## 论证与证据反推

区分“资料如此记载”“已观察到变化”“优于可比基线”“某因素导致变化”“未来可能实现”。每次提升结论强度，都应检查是否增加了相应证据。

选择能挑战本项推理的具体问题：对象和时间是否相同，比较是否同口径，推理前提是否成立，是否存在反证或竞争原因，同一来源是否被重复计票。问完方法清单不代表充分；只留下会影响判断的问题。

证据请求包含：服务的主张、当前不足、最小必要材料、可能取得的位置、取不到时的较弱表述。没有数据不直接证明主张为假；执行失败也不等于假设被推翻。

重要数值按 [数值声明与复算](numeric-evidence.md) 绑定实际输入版本、计量区域、公式与舍入层级。正文中的估时、预算或模拟应保留模型假设；有同口径复算才能声称计算已核对，有实际测量才能声称实测。当前定义缺失时保留缺口，不用自选口径填成作者原意。已确认CSV范围与公式后，可按 [显式计算](report-calculation.md) 生成真实输入/规格/结果/凭证，再以独立算式或适用oracle复核；工具成功不证明业务可比或因果。

## 从关系收敛为内容

围绕听众需要回答的问题组织模块；用完整判断表达观点，而非仅“背景/成果/未来”等标签。检查下层判断即使全真，上层是否仍缺条件。

合并重复但保留有意义的差异、独立贡献和反证。论点取舍不能简化成“越少越好”或数字权重相加。内容可以进入主线、备份、待研究，重要限制要在读者作出判断时可见。

区分解释桥梁、证据桥梁和目标桥梁。过渡句不能补证据。叙事顺序可以调整，但不能把说明、先后或支持改写成因果。

## Blueprint 到页面

按 [叙事与页面行为](narrative-page-behavior.md) 的触发条件实际执行，不只填写检查表：N01从确认结果找必答，再由模块反查职责；有实质路线分歧才用N02比较；N03串读关键判断并从结尾反查支持，缺背景/证据/目标相关性时返回对应层修复。

Blueprint 至少能让读者回答：本次采用什么目标，谁需要回答哪些问题，核心判断是什么，凭什么成立，限制是什么，模块之间怎样关联，还缺什么。每块内容应对某个必答问题负责；保留会改变判断的证据定位及未决项。做“只读核心判断”和“从模块倒推问题”检查：如果目录换了但必答问题、证据和篇幅取舍没随目标改变，回到目标与内容映射修正。

先用P01明确本页问题、理解变化与必要前置；P02核对关键细节、角色和主张强度；删减/合并时按P03保留重要内容去向。可以记在原Blueprint/笔记中，不向渲染JSON加入未定义字段。页面计划再决定听众在此刻需要理解什么、什么必须共同看见、什么可逐步展开。一个模块可跨页，多个相关单元也可同页。图形、大小、位置、颜色和箭头不能新增未获支持的含义。需要HTML时按 [内容到HTML](report-html.md) 形成显式页面计划，用随包工具生成，并在真实浏览器检查最终页面；生成回执不等于视觉通过。尚无渲染能力时交付页面语义及真实边界，不制造截图或布局通过记录。

## 局部修订

按叙事与页面行为R01先锁定原产物版本和用户允许的范围；间距修复保持数字/主张/结构，重大目标变化再重查路线。新修订 Run 将原产物登记为待修改的 Source；快照不是已经采用的新产物。继续旧 Run 时先核对已有记录，新材料或新版本显式登记，保留旧快照，再按 [版本变化操作](report-run.md) 查询旧版本的影响。数据或口径变化影响相应依据；目标变化影响策略与内容选择；仅改文案或布局通常不需要重算所有数据。按明确依赖识别影响，仍需判断新措辞是否增强结论、删除限定。

保留历史版本与旧检查的适用对象。新产物不继承旧版通过标签；无关部分保持不动。需要可执行的选版和结果接纳记录时，按 [版本选择与结果接纳](version-lifecycle.md) 登记实际新产物及依赖、明确选择，再凭真实复核的精确目标 Check 记录接纳。工具保存声明和指纹，不替代复核；遗漏依赖仍需人工发现。公开说明实际修改、重查内容和仍未解决的问题。

数值口径变化时同步修正依赖它的计算、正文和必要附件；补证时注明收到时间与本次重查，不倒写过去的执行。当前摘要和检查说明应给出最新适用判断，历史原判及其证据另行明确标识。

## 交付可检查的当前版本

按 [最小证据交接](evidence-handoff.md) 提供实际产物及支持本次判断的来源定位、必要定义与真实输出。当前数值依赖自定义计数或舍入规则时，应随交付说明该规则；无需为此附上所有旧稿和审计意见。只有本次涉及修订谱系、过去执行等问题时才补相关历史依据。

清楚区分已提供、本包省略、当前不可得和不在范围；缺少历史附件不等于它从未存在。可选 [计算说明](../assets/review/calculation-note.md) 与 [证据清单](../assets/review/evidence-inventory.md) 用于材料较多时，短任务可直接写必要信息。采用 Run 时沿用 Source/Artifact、`uses` 和 Check 的精确版本引用，不强制增加图或必填文件。

## 诊断、编辑与会议使用

遇到具体判断缺口按[思维方法](reasoning-methods.md)挑选操作，改前后说明处理的是概念、前提、关系还是证据桥梁。价值表达既查有依据的重要意义是否遗漏，也查是否越过观察支持；“可帮助比较”不能变“已降本”，无金额也不必退回功能清单。

路线有实质分歧时先给简短草案，比较起点、必答、证据和结尾而非只换标题。会议质疑与时长变化按[会议表达](meeting-expression.md)重排主线/Backup/补件；页面设计按[视觉编辑](visual-editing.md)先真实粗排再精修。局部反馈先诊断属于用词、关系、容量或目标；明确只改间距不得改变数字或路线。

用户要求留存有用反馈时，按[私有经验](report-experience.md)显式保存/检索/修正；偏好、任务观察和待验证方法候选分开。历史案例只能提供问题与条件线索，不覆盖当前来源，不自动更新规则。

页面默认沿用[视觉编辑](visual-editing.md)中已确认的近白浅蓝、轻薄柔影与克制磨砂方向，以内容职责分配空间。保留一个醒目主标题；巨型淡字后景和轻微错位仅用于适用的封面/转场，不能成为每页模板、重复标题、装饰截图或改变数据含义。用实际复杂页核对正文对比、关键条件与图形完整性。
