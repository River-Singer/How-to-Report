# 自有模板的参数化 PPT 制作

新稿及实质结构变动先完成[制作前设计评估](ppt-design-preflight.md)：将已成立的内容路线落实为每页任务、材料与数据准备、真实组件选型、栅格读序和容量约束，先廉价核对再成图。随后沿[PPT Storybook](ppt-storybook.md)取用注册模板、原生资产、图标和[68种图表资产](../assets/design-system/chart-assets/README.md)，由engine计算。下述scene/chart模板的类型限制是原接口兼容合同；新图表按`chart-assets`实时合同使用，输出编辑等级与原生Office Chart分别说明。

需要查看全库、按页面任务寻找原型，或需要跨页数据绑定、自由组合与持续修改时，按[作者工程入口](ppt-engine.md)使用inventory、variant查询及版本化文档。既有参数模板与原生制作继续适用本页合同。

对象、局部组件和推荐组合通过library发现，3个有限recipe可用compose生成带profile身份的作者工程。具体slot、可选child及正常调用见[组件系统手册](ppt-component-system.md)。

内容确认后按[交接方法](ppt-handoff.md)继续。先读[模板索引](../assets/templates/README.md)及所选模板的AI说明，再依据本次沟通选择family和variant。制作流程提炼自PPT-Master的规划、结构SVG、原生转换和检查方法，实际来源见[技术来源](../runtime/ppt-engine/provenance.json)及[MIT许可](../runtime/ppt-engine/LICENSE)。

## 沟通与页面关系

沿用真实汇报者、听众知识、目的、时间和阅读方式。现场版由已交付口播补足解释，独立阅读版在页面保留必要关系。正文和口播直接向听众发言，按[听众表达](audience-copy.md)处理具体表达和真实归属。

先确定比较、顺序、归属、层级或依赖等关系，再选相应variant。箭头、分组、中心位置和大小有资料支持。封面、章节和结束页按本次需要使用，页数及密度服务实际沟通。

## 参数、tokens和资源

模板AI说明交清输入、默认值、文本字段最短最长字符数、variant差异及调用方法。按实际schema填参数，所有可编辑文字可回到输入或明确派生规则，零、缺值、待定和可选空文本保留各自含义。

统一tokens提供纯白16∶9画布、标题位置、页眉页脚和正文区、颜色、字体、字阶、间距、线条及图表表格样式。单页使用允许的配置和字阶。几何变化同步结构合同，结构variant使用与其槽位对应的Layout。

字符范围与实际测量共同检查容量，按字体、字号、字重、字距、行高及框体估算，再渲染核对换行。容量不合适时选择有据改写、适当variant或明确的内容/页数调整，保持统一tokens的字阶与几何。

只使用所选自有模板和用户允许的本地资源。图片承载业务数据时，在材料分析阶段实际查看原图，提取可读数字、单位、日期、筛选范围、关系与趋势，与正文合成有依据的判断。将所需信息组织为可编辑指标、表格、图形或图表，核源时同时对读原图。趋势图缺少精确序列时，按可支持的趋势或约值表达，精确数据须有对应来源。

图片本身承担界面识别、证据展示或案例说明时，按该用途决定完整展示、裁切与局部放大，核对最终尺寸下的重要信息可读性。业务截图保存在报告项目，其在成品中的使用由实际任务决定。

先实际查看Word等输入中的配图，判断哪些需要让听众看到原貌。已有截图能承担界面/工作成果证据，或复杂图形暂不能由现有组件准确重建时，可直接使用原图，由现有image组件与computed容器完成排版，不必为重画它先扩展引擎。原图不会自动补足未记录的指标或证明效果；重要数字比较仍优先从可核数据生成图表，保留必要上下文与来源。图片内部文字和形状仍是图像，不宣称成为原生可编辑对象。

若关键配图缺失且用户已授权占位，使用明显矩形占位并说明待补内容；由布局树计算位置和尺寸，在作者说明列出用途和建议图片。占位不能冒充截图、完成证据或最终视觉已验收。不得用无关图片撑满页面，也不由AI手填坐标或自由绘图。按[数据表示任务](ppt-data-display.md)选择图、表或证据图：不能把解释任务中的报数段落截图以规避图表表达；真实业务界面的列表和供核对的明细表各有适当用途，仍核最终可读性。

先看有效内容区域、无关白边和主体焦点。需要完整关系、数轴、单位、图例或界面上下文时使用contain。插图需要充满框且主体可以安全保留时使用cover，并用image_position九锚点选择左中右、上中下焦点。按最终显示尺寸调框和裁剪，必要图注、来源与说明保持独立可编辑。原生裁剪保留完整图像范围，项目images保留原始本地资源，嵌入媒体按引擎既有规则可能规范化或等比优化。图片的alt当前进入SVG desc，PowerPoint替代文字以实际保存和回读范围确认。

## 按关系选择图表

先按[数据表示选择](ppt-data-display.md)判任务：查阅对象与核对明细时直接选简洁表格，解释数据时完成[业务数据分析](business-data-analysis.md)，沿[数据加工审核](ppt-visual-review.md#数据加工先于版式判断)核口径、必要派生、基准和业务含义，再选能表达变化、差异、构成或关系的图。逐图合同、能力状态、FT九类目录和调用见[图表使用场景手册](ppt-chart-usage.md)。关键量、单位、分母/基准在图面清楚可辨。孤立单值没有关系可编码时不强造柱图；混合任务的主图与必要明细分工，避免重复。

- 柱形适合比较类别规模、排名或少量时间区间的离散总量，条长从零开始，比较使用共同尺度。长名称或强调排序时可选择支持的横条表达。
- 折线适合真实有序观测的变化。当前普通scene和chart模板使用等距类别，适合等间隔序列，保留null缺口，不承诺连续日期轴或实际非等间隔时间。截图只提供趋势和一个精确读数时，可用趋势说明与该读数卡片表达，有据的精确序列再用于逐点折线。
- 折柱组合适合同一期间或类别的两项有关指标，需要数量与比率等并置才能帮助具体判断。明确两项单位和各自轴，检查缩放是否会制造同步印象，必要时采用对齐的小图。当前combo已有底层原生路径，公共scene和chart模板入口待接通。
- 饼与环形适合用非负量表示同一整体的互斥部分，期间、范围和分母一致，分项合计与整体对应并保留舍入说明。少量差异明显的部分较易阅读，细微差别或较多类别可用柱条。环形的中心可放需要强调的总量或占比。存在重叠的功能用户分别比较其规模或采用情况。
- 单个重点量可用指标卡，有明确目标的量可用进度或目标对比。流程、归属、依赖和行动使用相应关系图或结构卡，位置与连接承载真实关系。

当前自有chart参数族公开column、line、pie与doughnut，scene另支持bar，比例环可使用progress-ring组件。模板饼环的数值/占比文字使用外部图例区域，开启show_data_labels时需要同时开启show_legend。采用其他图型须有实际支持该类型的制作入口、完整原生数据、对应预览与导出检查。底层支持范围和参数族已开放范围按实际能力说明。

数量图先明确类别、单位、数据域、尺度和基线，实际数据决定几何。Chart/Table使用完整原生payload，数据和可见表示保持一致，导出显式激活原生对象。表格先排清行列含义、数值对齐和精度，再应用tokens样式。通用选择与可读性依据见[离线来源](method-sources/sources/chart-image-production.txt)。

## 实际制作接口

参数入口为[report_ppt.py](../scripts/report_ppt.py)，按其`--help`及模板文档操作。它将内容、config、variant和tokens编译为包外项目的`svg_output/`、本地资源、逐页口播和数据payload。

[ppt_runtime.py](../scripts/ppt_runtime.py)提供通用制作接口。

```text
python <Skill>/scripts/ppt_runtime.py check <项目根> --tokens <tokens.json>
python <Skill>/scripts/ppt_runtime.py export <项目根> --tokens <tokens.json> --output <新输出.pptx>
python <Skill>/scripts/ppt_runtime.py inspect <输出.pptx> --tokens <tokens.json>
```

Python调用为`check_project(project, tokens, notes=None)`、`export_project(project, output, tokens, notes=None)`、`inspect_pptx(pptx, tokens=None)`。tokens可为JSON路径或已解析对象，包含完整`theme.slots`、`font.families.title/body/latin`、`font.sizes.title/body`及`canvas.width/height`或`layout.canvas.width/height`。输入项目包含`svg_output/*.svg`及可选`notes/<SVG stem>.md`，资源按项目相对路径引用。显式传入notes时，检查与导出使用同一份映射。Python进程已加载其他来源同名制作模块时，使用包内CLI在新进程执行。

check运行保留的SVG契约检查、跨页结构合同、画布与白背景检查，确认字体和文字度量helpers可用。`validation/ppt-check.json`绑定本次SVG、资源、备注、tokens及实际runtime身份。export要求通过报告与当前输入一致，核对哈希后复制本地源快照供builder读取，在临时原生包中显式注入完整12色槽、major/minor字体和Master字阶。发布前再次核对当前输入与runtime，回读通过后发布新文件，导出回执保存所消费的检查身份。改变输入后重新检查，已有输出采用新版本。

inspect读取实际PPTX的画布、所有Theme色槽和字体、Slide/Master/Layout数量、形状名称、文字、几何及字体信息。返回值支持稳定对象名称与模板几何对照。传tokens时比较实际画布和Theme值，未传时返回实际结构。

## 成品检查与修订

结构通过后渲染实际页面，逐页查看溢出、重叠、缺项、对齐、主次与可读性。模板逐variant调试全局标题、页眉页脚、正文区和真实文字容量。文字估算与长度检查分别记录覆盖，字体显示由实际渲染和目标宿主结果验证。

对实际PPT成图单独执行[模板适配与数据可视化审核](ppt-visual-review.md)，核当前模板是否匹配页面任务、库内是否有更合适的具体原型，以及图种、范围、尺度、读数和截图可读性。结合layout_plan、asset_usage和真实候选形成逐页证据、取舍和具体修法，修订后复验受影响页面。本层与内容、常规视觉和编辑操作分别记录。

依据最终页面更新口播，讲清主要事实、证据、关系和条件。按[生成主线D](reporting-method.md)对读屏文和口播，制作提示放在作者区域。讲述时长通过实际排练验证。

按任务需要在目标PowerPoint中修改文字、移动形状、修改图表数据或表格单元格，保存并重开确认。手工编辑后回读Theme及已命名对象，具体样式符合性按模板对照范围判断。实际视觉、编辑、内容审计和真人理解分别记录。

原生PPT保留式编辑需要实际编辑能力、原件对照与对应操作验证。该SVG接口的结果覆盖本次结构SVG项目。失败时保留当前稿、参数和已有文件，按具体原因修复并继续。
