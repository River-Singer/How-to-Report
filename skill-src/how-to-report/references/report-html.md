# 从内容蓝图到可运行页面

需要 HTML 汇报时，按 [叙事与页面行为](narrative-page-behavior.md) 执行适用的P01–P03、V01–V02、S01、M01、L01–L02、A01检查；先做真实选择/核对/修复，再记录证据。先按 [生成与修订方法](reporting-method.md) 形成 Content Blueprint，再选择页面必须让听众理解的问题、判断、证据和限制。页面不是内容单元的固定一对一投影；不为凑齐布局而拆页、补数据或强化主张。

## 从内容关系选择同屏组合

一页可以同时承载不同拓扑：用主面板呈现中心分析，辅助面板提供层级、对照、趋势或必要证据。先说明各块回答什么问题、为何需要同屏，再安排空间、比重和阅读顺序；不要把每页强制套进一种卡片模板。递归布局只描述空间与元素引用，不能从相邻、大小、连线或层级自动推出业务结论。简单内容仍可使用下列兼容布局，不必为展示能力增加组件。

- `focus`：一个中心判断及必要支撑，重点必须能独立读懂。
- `compare`：需要同屏比较的对象；先核对单位、时间和比较口径。视觉并列本身不证明可比。
- `sequence`：有理解先后或阶段关系；先后不自动代表因果，也不暗示每阶段都已完成。
- `data`：有同口径数值的比较，保留单位、数值标签及缺失说明。缺失值用 `null`，不能补零；没有可信数值时选择文字布局。

组合时可用文本、层级、指标和有根据的图表承载内容。条形适合可比数值，折线要求真实顺序和时间口径，热力矩阵要求行列交叉的同口径测量；没有可信数值时用文本/关系结构，不借用工程样例数据。折线缺失要留缺口，不能跨缺失连线或补插值；矩阵空值不能变成零或最浅色而不说明。

布局选择由内容责任决定。图形、颜色、大小、排序和标题不得新增材料未支持的关系。重要限定必须在读者作判断时可见，不藏在页外或只有生成者能读到的字段中。

## 显式页面计划与离线生成

使用本包 [HTML 工具](../scripts/report_html.py) 和 [工程样例](../assets/report-html/sample-plan.json) 所定义的页面计划0.1。样例仅演示字段与布局，属于合成工程资料，不是用户事实或通用答案。普通任务只采用实际需要的页面和元素。

根字段为 `page_plan_version:"0.1"`、`title`、`language`（`zh-CN|en`）和 `pages`，可另加 `canvas:{width,height}`：width为1200–2400整数，height为675–1600整数，宽高比1.2–2.4。省略时使用1600×900预设；同一配置驱动画布、窗口缩放与打印，不支持任意CSS尺寸。所有页有 `id/layout/question/title/takeaway/limits/refs/elements`；`limits`至少一条真实范围/限制，引用为 `{id, revision}`（revision是正整数），可加 `locator`。页、元素及内嵌数据ID在整份计划中唯一，以ASCII字母开头，后接字母/数字/下划线/短横线，最多64字符。只用已定义字段；引用形状正确不证明原材料存在或支持文字。

**简单计划兼容路径：** `focus`支持1–3元素，`compare`恰为2，`sequence`为2–5，`data`为1–8。简单元素用 `id/title/body/refs`；数据页另加 `unit`，每元素另加 `value`。这些边界只限制当前工具形状，不是业务观点配额或任意长文字能装下的保证。

**组合计划：** 页用 `layout:"composed"`，另有 `tree`，允许1–12个元素。布局叶为 `{element:"元素ID"}`；容器为 `{type:"row"|"column", weights:[正有限数字], children:[节点]}`。每容器2–6个子节点，weights逐项对应，用相对权重表达主辅空间；最多5层、31节点。每元素恰出现一次，所有叶须全覆盖元素，按树深度优先读取的叶序必须等于elements数组顺序。不能重复放置同一元素来制造多份独立证据，不能把空间树当因果/业务关系图。

组合元素公共字段为 `id/type/role/title/body/refs/limits`；`role`为 `primary|supporting|context`，`limits`至少一条真实范围/限制。类型及额外字段如下：

| type | 额外字段与边界 |
|---|---|
| `text` | 无额外字段；用正文表达完整判断和支持 |
| `metric` | `unit`、`value`；数值突出不等于已核验绩效 |
| `hierarchy` | `levels`为2–5项，每项 `{id,label,body,refs}`；明确层次关系是什么，勿默认组织权责或因果 |
| `chart` | `chart`对象，使用下列三种有明确数据形状的图表 |

| chart.kind | 其余字段 |
|---|---|
| `bar` | `unit`、`items`（1–8项 `{id,label,value,refs}`） |
| `line` | `unit`、`x_labels`（2–8标签）、`series`（1–3项 `{id,label,points}`）；points与x_labels逐项对应，每点 `{id,value,refs}` |
| `heatmap` | `unit`、`rows`与`columns`（各1–6标签）、`cells`二维数组；每个行列交叉必须有 `{id,value,refs}`，不能省掉缺失单元 |

全部数值是有限JSON数字、范围±1e12或 `null`；布尔值不能当数值，value字段不得省略。null明确表示不可得；不能补零、插值或跨缺口连线。折线的x_labels按序等距排布，不自动解析日期或不等时间间隔，不能据不适合的间距推断变化速度。层级label、条形label、各线的label、x_labels及矩阵各轴标签在所属集合中忽略首尾空白/大小写后须可区分。内嵌level/series/point/cell/item的ID也全局唯一。

每个level/item/point/cell有其精确refs；series以其points承载引用，metric使用元素本身refs。页面与元素限制必须跟相关显示可见。元素引用索引提供阅读定位，DOM与page-map保留各数据项的精确引用；仅编号一致或映射闭合不证明来源支持内容。

```text
python "<本Skill目录>/scripts/report_html.py" render "<实际page-plan.json>" --output "<新的HTML输出目录>"
```

必须使用尚不存在的输出目录，父目录已存在且位于安装包之外。工具只读取明确的本地JSON及随包运行资产；按文本转义，不执行计划中的HTML/脚本，也不获取外部网址。生成 `index.html`、捕获的 `plan.json`、`page-map.json` 和 `render-receipt.json`。HTML 自带受控样式与脚本，可离线打开；不依赖 CDN、联网字体或其他Skill。

V01先判断文字/表格是否足够；V02核定量数据适配；SVG按S01检查关系含义、比例/内部标签和文本替代，多视图按M01核共同问题与口径。这些动作可在Blueprint/现有笔记留证，空间树不能代替它们。

生成回执只说明实际输入与产物字节、结构检查和生成动作。它不是浏览器通过、语义通过或正式接纳。不要直接把回执状态抄成 Run 的内容 Check pass。写入失败保留可核查的部分结果，使用新目录重做，不覆盖旧交付。

## 看实际页面再交付

按L01使用真实长标题/标签/限制粗排，失败先重分空间、去无用装饰/重复，再换表达或分层/拆页；保留必要同屏比较。L02与A01检查实际逐页/逐支持状态与注意力，不能由占位内容、CSS属性或截图稳定直接判通过。

1. 在可用浏览器打开最终 `index.html`，实际操作翻页按钮、键盘、直接页链接及窗口缩放；打印样式须在实际打印媒体中检查。
2. 逐页检查真实文本、数值、来源和限定的位置；检查关键内容是否越界、重叠或过小。使用运行时 `window.reportDeck` 的布局检查结果作为几何证据，并保留浏览器、窗口尺寸、HTML哈希和实际返回值。不要把源码检查冒充浏览器检查。
3. 对照实际页面的读者含义：主辅空间是否与内容责任一致，组合是否暗示未经支持的关系，比较是否可比，顺序/层级是否暗示因果或权责，折线是否跨缺失连接，矩阵色阶是否掩盖数值/单位，标题是否升级确定性。几何通过不能证明这些语义问题通过。
4. 内容过载时先回到内容取舍、拆页或换拓扑；不静默删限定、缩成不可读小字或裁掉关键内容。保存修复前后版本，重新检查受影响页面。

无浏览器时仍可交付HTML及结构检查，明确布局、交互和视觉语义未验证。工程样例的浏览器结果不能转用于本次新报告。

## 接入 Run 与独立审计

工具不自动修改 Run。按 [版本选择与结果接纳](version-lifecycle.md) 登记实际计划、HTML及映射等产物及真实依赖。若HTML依赖内容计划，计划应声明其实际内容/来源/目标依赖；不能只登记最末端文件而漏掉上游。真实复核后才写精确产物版本的 Check；生成成功不等于可以接纳。

修订使用新计划版本与新输出目录，保留旧页面、检查和说明；目标改变时重看内容责任，数值改变时同步相关标签、正文与图形。工具不自动重算业务数据。

独立审计先看实际页面，记录读到的含义，再按需要读取生成计划与映射。交接时把计划作为后读附件，说明暴露顺序和独立性；不能因为字段齐全、ID可对上或生成者称已通过就给出独立结论。
