# 理解并核对项目进度

用于进度、里程碑、预测或验收的事实需要核对时。先看听众要了解什么、需要决定什么；已有周报、表格或一句更新即可，不要求用户先填写 JSON。内容组织和是否分页由当前沟通任务决定。

## 把不同事实分清

- 明确记录截至哪一天，原计划是否获批以及实际采用哪版。没有基线仍可以说明现状，不能凭空计算延期；没有当前预测，不复制原计划或旧预测补上。
- 已完成、正在进行、尚未开始和受阻说的是执行状态。验收是另一个判断，需要知道标准、范围、结果和依据，局部接受不自动证明项目整体验收。
- 预测日期与已发生的日期分别表达。重要依赖写在对应判断旁，例如“预计1月6日完成，接口审批时间还未确认”；无需反复解释“预计尚未发生”。
- 只有有明确计量依据时才报告完成率。经过的时间、任务条数和工作量不是同一件事。没有报告百分比，不必专门讲为什么不报。
- 相对原计划的偏差按同一日期口径计算。任务日期差不能相加成为项目总延期，预测变化也不是已造成的损失。
- 行动请求与已实施措施分清；缺少记录不等于没有发生。材料支持真实用途和阶段结果时把它讲清楚，不把正文写成核验日志。

先用这些区别理解材料，再按目标选择需要讲的内容。协调会可能重点说明待解决的条件；复盘可能需要事件与原因证据；短更新可只保留重要变化和下一步。不要为了方法完整把所有字段变成目录。

## 按需使用离线日期工具

遇到需要重复核对的日期、状态、基线和依赖时，可将已有记录整理成[合成输入示例](../assets/schedule/sample-schedule.json)所示的结构，运行：

```text
python <skill>/scripts/report_schedule.py validate SPEC.json
```

[ScheduleSpec 0.1 结构参考](../assets/schedule/schedule.schema.json)供工具输入使用，不是汇报模板。工具仅依赖 Python 标准库，在本 Skill 内独立运行；只读输入并返回核对结果，不写文件、不改 Run、不排程、不生成图或页面。输出含实际输入/方法哈希、日期比较与来源引用、警告，以及未执行的语义审查状态。正文使用经过判断的结论，不直接粘贴 JSON。

当前工具支持自然日、日终状态、1900—2100年日期和零间隔的完成—开始依赖。实际日期不得晚于状态日；剩余预测在状态日之后。已完成任务需要实际完成记录，未知端点保持未知。日级记录不能核实同一天内交接的先后顺序，工具会返回具体警告；不自动挪动日期消解冲突。

历史预测与本期比较使用明确的同一批准基线。不同基线分组核对；旧记录不改写。报告日等于本期状态日且两处都给出预测时，日期必须一致。历史预测报告日晚于已记录发生日时保留原记录并提示核对当时可得信息和双方来源，不自动判定来源作假。缺历史点不插值，单个记录也不形成变化趋势。

`date_comparisons`逐项返回原计划完成日、当前实际/预测完成日及自然日差；缺任一比较端点时差值为 null，不补零。工具最多读取8 MiB输入，其集合数量上限用于限制本地处理资源；它们不限定汇报应讲多少事项或多少页。长文本不再受页面标题或卡片容量约束。可选`summary`仅检查选择项确实存在，是否遗漏重要问题由内容审查结合本次目标判断，不自动要求列出整个项目。

计算和结构一致不能证明项目事实真实。需要时将结果作为已执行计算留在工作记录，用简明资料名称说明重要结论的依据；核心内容审计仍核对实际来源、状态、条件与判断强度。
