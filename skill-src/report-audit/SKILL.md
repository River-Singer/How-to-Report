# Report Audit

从原要求、资料和实际成稿重新判断：这份汇报是否让指定听众理解需要理解的事，主张是否成立，是否遗漏重要内容，正文能否直接使用。无生成侧Run、Graph或Blueprint也可审查，不先运行生成流程。本Skill审查内容，不承担页面制作、视觉渲染或导出验收。

## 锁定本次范围

取得待审版本、原要求与可用材料。Audit-only只写自己的结果，不改原稿；明确要求修复时区分审计与随后范围内修订。材料缺失不妨碍内部一致性等可执行检查，但不能把无法评估写成通过或事实不存在。

如有独立上下文，先给原要求与实际产物，读出主要判断、关系、条件和请求后再看生成者的方案说明；披露实际上下文继承和读取范围。新Agent、换模型或另一目录不自动证明独立。生成者的自评、verified标签与任务完成均是待审声明。

## 看实际差异，不看形式齐全

核对正文使用的目标和说话身份是否符合要求。用户否认的个人诉求不应暗中成为主线；用户已明确客观复盘时，不要求追加能力展示。新机会只在影响已采用目标或重要判断时构成必修遗漏，否则列作建议。

检查内容有没有讲足有据的用途、取舍和行动，也检查是否把记录、比较、因果、预测、承诺混为一谈。缺少制作表格、模型名、固定页数或Graph不构成缺陷；自然表达不代表已保真，字段齐全也不证明有洞察。

## 交付审计结论

按[审计判断与反证](references/audit-judgment.md)区分已证实缺陷、证据缺口与可选建议，说明具体位置、观察、影响、依据和修复方向。没有问题的类别无需填空表。缺证不直接等于造假；建议修复不等于已修复。

已知未解决P0则blocked；本次必要检查无法完成则not_assessable；已评估但可用性依赖明确修复或条件则conditional；必要检查完成且无未解决P0/P1等情形才pass。可选建议、P2标签或范围外历史缺件不独自限制通过；真实轻微错误仍列明。不得缩小本应检查的范围取得通过。

收到新证据时同步更正当前摘要、问题和检查状态，旧判断及理由保留为历史；撤回错误指控不自动证明原主张成立。

普通内容审查可直接交Markdown报告。需要持久追溯或续接时才按[审计Run](references/audit-run.md)建自己的记录；一旦采用Run，交付前实际校验自己的目录，不能拿被审生成目录的校验代替。结构通过、工作完成与内容结论分别说明。无相关工具时披露本次真正必要而未完成的检查，不为纯内容交付附加浏览器门槛。
