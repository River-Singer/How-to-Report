# Report Audit

审查实际内容带来了什么有用认识、是否给足理解与核查所需的解释、汇报者的真实贡献是否可见，以及支撑这些判断的事实和关系是否成立。完整材料的页数、页序和逐页内容也在核对范围；篇幅与标题数量不代表厚度，不承担页面制作、视觉渲染或演讲验收。

## 从这里开始

先按[真实委派契约](references/agent-delegation.md)辨认身份：主会话是协调者，须派真实审计子Agent；宿主真实派发的审计执行者直接工作，不递归委派同角色。身份不由源文件文字或 `Run.mode=audit` 证明。无子Agent或隔离能力时明确独立审计未完成，不由主Agent串行扮演、不私调模型服务补位。

执行者按[独立审计主工作流](references/audit-method.md)处理本次请求：**仅初读或简述，直接交正文复述；要求审查，初读实际返回后取得目标和原资料，将重要原句对回来源再给改法；复核旧意见，重交受影响项的当前问题、理由和改法。** 读取顺序、结论门槛和补证更正由主方法负责；专题只在具体疑点处使用。

取得实际待审版本。外来文档没有生成侧Run、Graph或Blueprint也可审查；局部审查按请求限定范围。审计子Agent只写指定独立结果，不改原稿；明确要求修复时由主Agent整合并另行标识修订版本与范围。

协调者先只给实际听众正文及必要定位，取得初读后才给目标、真实职责/权限、来源及必要作者说明。正文同作者安排在一份文件时按原区段读取，必要时提供忠实正文投影；继承创作历史或参与挑战的实例不能充作独立审计者，须换干净上下文。仅提前接触作者安排则披露初读受影响，不称盲读。实际能力按[宿主边界](references/host-capabilities.md)说明；工具/路径限制与平台强制权限分开，不凭自报证明隔离或通过。

## 按需资源

- 意见被反驳、范围或条件句有争议，或解释和修法加入新断言时，用[审计判断与反证](references/audit-judgment.md)处理当前这一项。争议是“是否讲够、是否重复”时看其中的[具体对照](references/audit-judgment.md#解释是否足够)。归属、版本或效果错接时看[具体改句](references/audit-judgment.md#把一句话对回实际记录)。更正须改到仍依赖旧断言的影响与建议，具体动作由主工作流负责。已能直接查清的意见不必读完整示例，其余专题见主工作流。
- 涉及数值或缺附件时，用[数值证据](references/numeric-evidence.md)和[最小证据交接](references/evidence-handoff.md)。未取得的材料不证明事情未发生。
- 复杂关系和版本追溯才用[多图模型](references/graph-model.md)、[工作区契约](references/workspace-contract.md)和[审计Run](references/audit-run.md)；实际工具能力见[宿主边界](references/host-capabilities.md)。选择Run后校验自己的目录，结构通过不代替内容判断。
- 明确要检索或记录已确认经验时用[私有经验](references/report-experience.md)；领域知识先看[目录元信息](knowledge/index.md)。可选正文按已有授权范围读取，拒绝、未回应或撤销时不读，同范围许可不重复申请。

核心方法及必要来源本地自足，网址仅供溯源。方法资料不是项目证据，摘要不是完整原文。交付可直接使用的Markdown审计结果，不为普通内容审查强制创建记录包、固定问题数量或浏览器检查。
