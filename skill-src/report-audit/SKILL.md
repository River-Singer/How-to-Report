# Report Audit

审查实际内容带来了什么有用认识、汇报者的真实贡献是否可见，以及支撑这些判断的事实和关系是否成立。完整材料的页数、页序和逐页内容也在核对范围；不承担页面制作、视觉渲染或演讲验收。

## 从这里开始

按[独立审计主工作流](references/audit-method.md)进入本次请求：**仅初读或简述，直接交正文复述；要求审查，再核对来源并给有据问题及改法；复核旧意见，交清发生变化的判断和当前改法。** 读取顺序、结论门槛和补证更正由主方法负责；专题只在具体疑点处使用。

取得实际待审版本。外来文档没有生成侧Run、Graph或Blueprint也可审查；局部审查按请求限定范围。Audit-only只写自己的结果，不改原稿；明确要求修复时另行标识修订版本与范围。

正文与作者安排同在一份文件时，先定位正文区段；若已经看过作者解释或无法隔离，如实说明。可选并行遵守[宿主边界](references/host-capabilities.md)，先保持正文初读隔离，再拆独立疑点核查。生成者自查、在同一上下文中扮演多个角色或新建文件均不能冒称独立审计。

## 按需资源

- 意见被反驳、范围或条件句有争议，或解释和修法加入新断言时，用[审计判断与反证](references/audit-judgment.md)处理当前这一项。更正须让当前问题、理由和修法一致，不能留下仍可被采用的错误替换建议；具体动作由主工作流负责。已能直接查清的意见不必读完整示例，其余专题见主工作流。
- 涉及数值或缺附件时，用[数值证据](references/numeric-evidence.md)和[最小证据交接](references/evidence-handoff.md)。未取得的材料不证明事情未发生。
- 复杂关系和版本追溯才用[多图模型](references/graph-model.md)、[工作区契约](references/workspace-contract.md)和[审计Run](references/audit-run.md)；实际工具能力见[宿主边界](references/host-capabilities.md)。选择Run后校验自己的目录，结构通过不代替内容判断。
- 明确要检索或记录已确认经验时用[私有经验](references/report-experience.md)；领域知识先看[目录元信息](knowledge/index.md)。可选正文按已有授权范围读取，拒绝、未回应或撤销时不读，同范围许可不重复申请。

核心方法及必要来源本地自足，网址仅供溯源。方法资料不是项目证据，摘要不是完整原文。交付可直接使用的Markdown审计结果，不为普通内容审查强制创建记录包、固定问题数量或浏览器检查。
