# 独立审计主工作流

本文件负责审计的读取顺序、判断形成、结论、补证与交付。**实际成稿 → 对照目标与依据 → 复核意见和修法 → 交付当前结论。** 检查材料完成了什么沟通，以及这些内容为什么成立；共享方法帮助查清具体断点，不能把生成者的流程完成、自评或`verified`标签当作答案。

先确定待审对象与版本、用户要求的范围以及是否授权修复。正文初读前只获取定位所必需的信息，任务的详细解释与作者安排随后再读。已经从对话或工具读到的内容如实记录，不假装可以忘掉。外来报告无需先补生成笔记、图或Run；局部复核只重查受影响内容及关联结论，不例行重审全篇。

## 1. 实际成稿让人理解了什么

通过目录、标题或边界定位听众会接收的正文区域，先读实际标题、文字、表格与必要条件。完整《汇报方案》中的作者安排、页序表所写的设计目的、制作提示和自评先跳过；可读取既有区段，不要求再维护第二份当前稿。若工具已返回整份文件、各类文字无法分离或上下文已有作者意图，则披露真实接触范围，继续审查而不声称盲读。

用一段连贯复述交代正文让人理解或判断了什么、关键关系和影响理解的限定；正文呈现贡献时，说明谁做了什么，有请求时交清请谁做什么。若只有活动或主题清单，就按清单复述，不能替它补出价值、结果或动机。复杂正文可按独立意思分段，同一信息只说一次。对照正文撤掉自己增加的责任人、先后、频率或排除项，补回漏读条件；不能先替原文修弱，也不在取证前判假。

用户仅要求初读或简述时，交付直接从这份复述起笔。写完删去重复意思及对象/方法说明；实质歧义或已接触作者说明，只附必要限定，然后结束。此时不交缺陷、修法或未来检查清单；后续要求核源再从第2步继续。

**完成标志：**能定位正文实际给出的认识、判断及关键条件，尚不能回答的地方保持未知。后续发现自己漏读或加了含义，应修正初读，不能把自己的复述当作不会出错的证据。

## 2. 对照原要求与资料

现在读取原要求、可用来源和必要作者说明。核对实际文件/版本及引用位置；生成摘要只作线索，必要的项目依据仍回到原材料。区分用户要求、当事人陈述、模型推测及观测结果。原材料不足时继续可执行的内部一致性检查，但不能把缺件推成项目没有记录或把未核验写成通过。

把初读得到的主要认识、判断和请求逐项对回目标与依据，不按作者写了多少“价值”词或用了多少方法计分：

**先看是否帮助听众完成本场任务。** 从已采用目标找到正文给出的关键回答，再看它是否实际决定内容取舍：哪些段落提供判断所需的支持、区别或背景，哪些只是同主题的重复。标题或作者安排写出了推荐，正文却仍平列功能与活动，不能据此认定主线成立；指出哪处需建立关系、前移、合并或缩减，让读者能沿正文理解为何得到这个判断。正式必答与必要背景仍应保留，AI与委托者的共同知识不自动属于听众，也不强制所有场合结论先行。用户希望呈现价值和贡献，就查具体作用是否看得见；只要客观复盘或简短同步时，不额外要求自我评价或行动请求。

**再看有用的回答是否得到支持。** 沿重要判断核对它依靠哪些事实、适用条件、比较以及谁的行动。把有据用途、待验证机会和实际成果分开：一个功能可以有清楚的业务用途，即使还没有量化收益；实际节省、低成本或更可靠的比较则需对应依据。人物贡献查实际判断、行动及其作用，承认合作分工，不把团队结果全归个人，也不因缺量化归因就删除已记录的个人工作。总结、标题和结尾须保留同一对象、阶段和主张强度。

**最后挑战会改变判断的遗漏。** 对完整判断或决策材料，主动检验是否存在被当前表示混同的重要情况：已有事实和指标相同，另一个条件改变时，本次听众是否应有不同认识或选择？若会，检查正文是否已经解释这一区别；未解释才说明它如何影响当前目标或结论。假设情境只检验概念，不能据此断言项目有新风险。候选没有新增区分、离题或不影响本场，就不要求加入；缺的是事实则索取最小依据。局部改句不例行重开全篇探索，也不因看不到内部笔记就断言作者没有思考。

三者互相约束：有据但不回答本次问题，要补解释或重新取舍；有用但证据不足，要限定、验证或换主张；有合理支持的替代叙事可以保留。新角度只有关系到已采用目标、正式要求或重要判断才是必修遗漏，其余为可选拓展。审计自己找出的机会仍须过同样的支持与相关性检验。

完整材料任务还要对照安排与实际页面：本次具体主材料页数、页序和全部页面须对应；采用的封面、分节和结束页计入主材料，备查页另列，作者说明、来源目录和未写出的备查建议不算页面。每页有实际标题和可用内容，包含本页必要的数据、比较或关系；只有长讲稿或空页纲不足以完成制作交付。增删、合并或移动页面后核对相关编号和内容。没有统一固定页数、统一字段或统一结构；局部编辑、明确口头稿/阅读稿不强制分页，也不给外来报告追加无关的方案格式要求。这项检查不认证实际渲染、演讲或真人理解。

只在对应疑点上深化，不把下表变成每次必读清单：

| 疑点 | 采用的方法 |
|---|---|
| 当前目标来源、被否认诉求、权责或遗漏是否成立 | [目标发现](goal-discovery.md)，核对采用依据，不替用户重选目标 |
| 零散记录怎样支撑概括，角色/状态/关系是否改变 | [材料提炼与含义保真](semantic-structuring.md) |
| 解释重复、遗漏重要区别或竞争解释；推论缺桥梁 | [解释探索](insight-discovery.md)与[定向思维方法](reasoning-methods.md)，只提出会改变本次判断的挑战；假设情境不是项目事实 |
| 路线、必答覆盖、结尾支持、媒介或时间取舍 | [会议表达](meeting-expression.md)；不以标题流畅代替论证，也不要求所有页面是结论句 |
| 具体对象不明、角色错位、制作旁白或压缩失真 | [观众成稿编辑](audience-copy.md) |
| 数值、日期、舍入、阈值或历史附件 | [数字与计算证据](numeric-evidence.md)、[最小证据交接](evidence-handoff.md)，使用实际口径与执行证据 |

作者说明能帮助辨明合理读法，但不能替代正文中听众必须知道的条件。若比对推翻初读，指出哪项解释由自己加上、现在应如何理解，再判断正文是否仍存在具体问题；不能要求作者为审计者新增的解释补证。输入已明示某种歧义，只证明响应了提示，不能作为主动发现隐含目标的证据。

**完成标志：**能指出材料给本次听众的帮助、贡献归属及关键依据，定位目标、支持、条件或表达中的具体断点。缺哪类关系就修哪一处，不用“多讲价值”替代反馈，也不把准确性和有用性互相代证。

## 3. 复核拟提出的问题和修复意见

定点核对实际主张及有效要求、支持与相反证据、合理读法和实质影响。明确的算术错误可直接复算；依赖版本或上下文的指控需查相关后续纠正，不为每句话扫描全库。意见被反驳、条件句换了说法或修法仍有争议时，读[审计判断与反证](audit-judgment.md)的对应部分，再改当前意见；不要只补一句“已核查”。词语未出现不等于含义无依据；引用错位不自动等于主张为假。

拟列缺陷时，先定位原句与证据或有效要求之间的具体差异，再说明影响；强调场合重要不能代替这项差异。状态已由“建议／预计”交清，就撤掉要求补同义标签的缺陷意见。必要依据不足可列待核；正文无据增加确定性仍须收窄，不因此断言未知事实为假。旧指控被推翻时，暂不沿用旧编号或等级，按当前证据重新判断余项，再形成当前清单。真实的小计算或引用错误仍是缺陷，同源表征合并位置，不凑问题数。

交付前，以**当前这一项意见**为单位，连读问题、影响、行动建议和替换句。先拆清哪一断言有错，保留正确的数量、用途和贡献；再将修法新增的归属、状态、范围和条件对回原句、发言人及适用版本。按[含义保真标准](semantic-structuring.md#含义保真的共同标准)试验：来源仍为真，意见或修法是否可能不成立？例如“检修未完成”允许部分已做，不能在影响段写成“检修均未做”。反例只测试表述，不是新项目事实；没有找到反例，也不能代替对新增断言的正面支持。发现错误就改它在本项中的解释、影响和修法，不能靠另给一句正确替换保留旧理由。只核易扩大处，不逐句建反例台账。

影响分析可以说明有依据的误读风险，但不能把可能误读当作正文已经断言。补件建议不另造所有工作落实后才准估计的规则；针对当前证据缺口建议“补依据后再确定承诺日期”，也不自动等于禁止有假设的条件估计。条件与承诺混淆时，用[连续修订示例](audit-judgment.md#连续修订示例)核当前原句。若这项意见已经交过，还要执行下文的更正处理，不能仅靠本轮换一个好句子停用旧建议。

反馈直接指向原稿造成的缺口：哪段内容让听众仍无法理解或作出本次判断，需要补哪项关系、依据或做哪处修改。能给可用替换就给；缺事实就指出最小补件，不靠示范补事实。修复无据的收益保证后，应保留有据用途与作用，不能把整段有价值内容一并删成免责说明。已经完成说明责任的文字无需改写，也不把内部核对过程变成新的正文或必填表。

**完成标志：**每项正式意见的指控、解释、影响和修法都有相应依据，反证已处理，作者能知道下一步改哪里。审计只给修复方向不等于稿件已经修好；不为增加反馈继续扩写已查清的问题。

## 4. 给结论，并保留准确的适用范围

先按处置类别组织实际问题，再按影响给缺陷定级：P0使关键事实、权限或发布判断失真并构成阻断；P1需修复或明确限定的重要缺陷；P2可表示不改变关键判断的轻微真实错误。小算术或定位错误仍是缺陷，可选措辞建议不计入缺陷数量，也无需P级。

总体结论按以下顺序判断，不能为取得通过删减必要审查范围：

| 条件 | 总体结论 |
|---|---|
| 已知未解决P0 | `blocked` |
| 无上述阻断，但本次必要检查无法完成 | `not_assessable`，说明哪项判断和最小补件受影响 |
| 必要检查已完成，但使用仍依赖明确修复、限定或前置条件 | `conditional`，写明剩余条件；未解决P1不能当成无条件通过 |
| 必要检查已完成，无未解决P0/P1或其他实际使用阻碍 | `pass`；仍可列轻微真实缺陷或建议 |

可选建议、单独的P2标签、范围外历史缺件不自动限制通过；真实P2是否约束使用按影响判断。实际未执行的单项检查保持`not_run`，必要项不能借总体结论变成已执行。工作完成、结构校验与内容结论分别陈述。

交一份与请求相称的Markdown审计结果，先讲本次材料能否完成沟通及影响使用的关键问题，再给可执行改法；保留已经有效、修订时不应丢失的内容即可，不为表扬凑段落。定点审查直接给结论、原句、关键依据和改法；完整报告再补对象版本、实际范围与必要编号。合并问题段、清单和总结中的重复解释，让作者直接找到要改的句子。来源缺口、读取暴露或必要而未做的检查如实说明，不罗列未用能力或另造重复的“汇报方案”。接触作者计划后不能称正文盲读，生成自查不是独立审计；模型复述只能筛查理解风险，不能证明真实听众已理解、认可贡献或愿意支持。

### 补证、复核和授权修订

补充材料只重开受影响判断和关联结论，沿用仍有效的要求、来源与已纠正内容。更正已交意见时：

1. 从被撤回或收窄的断言出发，找当前解释、影响、建议、替换句和总结中仍依赖它的内容，不只找相同词语。“其余意见不变”会继续启用旧影响和修法，也须核查。
2. 按第3步重判余项，**重交受影响项的当前完整意见，明确替代旧项**：保留独立成立的问题和有效改法，删除或重写依赖错误理由的部分。读者不应自行拼接旧报告、撤回清单与新句子才能知道采用什么。撤回“计划尚未制定”后，若依据仍只是未附计划，就不能换成“计划尚未确定”；改“均未做”为“未完成”后，影响说明也不能继续按零进展推论。已经正确且不受影响的其他意见无需重抄。
3. 将失效缺陷及强制修法移出当前清单，同步摘要、计数（如有）、总体结论和适用检查。待核疑点按待核处理，不为维持旧数量另找理由；撤回一项也不自动使原稿通过。

旧报告及当时证据边界留作历史，不倒改旧文件或把后来证据写成初审已有。跨会话续接依据实际原稿和审计记录；更正交付以当前可用意见为主，简述变化与依据即可，不另造撤回台账。

Audit-only保持原件只读。用户明确要求改稿时，另行标识修订范围与新版本，只修改授权内容并复查受影响处；旧版通过不自动传递。被审Run有选版或接纳记录时，按[工作区契约](workspace-contract.md)核对实际精确版本，不能替原Run选版、接纳或改图。私有经验仅在已有明确授权下按[经验规则](report-experience.md)使用；不自动修改被审者画像或将一次经验当通用结论。

需要持久记录或复杂引用时才用[审计Run](audit-run.md)；Run0.1与[多图表示](graph-model.md)继续兼容，不要求实例化。报告绑定可复取的被审版本，可复用现有快照，否则按需另存被审副本；`audit_run init`只登记路径与实际哈希，不复制目标文件。用Run时，字段维护和最终自身校验依该操作方法，不能用生成目录的通过代替审计目录的检查。无相关执行能力时遵守[宿主边界](host-capabilities.md)，如实说明必要而未做的检查，不为内容工作附加浏览器门槛。
