# PM-03：按问题选择进度视图

版本：0.2.0。核对：2026-10-28。可选项目管理卡，仅在许可覆盖本卡时读取。沿用[PM-01](pm-01-delivery-status.md)的活动/交付/验收区别和[PM-02](pm-02-dependencies-risk.md)的依赖与决策，不将本卡变成完整排程工具。

**何时使用**：需要让听众区分承诺、实际进展、剩余预测和验收结果。没有可靠日期/状态时先请求资料；普通一句同步可不用图。

先核实状态日、获批基线ID/版本、实际记录与预测依据。日历过去比例不是完成率；任务数量比例不等于工作量或项目价值；百分比需要范围、分母和证据。执行完成不代表验收通过，未给验收记录应为未知，不能写成拒收。重新预测不自动重设批准基线。

| 听众要判断什么 | 合适视图及输入责任 |
|---|---|
| 当前偏差与需决定事项 | 摘要：有理由选择重要事项，并保留未展开内容的实际去向；不默认截前几条 |
| 基线、实际和未来安排的关系 | 甘特：三种时态不同标识，日期有来源、边界明确；无完整网络不称关键路径 |
| 关键交付节点是否实现 | 里程碑：节点日期和状态独立，不把阶段画成等份进度 |
| 已做工作形成什么交付/效果 | 结果与验收：条件、产物、观察结果、验收状态分别表述，缺评估不编造收益 |
| 预测是否持续漂移 | 先读[PM-04](pm-04-forecast-history.md)，需要逐期历史，单一时点不画趋势 |

选图后为同一事项在不同视图绑定同一精确来源版本与状态日；保留基线批准状态。执行/预测/验收颜色应另有文字、线型或形状，不能仅靠红绿辨认。缺资料时降为有限文字/表格或明确阻断该视图；不为完整五图补造历史、均分进度或自动填零。

**可审阅产物**：说明读者问题、选图/不画理由、来源版本、定义、必要条件和实际计算结果。自然日、状态日截至日末、FS等仅在当前工具明确支持时使用；它们是工程口径，不是所有企业的默认规则。业务排期事项与Agent执行任务分开。

**挑战与停止**：能否从实际图中辨认计划/实际/预测及未知验收？变更一个日期/批准版本，所有受影响视图是否一致改变？不能用几何通过替代语义判断。问题已回答或剩余缺口必须补材料时停止，不为了“专业”生成所有视图。
