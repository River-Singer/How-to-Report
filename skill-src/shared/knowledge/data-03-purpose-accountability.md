# DATA-03 数据用途、责任与生命周期

版本：0.3.0。核对：2026-11-12。可选统计数据卡；仅在有效许可覆盖本卡及相关来源时读取，不扩大既有授权。

## 判断问题与输入

数据能否用于本次用途，谁负责定义、质量、访问及后续处置。

必要输入：具体字段/对象、来源和取得条件、处理用途、接收者、授权范围、业务定义、质量记录、保存/删除安排及实际责任人。

## 实际操作

1. 沿取得、处理、共享、使用、保存、删除对应本次用途，区分已获访问与允许用于本目的，技术上可取不等于获准用。
2. 将业务含义与质量决定、日常维护、技术保管/访问实施分开，映射到已确认责任；不能从“数据负责人”头衔推定全部批准权。
3. 核该数据对当前判断是否足够准确、完整、及时与可比；一个目的下合格不代表适合另一目的，来源变化或口径变更要重新核对应影响。
4. 检查个人或业务影响及共享后的责任、保留和撤回条件；安全保护与数据用途/隐私风险不同，不用加密替代用途判断。

## 产物、限制与停止

交回用途—数据—责任的对应、可支持范围及未决输入。企业授权和适用法律必须来自真实规则，不把英国角色名称或NIST框架当法律结论。

缺用途/权限/字段时索取最小清单或现有授权说明；不能自动扩大资料读取。缺法务认定时标为待专业确认，其他已知分析继续。

汇报人负责完成这些分析并组织为可理解的内容；挑战者用同一知识按真实职责检验最强的目标相关阻断，实质输出仅问句，不给答案或修法；独立审计核实际内容、来源与执行，不按方法名称判通过。角色与派发规则见[委派契约](../references/agent-delegation.md)。

## 短应用与误用

合成例：运维日志可用于故障排查，但未确认可用于人员绩效评价；应区分两种用途和实际授权。误用：认为持有数据库账号便拥有任何分析、共享或无限保存权。 以上均为合成教学例，不是用户项目事实或固定问题模板。
