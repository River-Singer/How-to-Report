# 把一次汇报构思连成有用的内容

以下是自造教学材料，不是项目事实或模型测试。主例连续展示目标、价值判断、证据、新区别、取舍、页面和新证据修改；不是每次必读的提示词。正文只有分类时看[主例](#读者仍需自己拼接)，换听众看[用途变化](#换了用途就换组织)，部分答复看[请求更新](#新回复只完成部分请求)；重要判断缺解释时看[完整展开对照](../assets/examples/report-depth-proposals.md)。回本次来源解决相应困难，不照抄业务事实、页数或句型。

## 读者仍需自己拼接

### 处境与原资料

项目负责人请部门主管确定台账工具的首轮业务样本和联系人。主管已看过导入、定位演示，了解工具基本能力，本次需要简短说明怎样用于核对，重点是选哪组、怎样安排。用户希望真实贡献可见；主管有选择和指定联系人的权限。本轮只能安排一组，演讲时限未给，不申请正式使用。

| 来源 | 已有记录 |
|---|---|
| 开发记录 | 甲、乙两组台账均能导入，工具能定位到原始记录；开发组已完成本地功能检查，两组均未开展业务样本核对 |
| 6月5日业务记录 | 甲组合同号和含税金额的取数规则已经甲组业务确认；乙组同名字段的含义仍有分歧，尚未确认取数规则 |
| 项目记录及用户确认 | 汇报者对照两组字段说明，识别出同名字段含义有差别，并将差别整理给业务同事；开发组实现导入和定位，业务同事负责确认取数规则 |
| 会前安排 | 样本核对前须确认该组取数规则；原请求是请主管在6月10日前明确有核对职责的联系人及其可参与时间，再共同商定安排；核对结果出来后再讨论是否试用 |

这组资料未提供节省工时、迁移成本或正式使用效果的记录。它们不妨碍说明具体用途与贡献，也不支持“尚未测过收益”等反向事实。

### 从清单转成有选择的判断

初稿可能写：

> 已完成导入、定位和本地检查，具备推广基础。甲组规则已确认，乙组待确认；后续推进业务协同。本人统筹创新实践，发挥核心价值。

问题不止是措辞生硬：它把本地检查升级为推广依据，没回答首轮选谁，个人赞语也没告诉主管实际做了什么。

可以给作者这样的具体反馈：“先让主管知道工具帮助核对什么，再比较首轮选择会受什么条件影响。你已经发现了字段含义差别，把这个判断及作用讲出来。”

原来的表示只看“能否导入、能否定位”。现在尝试两种情形：技术能力相同，但一组已确认取数规则，另一组没有；它们是否应同样安排业务核对？已有前置要求说明不应相同。这一检验找到的是**业务口径是否确定**，而非“效能、赋能、能力”三个同义标签。假设比较用于辨认区别；本例甲乙的实际状态另由业务记录提供。

于是形成候选判断：工具让台账记录可追溯到原始出处，可支持业务核对；首轮建议选甲组，因为它已具备口径条件，可重点检验定位结果怎样用于核对。乙组先解决字段含义分歧。它没有声称甲组核对必成功，也没有依据称其成本最低。若本场优先解决最复杂业务，可能应先研究乙组；候选的价值取决于采用目标，不是甲组永远更优。

个人贡献接在真实工作上：汇报者辨认并整理了两组口径差别，这为区分核对前提提供依据；导入定位由开发组实现，规则由业务同事确认。将这几项关系写出来，比“我推动了项目成功”更能让听众判断贡献。本轮“先甲后乙”的选择仍是建议，不能写成本人过去已经推动落地的成绩。

### 让新区别改变实际页面

假设已有五页：导入能力、定位能力、本地检查、个人贡献、首轮选择。末页虽然正确推荐甲，前四页仍各讲一项资料；把推荐标题移到封面，也没有解决主要篇幅的分配。

现在按本次要解决的问题重编：

| 原内容 | 实际编辑及理由 |
|---|---|
| 导入、定位各一页 | 主管已看过演示，合成一处共同能力说明；保留怎样用于业务核对，不再逐项演示 |
| 本地检查一页 | 保留检查与业务核对的阶段区别，放在当前安排旁；不把检查经过扩成主线 |
| 个人贡献一页 | 将实际发现字段差异的工作放在甲乙比较旁，让贡献与本次选择相连 |
| 末页才推荐甲 | 将推荐和关键区别放在第一页，第二页交当前请求及接下来要核对的内容 |

由此形成两页主材料，无备查页；不是将五段挤进两张纸，而是删去已经知道的展开、合并重复背景，让每页承担当前需要的回答。

**第1页｜建议先核对甲组样本**

两组台账都能导入并定位到原始记录，但业务核对的条件不同。甲组已确认合同号和含税金额的取数规则；乙组同名字段仍有分歧，规则尚待确认。

我对照两组字段说明时，发现同名字段的含义不同，已将差别整理给业务同事。本轮只能安排一组，建议先选甲组，按已确认规则核对；乙组先解决取数规则分歧。

**第2页｜请在6月10日前明确联系人与可参与时间**

请明确有业务核对职责的联系人及其可参与时间。若同意首轮选甲组，我们再共同商定样本核对安排：沿台账找到原始记录，对照合同号和含税金额，检验这些能力怎样帮助业务核对。

开发组已完成本地功能检查，两组业务样本核对还未开始。核对结果出来后再讨论是否试用，本次不申请正式使用。

推荐采用的是现有口径条件，不需要追加“甲最便宜、乙错过就没机会”来显得充分；这些理由没有来源。相关的其他理由若确有依据仍可保留，不把“少写”变成只允许一个理由。完整交付见[合成方案](../assets/examples/report-proposal.md)，文字、表格等呈现均可。

如果本次改为给新同事培训导入、定位和检查方法，这些内容重新有了详细展开的理由；主管已知的背景也不再是新同事已知。删合依据是当前任务，不能照搬两页、先推荐或省演示的形式。

### 新证据使原选择失去依据

6月8日收到新业务记录：甲组刚更换合同编码规则，当前取数规则需重新确认；乙组分歧已解决，业务确认了规则。其他约定不变。

回B重比条件，第一页的选择与理由一起改，第二页的样本条件同步；不在末尾追加新状态却沿用旧推荐。当前第一页可替换为：

> **建议先核对乙组样本**
>
> 6月8日业务更新：甲组更换合同编码规则，需要重新确认取数规则；乙组的分歧已解决、规则已确认。两组导入和定位能力不变，建议将首轮改为乙组，甲组先确认新规则。
>
> 我此前对照字段说明，整理了同名字段的含义差别；本次规则确认由业务同事完成。

第二页改为“若同意首轮选乙组，我们再共同商定样本核对安排”，保留6月10日的联系人与时间请求、核对结果出来后再讨论试用。页序表同步，仍为两页。新的业务确认不变成本人的亲历贡献，历史发现也不因改选变假。

只改一条标题时不重构全篇；新证据改变选择依据时，才沿受影响的理由、页面和行动更新。可简短记录改选依据，不交所有候选或内部推演。

## 换了用途就换组织

回到6月5日原资料，若改为向首次接触的业务同事介绍参与方式，中心就从主管选样本变为业务怎样核对。可写：

> **找到原始出处，再按本组规则核对**
>
> 将台账导入后，工具能定位到原始记录。甲组已经确认合同号和含税金额的取数规则，可据此准备样本核对；乙组还需先确认两个字段怎样取数。业务核对尚未开始，联系人和可参与时间明确后，我们共同商定安排。

保留工具用途与关键区别，拿掉面向主管的任命请求和不服务这次介绍的个人贡献展开，不改共同事实。若用户仍要求介绍自己的贡献，则可以用相关事实说明，不默认隐藏。若只是简短进度同步，可直接交当前能力、两组口径变化和未完事项，不强留两页。能回答问题的分类或比较均可使用，不把操作链设为万能结构。

## 新回复只完成部分请求

下面是另一组排期材料，不是上一例的后续：

| 时点 | 记录 |
|---|---|
| 6月7日 | 上次预测6月9日开始测试，假设测试账号此前可用；原请求：“请主管协调，在6月10日前确认账号负责人及账号可提供时间。”复核须待测试完成；账号窗口不成立时另评测试范围与日期 |
| 6月9日 | 负责人已联系到，拟6月11日提交账号申请，账号可提供时间仍待答复；复核人员仅确认6月12日下午可用；本轮未提供新的剩余工作估算 |

修改稿保留整张历史表，当前行动却写成“负责人已联系，请跟进6月11日提交申请并推动账号获批”。日期还能搜到，实际请求却变了。

先对当前行动动手，不先写新一轮进展摘要。回到完整原请求，而非旧稿缩写；把新回复实际覆盖的部分与余项分开：

| 原请求中的内容 | 新回复允许怎样改当前行动 |
|---|---|
| 6月10日前确认负责人 | 已联系到负责人，转为进展说明 |
| 同期限确认账号可提供时间 | 仍待答复，动作和6月10日期限一起保留 |
| 账号窗口不成立时另评范围与日期 | 新回复没有替换触发条件；不能改成申请后再判断，或人员不足就自动缩范围 |

这是作者的编辑对照，不交给听众代为推导。先留下仍有效的请求，再补新进展及建议，当前行动可直接替换为：

> 请继续协调，在6月10日前确认账号可提供时间。负责人已联系到，拟6月11日提交申请，届时建议跟进办理进展。复核须待测试完成，现已确认复核人员6月12日下午可用；建议结合账号到位时间，重新估算测试与复核安排。若账号窗口不成立，另评测试范围与日期。

暂时遮住历史表，仅按这段执行：主管仍须在6月10日前协调问清时间，不会等申请后才询期；6月11日跟进是另加建议。最后才同步摘要与收尾，删去重复历史。确认一处人员窗口不等于其他时段都不可用，也不能拿旧预测区间的日期差冒充剩余工作估算。

若用户明确改为6月13日前确认可提供时间，就替换这项期限，其他安排沿用；若只完成一项，便只关闭一项。有适用工作量与假设时仍可给条件估计，本轮未附新估算不等于项目从未估算，或必须等工作完成才准估计。

局部修改先定位实际对象：请求在P2、实际末页P4是明细，不能把“最后一页的请求”默认为P2；先澄清影响范围的差异。对象明确后只改受影响内容。

## 来源不足时停在已知范围

以下为独立合成的馆藏整理材料。本次由馆长向理事会介绍工作，需说明现状与下一步。

| 适用记录 | 内容 |
|---|---|
| 成员记录与更正 | 项目成员为刘岚、周辰。早稿把编号整理归给刘岚；更正为周辰整理编号，刘岚整理讲解词。馆长本次代为汇报 |
| 工具记录 | 图像转文字模块在本地工作站运行；译文初稿使用云端翻译工具 |
| 检查记录 | R1核对的10条检索结果正确。R2修改了显示字体，本轮未附R2复测或节省时间记录 |
| 讨论中的助手建议 | 建议公开前增加人工对照；未取得该建议被采用的确认 |

草稿：“我和两位成员共同完成整理，全过程本地运行；R2十条检索全部正确，人工对照已减少返工。”一句话里名字和数字都像来源，动作、版本与效果却被换了。

把出错片段与对应记录对读，再直接修句：

| 草稿片段 | 对读后如何处理 |
|---|---|
| “我和两位成员共同完成” | 当前代表不新增历史成员。按更正写周辰的编号整理、刘岚的讲解词整理，保留真实贡献 |
| “全过程本地” | 本地属性只属于图像转文字模块；云端翻译另说，不在末尾加一条“安全未验证”来补救错误主张 |
| “R2十条全部正确” | 十条观察属于R1，不能挪给R2。也不能因未附R2记录就断言未做过复测 |
| “人工对照已减少返工” | 只有未确认采用的建议，既不支持实施，也不支持效果；仍可提出这项有用途的建议 |

实际正文可以这样写：

> 周辰整理了馆藏编号，刘岚整理了讲解词。图像转文字在本地工作站处理，译文初稿使用云端工具。R1核对的10条检索结果正确；R2改了显示字体，新版检索表现还需结合其复测记录判断。建议公开前增加人工对照，核对识别文字与原图是否一致。

这段保留可说的现状、贡献和建议，没有替项目宣布“从未测量”或“已降低返工”。节省时间不是本场必答，缺记录不必另成一条警句；若理事会要据收益决定投入，再提出所需测量。讲解里若还留着“我们已经减少返工”，同一断言仍未修完。正确内容不必套同一种改法：有适用R2检查记录就可写R2，有明确采用与效果依据就按其范围表达。
