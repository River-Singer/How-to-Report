# 条件与相互制约

方法修订：0.9.0（2026-11-12）。

- **触发**：两个局部判断难以合并、优化一处损害另一处、同一做法在不同阶段产生不同结果，或所谓冲突类型尚不清楚。
- **动作**：先区分概念差异、事实记录冲突、目标权衡与机制交互。回看共同来源、时点和范围；对可变条件提出具体替代情况，比较受益者、代价、依赖和可执行权限。事实冲突先核证，不能靠折中数值解决。
- **可观察结果**：用简短关系说明标出“在什么条件下，哪项变化会影响什么判断/行动”；保留依赖，不把相关当重复。若存在第三种安排，写出成立条件与验证需求，不能为了折中发明方案。
- **回落与停止**：将条件写进实际建议、风险或备选。区分已足够、剩余缺口是事实，或继续仅换说法时停止；不强制正反各半、矛盾必有解决或每次寻找“主要矛盾”。
- **需挑战的地方**：单项均成立是否足以支持综合结论？是否用阶段不同抹去真实矛盾？是否把潜在交互当实测机制？若变化没有相关的判断后果，不算有效发散。

背景：[本地条件分析说明](method-sources/sources/conditions-background.txt)。哲学背景与经验事实、LLM实验是不同证据类型；本方法不要求采用特定哲学立场。

本卡交回一个可用区别、修正判断或具体待核事项；不另启动成稿/验收流程。共用[含义保真标准](semantic-structuring.md#含义保真的共同标准)。

## 把操作落回判断

必要输入：相互作用的主张/候选、对象与版本、资源和时间条件、真实职责/权限以及关键证据；先区分事实冲突与价值取舍。

联合检查分别成立的条件是否可同时成立：同一资源是否被两次承诺、节省是否引入另一项费用、保障是否只覆盖局部。逻辑反例能说明推断不足，却不能证明现实一定落在反例中。真实冲突应回到来源、条件或有权者取舍，不能用折中措辞平均掉相反事实。

合成例：两方案分别都能用一位专家完成，但同一窗口无法同时投入，整体承诺尚不成立。误用：将双方不同版本的截止日取平均，或称“安全与效率平衡”就算完成取舍。 以上为合成教学例。

主Agent先用已有资料完成可做的分析，真正缺事实时说明具体最小输入/替代、它决定哪个判断和不补时的边界；不是让用户完成分析。所缺若为工具或专业能力，明示尚未完成的核验，不伪称只缺资料。产物是有依据的区别、判断或未决条件，落实到实际内容后停止。

挑战者只用方法形成目标相关问句；不把本卡操作清单或修复建议交给主Agent。审计仍检查依据、影响和修法；真实委派见[契约](agent-delegation.md)。
