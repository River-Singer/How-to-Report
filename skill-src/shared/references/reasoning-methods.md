# 按判断缺口调用思维方法

只在概念、前提、条件或推理桥梁会改变本次产物时调用。先说清待解决的问题，再选一张卡；不依次遍历四法，不把方法名当作发现。简单日期格式、措辞或已明确的短同步直接处理。卡片是现有 Goal/Hypothesis/Evidence/Argument/Obligation/Blueprint 的操作补充，不增加业务 State 或 Agent。

| 当前缺口 | 读取方法 | 应发生的变化 |
|---|---|---|
| 同词异义、状态或分母混用 | [概念与状态](method-concepts.md) | 分清会导致不同判断的对象与状态 |
| 方案依赖未核对假设或把手段当目标 | [前提与约束](method-premises.md) | 找到需要核实/保留的条件，回到具体方案 |
| 局部优化、相互制约或阶段变化 | [条件与交互](method-conditions.md) | 区分冲突类型，形成可检验的条件变化 |
| 从材料跃迁到价值、效果或承诺 | [主张与证据](method-argument.md) | 补推理桥梁、缩小主张或提出辨别性补件 |

需要留存时，只记录必要的“原问题/表述 → 新区分及材料定位 → 内容或证据需求改变 → 未决与停止理由”。它是可审阅结果摘要，不是私有思维链。没有内容变化时允许记录不适用；不能用填满字段或“认真分析了”证明方法有效。

新方向仍按[解释探索](insight-discovery.md)做区分、删除与交互检查；新目标仍按[目标发现](goal-discovery.md)处理用户选择。缺事实时请求材料，不能继续堆概念。模型自纠不等同外部证据、独立复算或真人反馈。

这些操作是本产品的设计，不是已验证的模型收益。背景资料和实际阅读范围见[离线方法来源](method-sources/index.md)，仅按所用方法读相关段落；不需要联网。
