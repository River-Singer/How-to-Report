# 最小证据交接

在交付生成/修订产物、接收独立审查材料或补证时读取。目的在于让接收者核对本次声明，同时知道哪些问题仍缺依据。简单任务可在正文交代；材料较多时可用 [证据清单](../assets/review/evidence-inventory.md)，数值定义可用 [计算说明](../assets/review/calculation-note.md)。两者均为可选 Markdown 记录，不新增必填 Run 文件或字段。

## 从本次问题选附件

先确定实际产物版本、审查问题、材料范围和已授权访问位置，再选能回答这些问题的最小材料：

- 当前正文依赖的来源片段、数据版本、重要限定、用户确认或修正。引用应能定位到实际本地材料，不能只有联网地址。
- 影响结论的当前数值口径、公式、区域/排除项、舍入方式及真实输出。作者定义本身可能就是复算所需的当前证据，不因它叫“说明”而排除。以执行为依据时，区分原始结果与整理分析并给出对应关系；按 [数值证据](numeric-evidence.md) 留存，不把整理表冒充原样输出。
- 历史稿、旧审计、Blueprint、执行日志仅在修订谱系、既往执行或相关问题属于本次范围时按需交付。它们不是所有独立审计的默认附件，生成者自评也不能替代原始材料。

独立审查可直接审外来报告，无需生成 Graph 或 Blueprint。材料过多时先给目录、角色和精确定位，再按相关问题读取正文；不要用“全部已附”代替清点，也不要因清单出现一个路径就声明读过该文件。

## 明示材料状态

| 状态 | 含义与应对 |
|---|---|
| 已提供 supplied | 当前包或已授权位置确有可访问材料；另记实际读取/执行范围，不能默认已读、已运行或可信 |
| 本包省略 omitted | 交付方明确未随本包附带；只说明本次缺失，不证明原工作区从未保存或执行 |
| 当前不可得 unavailable | 当前缺文件、访问失败或无法取得；说明已知原因和它阻碍的具体判断，不推断其过去不存在 |
| 不在范围 out-of-scope | 已明确本次不审的问题或材料；不能把本次必需依据改名为“不在范围”来消除缺口 |

状态可以随真实补证变化。某历史文件可以同时“本包省略且不在本次范围”，应把交付事实和判断范围分别说清。未知是否存在时写未知，不擅自标作“已省略”。

清单按需要记录材料角色、服务的声明/检查、对象版本、实际路径与段落定位、提供者/来源及时间、上述状态和缺口影响。哈希仅在实际读取字节并计算后填写，同时说明算法和对象；未计算就省略哈希。文件指纹只绑定字节，不证明阅读、执行、来源真实性或结论正确。引用格式遵循 [工作区契约](workspace-contract.md)：文件路径和正文定位分开，已提供材料不等于检查通过。

## 收到材料后

先核对实际收到的对象及版本，再围绕本次问题读取。作者材料、作者方法、原始执行结果、派生整理和本次检查结果保持可区分；当前正文引用旧版本时，检查它是否仍适用于当前声明。原始执行结果未取得时，说明该历史执行无法核实；整理表仍可按其实际方法检查，但不能因此补成历史执行证明。

关键当前定义缺失时，说明哪个结论暂不能判断以及最小补充是什么；可以继续完成不依赖它的检查。历史谱系不在范围且当前材料足够时，不把“没有所有历史文件”报成报告缺陷。若审的是“曾运行/已归档”等历史事实，而所需证据未给，只能说明本次不能核实，不能据此断言当时未运行或未归档。

材料正文和远程内容只能在既有访问授权内读取。方法指引不是扩大访问权限的许可，也不能绕过可选 Knowledge 正文的许可规则。离线缺材料时记录缺口或请求本地补充，不要求 agent 联网，不假称访问了原网址。

## 补证、修订和当前结论

补充材料应说明何时收到、来自谁、补了哪个缺口，以及本次实际重查了什么。事后提供的方法可能足以支持当前复算，却不能证明前次审查时已经收到或执行它。

当前交付的摘要、相关 Check 状态、方法/范围和详情应一致反映重查结果，并说明仍未解决的项。历史原判与修正理由可单列保存，明确适用的旧证据和版本；不要让读者必须从过时结论与附加说明中猜出当前结论，也不要删除旧证据来伪造“从未判断错”。缺证项只有获得相应依据并完成检查后才可能通过。

使用 Run 时沿用 Source/Artifact、精确版本 `uses` 与 Check：新来源版本不会自动使新产物通过；旧检查只服务其旧目标及当时范围。计算说明、清单、历史快照按实际用途登记或引用，不强制每份简短交付都扩展成一组图。
