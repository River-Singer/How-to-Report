# 先判听众任务，再选图表或明细表

这是本项目当前的数据表示规则，供制作前设计评估与实际成稿审核共同使用。用户已明确：解释数据用图；供应商名单、工作人天等供查阅核对的明细用表。原来的“表格最低优先”只约束解释型页面，不能扩大成所有数字必须成图，也不要求先查遍图库证明无图可画才允许明细表。特定任务有更新、明确的禁用要求时，在其有效范围内遵守。

## 决策顺序

| 听众要完成什么 | 应选表示 | 例子与边界 |
|---|---|---|
| 理解增长、差异、构成、分布、关系或状态比例 | 实际检索注册图库，读候选合同，用合适图形直接编码所需关系 | 流量增长用趋势；注册/激活状态用有真实分母的比例图；理解人天在阶段、角色或总BOM中的分布用比较/构成图。数据埋在段落、纯大数字卡或换成表格让人自行心算，不能完成解释任务 |
| 查找具体对象、核对多项属性、逐项复核明细 | 简洁的名单表、属性表或交叉表 | 供应商名单，人员/工作项×月份的人天，角色×阶段的报价。表格是适配的首选，不需要无意义的选图淘汰流程 |
| 同时理解分布并核对明细 | 主图解释＋必要明细，依实际用途同页或备查 | 主图回答峰值/构成，明细保留精确查询。不要在正文、图、表重复整套数字；备查位置必须听众实际可用 |
| 理解定义、能力、机制或流程 | 有层次的短语/解释段，配真实关系图或素材 | 有数字、日期或序号不自动变为数据图；日期是人员属性时可留表，日期事件推进才选时间线 |

先在已有页任务中交清“解释什么”或“查什么”，再查相应组件、定栅格和测排。混合任务先明确主次，不把两种表示机械堆在一起。此判断由模型/审阅者结合实际内容执行，字段完整、存在图表对象和布局通过均不能代证。

## 图表应真正承担解释

图形必须具有有意义的比较对象、整体、时间尺度、基准或数据关系，关键差别可由位置、长度、面积、色阶等编码读出。孤立数字各画一根满高柱，并不比直接列值多传达关系；单位不同、没有共同基准的量不能因“必须有图”硬造比较。单值有实际目标、上限、历史或整体时才据此画可解释的图；没有这些依据就保留真实单值及用途，不编造分母或参照。

图表使用真实单位、期间、集合和分母。独立尺度只在各图内部本来就存在可解释关系时适用，不能让不可比量看上去等大。数量比较核零点与共同基线；比例核分子属于分母、互斥与完整性；异期不能拼成趋势。标签、单位、必要条件和有依据的业务解释继续用文字；正文不逐项复述图中读数。

同类可比数据采用统一图种、尺度、尺寸和颜色含义；不同任务不强求同形。图表可执行、合成预览和真实业务适配是三种结论，分别记录。

## 明细表何时成立、怎样做

- **对象清单**：一行一个对象，列为有实际查询价值的属性。供应商、项目经历、功能范围属于此类；恒定列可上移成表级范围，不能删有区分意义的字段。
- **二维交叉**：行列是独立维度，交点是确定值，如角色×月份人天、角色×阶段费用。用于逐项核算时保留精度、单位和合计；总计须可加，缺失/未定/零分开。
- **属性对照**：少量方案依同一组条件逐项核对。互斥报价不能相加，赠送项、参考金额与应付值分开。需要理解成本构成时另用图表，不以表中加粗代替。
- **不属于明细表**：甘特条长表达持续时间，是图表；阶段×工作层级内的流程是机制组合；同尺寸案例卡只是栅格。选择依据是读者任务，不是有没有边框或用了什么原生对象。

先定表内对象、字段、顺序与查找入口，再分配列宽和测量行高。名称/解释列取得必要宽度，数值按位/小数对齐，同列统一精度；关键分组用轻分隔和清楚标题，不逐格填重底色。正文沿14 pt、最小角色9 pt，不把全部正文降到9 pt以容纳大表。容量不足时移除重复列、分组或语义续页，保留完整查询能力及表头；不能为少页删掉核算字段。

## 研究依据与适用范围

用户给出的两份本地德勤PDF提供了具体对照：POC页9/10项目索引、11/12案例展开、17/18阶段机制；Commercial页2/8功能范围、3/9甘特、5/11人天明细、6/12报价。共实际查看16个PDF页，页码按PDF序号，不等同于印刷编号。观察来自项目研究记录；PDF图面不能证明原稿对象是原生表格，也不构成商业报价合理性审计。

这些案例支持“查询与解释是不同任务”的方法归纳，不把它们的密集小字、品牌、商业条款或具体数字当作本项目模板规范。方法适用于新制作和实质修订；历史冻结产物继续按当时身份记录，不能改写旧验收。
