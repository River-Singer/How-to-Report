# 台账核对工具：申请业务联系人（合成教学示例）

这是自造材料及对应 Markdown 交付样例，不是实际项目记录或模型测试结果。示例展示一份简短会议材料如何明确页数、写出每页内容；两页与下列分组只适用于这组输入。

## 汇报安排

项目负责人向部门主管汇报，请主管指定业务联系人，先确认取数规则，再开展样本核对；本次不申请正式使用。建议主材料共 **2页**，不另设封面、目录或结束页，无备查页。先交代已有能力和业务核对的缺口，再提出需要主管决定的事项与后续安排。用户未给演讲时限，本例不据页数推算分钟数。

| 页码 | 标题 | 这一页解决什么问题 |
|---|---|---|
| 1 | 两项取数规则待业务确认 | 现在能做什么，下一步为什么需要业务参与 |
| 2 | 请指定业务联系人 | 请主管决定什么，人员落实后如何推进 |

以上安排和末尾来源说明写给汇报者，不计入页面。以下是可供制作使用的逐页正文。

## 逐页内容

### 第1页｜两项取数规则待业务确认

| 当前已有的能力与检查 | 还需业务确认的内容 |
|---|---|
| 导入台账，定位到原始记录；开发组已完成本地功能检查 | 合同号和含税金额两个字段的取数规则 |

两项规则确认后，才能开展样本核对。目前业务核对尚未开始，也尚未约定时间。

### 第2页｜请指定业务联系人

请安排一位有业务核对职责的同事参与，先与我们确认合同号和含税金额的取数规则，再一起核对样本。

| 需要推进的事项 | 安排 |
|---|---|
| 落实联系人 | 请主管指定业务联系人 |
| 商定核对时间 | 人员落实后，与联系人商定 |
| 开展样本核对 | 先确认两项取数规则，再核对样本 |
| 讨论是否试用 | 核对结果出来后再讨论；本次不申请正式使用 |

## 来源与教学说明

本例的全部输入如下，没有另用外部来源：

- 用户委托起草给部门主管的简短会议材料；实际汇报者为项目负责人，可代表该项目组说“我们”。
- 用户确认：本次请求主管指定有业务核对职责的联系人，主管有此权限；本次不申请正式使用。人员落实后商定核对时间，取得结果后再讨论是否试用。
- 开发组记录：工具已经能导入台账，并定位到原始记录；已完成本地功能检查。
- 业务组记录：合同号和含税金额两个字段的取数规则尚未确认；样本核对必须先确认这两项规则。业务核对尚未开展，也尚未约定时间。

本例分别组织“当前能力与缺口”和“请求与后续安排”，两页均有可用文字及具体关系，没有补出完成日期、节省工时或试用批准。下游可选择适合的呈现，不必照搬表格或新增图形。真实任务只附有用的来源与待确认事项，不把本例教学说明带入正式页面。
