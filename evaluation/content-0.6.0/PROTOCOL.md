# 内容行为评测协议 0.6.0

比较实际沟通内容，不考是否复述Skill名词。当前4项全部是开发者已读的Dev设计，不是未见集。批量模型运行由用户负责，此协议不自动授权调用模型。

## 冻结与分阶段输入

`dataset.json`冻结4项catalog、5份fixture与本目录协议/运行说明。执行者只接收当前回合与相应材料，先保存实际回答再释放下一回合。不能给模型评分条件、未来补件或开发示例当答案。后来的材料不能倒填进旧输出。记录无交互、拒答、未执行与不可评估的实际原因。

运行时记录宿主、模型/推理设置、包manifest哈希、资料版本、权限/工具、输入与输出、澄清次数和实际消耗。无可用Token/费用记录就写未知。不保存或索取模型私有思维链；只保留公开的建议、取舍、资料引用和实际工具结果。

## 比较方式

先运行当前案例即可。若做基线：B0在同模型、同输入、同工具和预算下使用普通任务提示；B1激活冻结Skill；B2是在相应生成结果上增加独立审计及授权修订，额外成本单列。基线不是“故意写差的提示”。不能用模型/输入不同的两次结果声称改善。

审查尽量先隐藏组别看实际稿件，再看来源和任务要求，最后看作者方案。需要时记录不同评审意见，不强求唯一主线。审计者看到先前上下文时如实说明独立程度。

## 判定

关键事实、数字、时间、归因、条件和请求不能捏造、漏改或擅自强化。缺材料不等于事实不存在；用户明确拒绝的目标不再优化；审计不改原件。对每个具体问题给出处与影响，区分缺陷、必要资料缺口与可选建议。

| 维度 | 本版问题 |
|---|---|
| Q1目标 | 是否发现/确认实质结果，明确目标时是否直接推进 |
| Q2区分 | 是否发现有用的新区别，同时避免重复和无关发散 |
| Q3证据 | 判断、状态、归因与条件是否由资料支持 |
| Q4叙事 | 主次和转接是否支持听众理解与决定，结尾有无无据升级 |
| Q5计算 | 适用时是否按相同口径实际复核，而非心算或伪称执行 |
| Q6成稿 | 能否由指定汇报者直接使用，少做二次翻译，无制作旁白 |
| Q7效率 | 澄清和分析是否值得，是否给短任务增加无用流程 |
| Q8控制 | 是否遵守局部范围、明确目标、授权及后续更正 |

可用0–4描述适用项：0相反/缺失，1明显不足，2有重要缺口，3满足任务，4有具体证据的出色表现；不适用不计0，数字评分不是必填。质量判断需附实际产物依据，不能用均分抵消严重事实错误。当前Q6为成稿，不得拿它重算旧页面评测。

C06-VALUE第二回合的独立算术基准为(20−12)=8天、8/20=40%；仅反映给定样本均值变化，不证明工时/金额或独立因果。其他案例允许多种正确路线，不能把猜中“隐藏真目标”、固定页数或维度数当验收。

程序只检查输入、引用与确定性事实；模型审计不是受众实验。正式效果判断仍需真实运行和适当未见材料，报告实际样本、失败及未评估，不能预填成功率。0.5.x协议和67项输入留作历史，不复用其通过标记。

## 结构化表达观察

在已有四案中观察，不增加批次：时序、依赖、因果与影响分别判断；并行协调/分支不能为了顺畅串成线；优势分组须有共同标准；从成稿反向还原主体、状态、关系与条件。局部并列不强迫全篇并列，叙事顺序也不能伪造业务依赖。允许模型用自然语言工作笔记，不要求完整图或新Schema。
