# 操作者与评审的场景参照

不提供给生成模型。场景/时间/知识前提是测试设定，不是对职级心理的普遍断言；不得要求所有报告套一种路线。原始素材是虚构输入，不是公开方法的正确答案。

| 组 | 与邻近任务真正不同的地方 | 可接受编辑结果与重点缺口 |
|---|---|---|
| 01 内部比赛 | 同事理解业务，想看AI实践；后轮压时且取消现场操作 | 做法与可见业务结果相连；压时重排重点，缺演示不能编成已演示 |
| 02 外部比赛 | 首次接触机构与业务 | 解释需求、实际操作、意义和创新依据；不照搬工具/分工清单 |
| 03 业务一级 | 先走查实际业务，再给试用馆员参与说明 | 操作对象与结果讲得懂；后轮变成所需资料与确认动作 |
| 04 业务二级 | 判断在哪些部门工作继续验证 | 有范围的业务价值，不因缺收益台账就编无测量事实或只列风险 |
| 05 技术一级 | 核当前实现和协作边界；随后只改标题 | 工程关系有具体内容；没有源码不编性能/架构；局部定位不越界 |
| 06 技术二级 | 从工程实践挑下一项目可试做法 | 提炼方法及适用条件，不把一次试用当组织级验证 |
| 07 总负责人 | 同目标同听众，由技术代表换业务代表 | 贡献归属和可负责的判断有变化，时限与共同贡献仍保持 |
| 08 外部同行 | 交流可借鉴经验，没有采购决策 | 去内部简称与审批话语，解释条件，不作交付/安全保证 |
| 09 项目进度 | 目标探索→确认→部分回复 | 原11月4日询时余项不能被拟11月5日提交后跟进替代；新增协调建议可以提出但不替换原要求 |
| 10 周报 | 12月21—27日书面协作读物，随后同周期计数更正 | 初稿按当时周表11条待处理；更正后是10条，累计登记23、累计净关闭13；月末事实不提前出现 |
| 11 月报 | 12月1—31日评议，不是周报合订 | 去重后当月新增15，累计登记25、净关闭17、待处理8；三项目标按实际时间判断，询人已答复，未批准对外开放 |
| 12 培训迁移 | 决策比较→门店参与说明 | 9000/10800费用组成相同不说明资金够用；80/48为名额，每场半天，三分钟继承 |
| 13 审计回归 | 正文理解→对照来源→审计更正 | 60%整体进度及充分交付保证仍有问题；已有建议状态不强制补词；范围待核不能使旧误报续存 |

周期数字只是问题台账，不是整体完成率。累计净关闭=累计关闭次数−重开次数；报告若选择只给待处理数且讲清变化，也可成立，不强迫列全部派生值。25登记−17净关闭=8待处理；测试14+10+6=30次不等于30项独立工作。

本批沿用既有公开培训/审计事实；新增图书馆实践和预约周期资料。旧档案协调资料删除预设作者汇报目标，保留事实和既有协调请求。不是未见保留集，不据此证明场合之间泛化。
