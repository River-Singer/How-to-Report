# 0.6.1 内容方法开发评估

状态：准备完成，未运行模型。六个合成案例以自然请求和后续条件变化，观察目标是否影响正文、信息不全时能否给出有用判断、编辑是否保住重要关系，以及审计的漏报和误报。

这些是开发者已读的 Dev 设计，不是未见测试集，也没有标准文案。输入与评审依据分别交付：生成者只接收当前回合；`cases.jsonl`、本目录说明和协议由运行者与评审者保管。批量模型运行由用户完成。

| 案例 | 变化 | 回合 |
|---|---|---|
| C061-GOAL | 普通进展请求 → 协调任务 → 改为原因复盘 | 3 |
| C061-JUDGMENT | 样机与测试机待安排 → 条件落实但工作量未知 | 2 |

| C061-TRANSFER | 单站实践 → 不同条件的候选站点 | 2 |
| C061-AUDIT | 只读正文 → 任务与来源 → 作者说明及旧审阅 | 3 |

检查结构或只显示当前回合：

```text
python evaluation/tools/validate_content_cases.py
python evaluation/tools/validate_content_cases.py --case C061-GOAL --turn 1
```

命令不执行模型、不写结果。输出的材料路径以 `fixture_root` 为基准；只向执行模型提供列出的文件内容，不能授予整目录阅读权限。审计案第三回合的旧意见不是正确答案。
