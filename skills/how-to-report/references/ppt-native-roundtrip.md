# 原生 PPTX 配置读取与重建

适用于用户要求读取真实 PPTX 的对象与布局配置，再原样重建，或基于原配置做保留式修改。入口为包内 `scripts/report_engine.py`，可从任意当前目录调用。原生工程独立于常规作者文档，两者分别使用自己的结构与校验入口。

## 三个入口

以下路径均为示意，输出选择尚不存在的文件或目录。

```text
python <Skill>/scripts/report_engine.py native-import --input <source.pptx> --output <new-native-project> --slides 4
python <Skill>/scripts/report_engine.py native-inspect --project <native-project>
python <Skill>/scripts/report_engine.py native-build --project <native-project> --pptx <new-rebuilt.pptx>
```

`--slides` 接收一个或多个从 1 开始的页码，例如 `--slides 4 7`。它标记重点审阅页，导入仍保留整份演示文稿及其依赖。省略时沿全稿检查。需要拆出某一页时，应另行实现依赖完整的页提取操作，不能直接删除其他 ZIP 成员。

三个命令成功时向标准输出写 UTF-8 JSON。内容、路径或输入校验失败沿引擎的 `{"valid": false, "error": "..."}` 错误格式返回非零状态，缺少命令参数由命令行解析器报错。导入和重建拒绝已有输出，使用新目标保留原件与历史结果。`native-inspect` 只读取和校验工程。

## 工程保存什么

入口文件为 `native-project.json`，版本为 `how-to-report.native-project.v1`。工程中包含：

- 来源名称与 SHA-256，以及全部包成员与依赖清单。
- XML 的结构化 JSON 树，保留元素、属性、命名空间、顺序与文本。重建从这些树重新序列化 XML。
- 图片等二进制资产及其摘要，保存于工程内部。
- 逐页对象配置及其 XML 绑定，供定位对象层级、原生变换和文字编辑。
- 实际提取覆盖与限制，区分结构保留和可直接操作的语义字段。

完整搬迁整个工程后可继续重建，不需要原始 PPTX。来源信息用于溯源。不得把原始 PPTX 或原始 slide XML 当作隐藏的重建依赖。

母版、版式、主题、关系与扩展节点也参与还原。部分对象外观来自继承，不能只看幻灯片对象上是否显式声明字体或填充。隐藏对象保留隐藏状态，原稿中的渐变、阴影和旋转也保留。用户要求新设计优先纯色、渐变最低偏好的规则用于新设计和明确的派生改版，原样基线保持原稿样式。

## 配置修改与边界

当前原生路径允许对已有原生变换与文字字段作明确修改，并按绑定写回对象。先复制一份工程作为派生版本，记录修改对象与理由，再运行检查和重建。文字长度变化可能超出原框，移动对象可能影响连接、遮挡或组合关系，修改成功仍需目标 PowerPoint 验证。

在入口文件的 `slides[].config` 找到相应页的配置。逐页配置中，`objects[].id` 和 `parent_id` 对应原生对象及组层级，`transform.coordinates.off`、`ext` 等字段保存实际存在的变换，`text_runs[].text` 保存文字片段。示意片段如下，实际编辑保留该对象的其余字段：

```json
{
  "id": "229",
  "transform": {
    "coordinates": {
      "off": {"x": 914400, "y": 914400},
      "ext": {"cx": 3657600, "cy": 914400}
    }
  },
  "text_runs": [{"text": "更新后的标题"}]
}
```

这是字段说明，不是可独立导入的完整对象。`binding` 记录相应 XML 树节点位置，修改文本或变换时保留其绑定。重建优先应用语义配置中的文字与变换，因此不要只改 XML 树中的同名旧值。`properties` 中的路径、段落格式、填充等条目是 XML 树位置索引，表示可定位原始定义，并非任意类型都已经有统一高级编辑接口。需要编辑这些定义时，按原生 XML 语义修改并复验。

原生坐标以源 PPT 的整数 EMU 保存，旋转及变换沿 DrawingML 单位。组内坐标通过组变换解释，不应把子对象坐标当成页面绝对位置。首次还原不进行额外缩放、统一主题或字体替换。

这一入口提供原样配置重建能力。任意页的业务语义、可增删节点规则、文字自动回流和几何约束推导仍需专门适配。XML 节点被完整保留不代表该节点已有高级组件接口。新稿的 Grid、Flex、文档流和拓扑重排使用[计算排版与拓扑](ppt-layout.md)，按正常 `build --geometry-policy computed` 计算。

## 验收证据

原样还原至少核验下面三类证据，分别记录范围。

1. **配置与对象。** 比较页数、对象层级、类型、文字、几何、样式、关系和二进制资源，记录未解析或未提供语义编辑接口的部分。XML 结构比较只证明相应结构范围。
2. **实际显示。** 在同一台 PowerPoint、相同字体和导出尺寸下，分别渲染原件与重建件，逐页比较像素并检查差异区域。两张图片来自相同文件或只比较 SVG 边界不能作为这项证据。
3. **实际修改。** 在隔离副本中修改配置中的文字或变换，再重建并核目标对象确实变化。按需要在 PowerPoint 中完成文字编辑、组合移动、保存重开，验证承诺的编辑操作。

重建 XML 的序列化和 ZIP 压缩可使文件 SHA-256 改变，文件摘要不同不直接等于外观不同。相同像素也不能单独证明原生可编辑性。对最终版本记录输入配置、产物、渲染条件和实际检查身份；没有执行的检查保留未验证状态。
