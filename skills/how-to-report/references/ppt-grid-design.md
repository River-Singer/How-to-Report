# PPT栅格设计选择

页面内容与任务已明确、需要选择比例和对齐方式时读本页。先遵守[PPT交接](ppt-handoff.md#页面视觉语法与篇幅预算)的视觉语法、授权页数和减页要求，再沿[计算排版](ppt-layout.md)提交容器；不由AI手填最终frame。

## 设计栅格与计算grid

设计栅格确定主次、阅读顺序、对齐线、组间距离及重复节奏；求解器`grid`只是按轨道计算位置和大小。整齐等分不自动好看，也不代表内容完整。12列便于二/三/四等分，24列可描述更细比例；它们是设计参照，不要求在PPT里画12或24个框。

Ant Design采用24份划分，Bootstrap采用12列容器/行列结构；Carbon 2x Grid强调倍数、分割与一致间距。以下PPT选型是本项目对这些原则的应用，不是它们发布的PPT模板。固定16:9画布不套网页手机/平板断点，不按屏幕截图像素重新换列。[Ant Design](https://ant.design/components/grid/)、[Bootstrap](https://getbootstrap.com/docs/5.3/layout/grid/)、[Carbon](https://www.carbondesignsystem.com/building-blocks/foundations/2x-grid/overview)

## 按内容关系选排布

| 排布 | 适用任务 | 何时改选 | 现有容器表达 |
|---|---|---|---|
| 主内容＋侧栏，8/4或9/3比例 | 大图/主比较与较短的相关解释；9/3侧栏更窄 | 两侧同等重要，或侧栏实际是完整图表/长解释 | 两轨`grid`，列为`[{"fr":2},{"fr":1}]`或`[{"fr":3},{"fr":1}]` |
| 6/6双栏 | 同等重要的对象、方案或前后对照 | 内容量悬殊；有意制造的对称遮住真实主次 | 两列`{"fr":1}`，同类图保持尺度与图面尺寸 |
| 4/4/4三栏 | 三个可并列、解释量接近的对象 | 长标签/复杂拓扑在窄列内无法按规范读清 | 三列`{"fr":1}`；不足就改整体结构，不删条件 |
| 重复小图，2×2或3×2等 | 同类数据跨人群/期间重复比较 | 图种不同、尺度不兼容或每项都需长解释 | 同轨宽grid，行内同类图面和标签槽对齐 |
| 全宽主题＋下部主次/并列 | 上下两层共同回答本页，或主图需要横向宽度 | 全宽区只重复下方标题/读数 | 外层`column`，下层嵌套两/三轨grid |
| 纵向条带 | 阶段、步骤或多项横向长标签比较 | 没有实际顺序，却被排成推进关系 | `column`内重复row，稳定标签起点和图面起点 |

8/4、9/3在此是主次比例简称。当前fr按扣除间距后的空间分配；这不等于实现完整12轨道中跨8列/4列的精确跨列几何。需要上下一致的整列边界时复用相同容器比例、内距与gap，不假定独立子grid会自动共享轨道。

## 对齐与边界

先用同一内容外边界，再统一同级标题、图表绘图区和直接标签的起点。相关项间距小于组间距，重复单元使用同一套间距；不要每个框各自居中。纵向节奏由统一字阶/行距和测高建立，不能为了机械基线重叠文字或隐藏条件。共享图例与口径可节约空间，重复卡片背景和粗边框不是必须元素。

当前稳定语法是嵌套`row`、`column`、`grid`及数值/auto/`{"fr":n}`轨道，`fr`不是字符串`"2fr"`。完整参数读`report_engine.py layouts grid`和[当前合同](ppt-layout.md)，不要从网页CSS API推断PPT字段。显式列Grid直接子项支持`column_span`，按覆盖轨道加沟槽测量；不支持row_span/subgrid或与auto_fit混用。全宽标题也可用外层column中的全宽兄弟节点；侧栏跨数个内部行仍用左右分组后各自嵌套column。自动列数等能力仅以当前真实查询合同和已验证范围使用。

本页排布是设计建议，不是已登记的recipe或asset ID。须查询真实组件、绑定已有数据，再经computed构建、读取诊断并看实际成图。保留正文14 pt/最小9 pt、[按任务选图或明细表](ppt-data-display.md)、同类同图与全局配色；先在内容不丢的前提下尝试合页。栅格不构成删内容、碎片化分页或把不同分母混为同一比例的理由。原生源保真任务继续保持原配置，不擅自套新网格。

需要更细场景、读序、对齐、容量失败分支及当前引擎映射时，读[16种栅格与内容模式](ppt-grid-patterns.md)。文字较多的资讯/介绍页先读[长文本结构化](ppt-explanatory-content.md)。这些是选型方法，不宣称新增16个算法或所有模式均已有可执行recipe。
