# 前提与约束审查

- **触发**：建议依赖尚未核实的前提、方案与目标混淆，或症状解释遗漏真正制约条件。
- **动作**：区分已知事实、用户目标、不可擅改的合同/审批/资源边界和工作假设。将具体困难抽象为需要满足的条件，再改变一个可变前提比较后果。硬约束只能标出或建议另行变更，不以“第一性原理”取消。
- **可观察结果**：写明哪项前提有证、未知或被反例挑战；替代前提会改变哪项方案/证据需求。增加人力与取得接口批准可能解除不同阻碍，不能自动互换。
- **回落与停止**：回到原材料，指出应改的建议或最小补件。若抽象没有新增区分、前提已明确，或差别只能靠事实核实，停止继续升维。
- **镜像检查**：核对抽象有没有丢掉时间、授权、对象和必要条件；候选前提不能写成项目事实，合理替代不等于用户已选择。已明确目标不反复问动机。

背景：[本地抽象与纠错研究摘要](method-sources/sources/step-back.txt)。研究任务与管理汇报不同，不能据论文标题声称本 Skill 已提高推理正确率。
