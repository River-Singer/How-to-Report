# 从零散记录到有内容的概括

本方法负责来源提炼、关系辨认和含义保真，不负责整场叙事或执行顺序。记录多而杂、同主题状态不一、抽象后失去具体意思或压缩可能改义时使用。简单清楚的句子直接编辑。

## 找出本次问题需要的记录

围绕已采用的听众问题，辨认谁对什么做了什么、现在是什么状态、相对什么参照，有哪些解释、条件或请求。按意思辨认，不按标点拆句，也不要求每条填满字段。保留可回取的材料定位；材料未说、相互冲突和范围不明都不能改写成确定事实。

对聊天、改稿和多版材料，核同一事项的原句、说话者、适用范围与后续更正。历史的“我”属于当时发言人，不自动是本次汇报者；工具名称不证明人员身份，助手草稿中的个人贡献也不自动获得用户确认。来源已有的个人识别、判断、推进与协作作用应准确保留，不为避免归属错误而把所有贡献都抹成“团队完成”。早期角色被后文改写，不与新版拼成新增成员。先排除误归属；当前身份不影响内容时用有依据的团队或职能表述，确实影响本次内容才问用户。

来源声称的关系、当前推测与已经核验的关系有不同身份。原文写因果只证明它这样声称；缺乏关系支持时不要自动降格成“相关”或“可能影响”，因为二者仍声称关系。可分别写事实；确有假设则保留其假设身份。

## 跨记录归并，再写统摄句

先问这些记录共同回答什么：覆盖了哪些对象、哪项工作到了什么状态、阻碍是什么、采用了什么做法，还是哪个选项更合适？同词出现不等于共同回答；同一事项散落不同段落也可以归并。

1. 找出可共享的背景，合并重复记录；保留会改变判断的对象、状态、例外和条件。
2. 用统一的问题或比较标准组织一组信息。为听众补出资料已支持的对应关系：什么输入经过谁的处理成为何种结果，哪些选项按同一标准比较，或哪项未决影响哪项安排。事实、条件和请求可以共同回答“下一步如何推进”，不必为分类纯净拆散；但不得把工具、活动和预期收益伪装成同级已实现成果。
3. 用自己的话写这组材料共同说明什么，再回查每个组成部分。概括可以是原文没有的统摄句，但其含义必须由已有材料支持；不能借“重新组织”新增事实。
4. 保留支撑或区分概括所需的细节，移走不服务本次问题的分类。细节可以是一项操作、一次对照或一个关键例外，按本次问题选，不是只保留异常、亮点或数字；少数例子也不代表穷尽全部类型。是否已让听众理解，由主工作流用实际成稿检验。

例如“一线访谈已完成、规则清单仍在定稿”可以归为需求工作进展，不能缩成“需求已确认”。“积极开展调研”只是抽象标签；覆盖谁、发现什么、哪些还未定，才构成有内容的概括。一次访谈与一项规则不是同一计数单位，不按行数或共有主题相加。

删除前检查该信息是不是后续判断的前提。可以删无关明细，不能删掉会使结论读法改变的条件。标题、表头可以承担共有对象和期间；内容被独立摘出或转成口头稿时，要补回缺失的上下文。连续过程见[合成教学](content-decisions.md)。

## 概括不等于判断已经成立

概括回答“材料合起来说了什么”；推断回答“据此能判断什么”。前者有记录支持不保证后者成立。完成了访谈不等于范围已经批准，问题关闭数量不等于剩余风险不重要。

先保留忠实概括，再将新增解释、用途、建议及其条件交给[论证方法](method-argument.md)；主动新增区别的检查与深化由[解释探索](insight-discovery.md)承担，两种检验不互相替代。不要为了贴合预先目标而删反证，也不要因尚无收益数据丢弃有依据的用途说明。

## 含义保真的共同标准

生成、编辑和审计共用以下标准，具体顺序由主工作流负责。拟稿把状态、范围或条件写成确定事实时，可用一个合理边界情形核对：**来源仍真，改写却可能为假，差在哪里？** 例如“已开始但未完成”符合“未完成”，不符合“没做”；记录未提供，事情仍可能做过；某组件本地运行，其他环节仍可能采用不同方式。找到新增部分后回来源修句，不把假设当事实，也不要求逐句造反例。有依据的解释、带假设的预测和明确建议仍按其语气与条件核查，不要求变成必然事实。需要深化时用[概念](method-concepts.md)或[论证方法](method-argument.md)。

- **对象与归属**：动作和限定跟着原对象，不在委托者、团队、开发者、工具间转移；组件属性不扩为全链条，单个实例不变整体能力。
- **状态与范围**：已完成、进行中、未开始、拟议、预计、未获答复分别保留；否定、数量、期间、部分/全部和频率不扩大。先辨认否定的是资料还是项目行动：“未附测量记录”不能写成“尚未测量”，只凭未获答复不能写成尚未安排；未完成不排除部分开展。完成标准有验收/接受要求时，“记录齐备”“已提交”不能统称完成交付；概括、标题和比较使用同一适用终点。用户禁止某项正面断言也未确认相反事实。缺件影响判断才说明证据需要；正文、追问答案与作者说明同样核据，无关否定直接删去。
- **比较**：对象、单位、时间、基线和定义须可比；“相同”具体修饰什么应保留，费用组成相同不说明可用资金足够。两个各自为真的结果不自动可合计或共同支持结论。重要计算按[数值方法](numeric-evidence.md)复核。
- **关系**：时间先后不自动是因果；已知阻碍不排除其他原因，“增人不能替代批准”不等于“与工作量无关”。资料明确且影响判断的依赖不能省成两个独立状态，也不能只凭相邻日期推定依赖。职责列表不因逗号顺序变成流水线或说明执行频率；相关不等于同义，依赖方向不能反转，两个前提并存不代表它们之间有先后或互为前提；若只支持接受后可试用，试用窗口就不能反向成为接受的前置条件。
- **条件与强度**：必要条件不自动充分，预测不变承诺，用途不变实绩，职责承诺不变达成保证。核对“满足后就能”声称的充分性，也核对“全部完成后才能”新增的必要性；纠正过强承诺不能改成没有依据的评估禁令。带假设的估计可以在工作完成前提出，但其假设、工作量和时间依据须适用。
- **请求与归因**：“供知悉”不变“请批准”，来源意见不变作者独立验证。共用期限可约束多个动作；联系到人不等于问清时间，拟申请不等于获批。收到反馈、条件满足、计划可执行、备选触发各有依据，不能压成自动二选一。新增安排可以作为建议，不冒充原请求规则。更新及同项行动的一致性由生成主流程负责。

保留影响本次判断的反证和正式必答。上层标题和结尾应受下层内容支持，流畅和句式平行不证明含义未变。不要求逐字保留，也不禁止正当专业词。发现问题修最早出错的归并、关系或概括，不用末尾免责声明替正文纠错。叙事/详略由[会议表达](meeting-expression.md)负责，措辞由[观众编辑](audience-copy.md)负责。

归并思路的来源和研究限制见[阅读与摘要研究](method-sources/sources/reading-synthesis.txt)。它提供编辑启发，不是中文汇报或本Skill效果已获验证。
