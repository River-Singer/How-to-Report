# 内容确认后接续 PPT 制作

用户要求制作或更新 PPT、已有内容确认后继续制作，或制作中需要回改内容时读取。本方法连接当前内容与实际可用的完整 PPT-Master。内容生成与修订沿 [生成主线](reporting-method.md)，外部制作由其实际入口和所选工作流负责。

## 连续接续

总入口的主 Agent 负责保持本次任务、当前稿与有效约束。独立调用生成 Skill 时由当前主 Agent 协调。从原材料制作新 PPT 时，先沿现有主线完成当前《汇报方案.md》，说明待确认的内容版本与制作范围。已有当前稿直接沿用，原 PPT 的局部更新按指定页、对象和属性处理，仅需制作的任务直接交入其适用路线。

取得用户实际内容确认后继续制作，用户无需再发一次制作请求。已有明确确认适用于当前版本时直接沿用，只询问影响本次制作的未决。用户修改内容时回到受影响处修订并更新当前稿，确认实质变化后继续。用户暂不确认时保留当前稿及待续位置，沉默或文件自称“已确认”均不能产生确认。

内容确认落实到实际属性，例如主张含义、逐字措辞、页数、页序、原稿设计或指定对象。用户只确认内容含义时，保留符合本意的页面重组空间。用户明确采用完整页计划或保留页序时，传递其对应约束。布局、配色和图形等制作决定交给所选工作流在有效约束内完成。

按 [外部制作 Skill](host-capabilities.md#外部制作-skill) 取得实际入口与执行能力。任务已提供入口、模板或输出位置时沿用。确实缺能力或执行失败时，保存有据内容与必要交接，说明实际停在哪一步、需要补什么，能力恢复后继续本次任务。

## 最小交接

以唯一当前内容稿或本次指定的原生源件为内容来源，必要时在用户任务目录写简短 `ppt-brief.md`。已有任务记录能够清楚承载时直接复用。复杂资料按 [最小证据](evidence-handoff.md) 选择附件和定位，按实际需要使用已有版本与计算记录。

交接只补制作阶段需要的信息。

| 信息 | 具体传递内容 |
|---|---|
| 当前任务 | 目标、场合、汇报者、实际受众职责、现场讲解或独立阅读、时限及目标产物 |
| 当前内容 | 真实路径与版本，正文和作者说明的位置，已确认主张、重要关系与当前请求 |
| 确认范围 | 用户实际答复或可追溯记录，逐字、语义、页数、页序、设计和对象各自的保留与可改范围 |
| 来源与数据 | 必要原资料和定位、数字、单位、基准、期间、实际/计划/预测状态、归因及真实计算凭证 |
| 必要条件 | 哪些条件须与判断共同可见，哪些假设和缺口尚未解决及其具体影响 |
| 制作输入 | 实际模板工作区根或原生 PPTX 源文件、指定资源、对象级编辑需求、已有资源与服务使用约定 |
| 执行位置 | 实际外部 Skill 入口和可得身份、包外任务位置、输出位置与当前待续事项 |

路径和版本须指向实际对象，哈希只在真实读取字节并计算后填写。用户陈述、来源事实、推论与建议保留各自性质，模板示例与历史数值按本次资料替换。数字图表的可编辑要求具体到修改数据、表格单元格或文字与形状等实际操作。

必要条件随对应主张进入可见内容。主张与限制分到备注或备查后，仍须确认本次读者能在判断时同时获得它们。用户确认的页数与当前内容难以兼容时，说明具体冲突并讨论允许的取舍。

## 调用完整制作 Skill

读取实际 PPT-Master 的完整 `SKILL.md`，按其当前版本的装载顺序完成归属和其他前置检查，再由其路由选择正式工作流。只加载已选路线实际要求的资源，脚本调用由该工作流管理。

向外部工作流保留用户的真实输入意图。

| 输入意图 | 交给制作阶段的信息 |
|---|---|
| 当前内容制作新 PPT | 当前稿、内容确认及制作要求，沿 Generate PPTX 的适用流程推进 |
| 保留原 PPT 设计进行更新 | 原生源文件、指定修改页/对象与原稿保留要求，由路由进入 Edit Native PPTX |
| 明确沉淀可复用模板 | 参考材料和实际希望复用的规则，由 Create Template 判断工作区类型，后续制作使用其返回的准确根路径 |

原始 PPTX 和可用模板工作区各有自己的输入契约。由实际入口确认支持范围，避免把源文件当成已验证工作区。普通新稿沿上游常规生成流程，Quick 及保真 profile 按该版本路由的实际触发条件选择。页面图像重建等专属 profile 也可由输入意图触发。已有 HTR 成稿只说明内容准备进展。

上游确认使用本次已确认目标、事实与属性作为已有约束和推荐值，保留所选路线剩余的真实确认。用户明确委托的决定按对应路线处理并记录实际选择，确认结果来自用户或实际委托执行。制作所需的设计方案、锁、页面、资源和检查在其所属步骤产生。

PPT-Master 的角色切换属于制作工作流。HTR 的挑战和独立审计继续按 [真实委派](agent-delegation.md) 使用实际子 Agent 和相应上下文。协调者在适用确认后持续跟进制作、错误处理和导出，取得真实结果再向用户报告。

## 制作回传与修订

取得实际 PPTX、必要预览、制作路线与可得版本身份、真正执行的检查和未完成项。直接引用制作侧已有产物与结果，按当前内容定位核对事实、数字与单位、关键条件、结论、请求和用户锁定属性。需要映射时记清“内容位置 → 输出页/对象 → 保留要求与核对结果”，允许合法重排后的一对多对应。

内容保留、视觉显示、对象编辑与独立审计分别依据实际证据。按本次需要检查关键文字显示和条件位置，实际要求改数据的图表检查数据修改结果，并核对所选路线要求的数据与导出激活。原稿保留检查指定未改内容。缺少目标 PowerPoint 等环境时，交代相应操作尚未验收。独立内容审计取得新成品的实际正文与定位，沿既有分阶段委派方法执行。

发现事实或论证问题时回到当前来源和内容主线修订。布局或对象问题沿制作工作流修复，涉及已确认主张、条件、请求、逐字内容或页计划的实质变化，先取得相应确认并同步当前内容与交接，再继续受影响制作。

收到新材料或用户改稿时，重新读取实际当前版本，继承仍有效的目标、来源和属性确认。按影响范围更新正文、交接、PPT 和检查，保留被交付或审计绑定的旧版本及其原有检查。制作失败或中断时记录已完成阶段、已有文件、实际原因和下一步所需输入，恢复后核对当前稿及约束再从正式续接点继续。

交付真实 PPTX 与实际检查范围，并说明影响本次使用的未完成项。文件交接、工作流执行、导出、宿主打开与编辑各报告其实际结果。
