# 项目进度：从明确口径到可核对的时间视图

用户需要进度、计划实际对照、里程碑、预测变化或交付验收时，按本页选择工具。先明确听众要知晓、判断或决定什么；简单一句状态更新不必画甘特。领域原理按已有Knowledge授权规则加载，工具不会替用户补造业务材料。

## 调用

```text
python <skill>/scripts/report_schedule.py validate SPEC.json
python <skill>/scripts/report_schedule.py render SPEC.json --views summary,gantt,milestones,outcomes,drift --output NEW_DIRECTORY
```

选择当前确实需要的视图，不要求每次五页。可选`--width 1600 --height 900`沿用受控Deck的画布范围。输入示例：[合成进度输入](../assets/report-html/sample-schedule.json)。结构参考：[ScheduleSpec Schema](../assets/report-html/schedule.schema.json)。完整跨字段规则由实际`validate`执行；Schema通过不代替运行检查。

运行仅依赖Python标准库与本Skill，生成使用统一Deck，输出包含原始`schedule-input.json`、派生`plan.json`、HTML、page-map、render-receipt与schedule-receipt。只写新的外置目录，不覆盖、不修改Run、不生成pass检查。收据包含真实输入/方法/输出哈希、所选视图、警告和未运行的浏览器/语义检查状态。注册产物时使用现有版本工具，明确引用实际使用的ScheduleSpec版本及原来源。

## 最小材料与时间语义

- 请提供本次状态日、采用的批准基线及版本、截至该日的实际记录、剩余工作的当前预测；已有周报和表格即可，不要求用户先制作JSON。
- 当前契约`schedule_version:0.1`只支持自然日与日终快照；完成日包含在区间，状态线位于状态日次日起点。不能换称工作日；不自动读取机器今天。
- `baseline`有身份、正整数版本、批准日与精确来源引用。任务/里程碑的基线日期使用该参照。无基线可画现状，不能推导按期/延期；无预测不复制基线。
- `actual`必须已经发生。进行中/受阻需实际开始，完成需实际完成；尚未开始不能带实际区间。`forecast`是状态日之后的剩余预测；预测不是承诺。
- `progress`可不提供。提供时必须有0–100有限数值、计量basis与refs；时间经过不等于实物完成率，不能自动算剩余天数或平均不同口径的百分比。
- `acceptance`与执行状态独立，区分未提交、待审核、已接受、未通过、未知。已接受/未通过必须声明标准、结果、范围和来源；允许明确范围的局部验收，不凭该状态推导项目全部完成。
- 每个日期/状态所属记录有精确`{id,revision,locator?}`来源，必要时locator指向原表格/记录。引用声明不证明来源真实或可访问，审计须实际读取。

FS只支持零lag基础检查，不是排程引擎。后继开始日期早于前驱完成日会拒绝；同一天的交接保留`same_day_fs_order_unknown`警告，因为日级材料不能证明日内顺序。未给出的端点无法检查，不表示依赖已验证。不得自行移动日期消解冲突、把红色关注项称作关键路径，或把任务偏差相加当作项目总延期。

## 按问题选择视图

| 视图 | 需要 | 缺失时 |
|---|---|---|
| summary | 显式`summary.task_ids`、选择理由，可选`summary.milestone_ids`及需要支持的actions | 不按输入前六项截取；所有受阻任务必须保留并可分页，行动全部输出，无行动不编造请求 |
| gantt | 任务和已有日期/状态 | 未知保持未知；只有一个端点显示点，不杜撰持续时间 |
| milestones | 有来源的事件及已有日期 | 事件以标记表示；无基线不写日期偏差 |
| outcomes | 交付物及可提供的验收记录 | 缺记录显示未知，不替换为未通过或已接受 |
| drift | 至少两个实际保存的报告期预测、同一批准基线 | 单点不能画变化；两点仅表一次变化；缺历史点不插值；混基线返回阻碍，拆成明确参照的系列 |

漂移每期预测绑定基线`id/revision`，报告日期按真实间距绘制；每个历史预测不能早于当期报告日。当历史`reported_on`等于本次`as_of`且同一节点也声明了当前`forecast_date`时，两项已知日期必须一致；冲突直接拒绝，不替用户挑选。当前预测缺失时仍保持未知，不从历史自动补入。若历史报告日晚于当前记录的节点实际发生日，保留原历史并发出带实际日、报告日、预测日及双方来源的`historical_forecast_after_actual`警告；需核对当时可得信息，不能自动改写旧记录。当前支持每个历史序列2–12个快照，每页最多4条。超过4条或真实日期过密导致标签不可分辨时，明确降级为完整分页日期表，不等距拉开日期或覆盖标签。超过12条需明确选择窗口并保留原始历史来源，不能静默截断。不同基线不可直接连成可比曲线。

摘要以状态、当前日期、相对基线偏差和关键条件构成紧凑表，而非重复完整甘特。任务与关键节点分别明确显示选取x/y；`summary.milestone_ids`可为空或省略，但页面会说明未选节点不代表没有风险。节点选择与关键条件完整分页保留。只生成摘要不声称存在后页。额外行动按页完整输出，可能重复少量上下文；事实并未被复制成新的业务对象。业务任务ID不是Agent工作TaskID；实际取证/计算/绘图任务仍使用Run的TaskGraph。

## 容量、图形与审计

时间轴在同一输入的各页使用统一范围，日期以真实自然日距离映射，标签显示年份以免跨年混淆。基线细灰、实际实体、预测描边/虚线，并提供完整文字日期、状态、偏差与来源。实际条表示经过区间；已有实际开始但未单列未来开始的任务，剩余条从状态日后起画到预测结束，只是剩余区间显示约定，不新增未来开始事实。

默认分页是保守初排，不是任意内容可容纳的证明。真实长标签、多个来源、行动与条件可使页面超出容量；先调整内容分组/列宽/行高/分页，必要时停止该布局。不要删关键条件、隐藏来源或无限缩字。按语义保真替代时保持同一事实，不为工具改写项目状态。

完成后实际进入所有页面/主要状态，核对几何、SVG边界、可读性、导航、阅读和打印；缺浏览器明确not_run。独立report-audit先从原资料和成品反读，然后再看PagePlan，检查基线是否被覆盖、实际/预测是否混淆、摘要是否漏关键阻碍、已完成是否冒充验收，以及标题是否比数据更强。

技术上成功不代表真实进度成立；这一合成示例只证明机制。完整来源方法与用户案例结果应分别保存，不把示例当真实MASTer排期。
