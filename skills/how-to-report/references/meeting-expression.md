# 会议疑问、时长版本与 Backup

用于正式汇报、答辩、评审或用户要求短长版本；简单短句不强制预演。先复用已确认目标、议程、对象权责和正式评价条件，不能凭职位猜性格或从“领导”推导必然要自我表扬。

## 让疑问改变内容

从当前核心判断及必要行动找少量候选问题：对方需要知道、相信、决定或能够执行什么？逐项回看材料，区分“缺事实”“已有事实尚未表达”“表达难懂”。这些是模型生成的候选疑问，不是真人已经问过或同意的反馈。

| 去向 | 判据与实际动作 |
|---|---|
| 主线必答 | 不回答会改变关键判断或请求，补在读者作出判断之前，必要条件不能只放Backup |
| 按问题可定位的Backup | 支持核心判断的展开细节，建立明确问题入口、目标页和返回位置 |
| 材料请求 | 关键问题无法用现有证据回答，列出最小补件和取不到时的有限说法 |
| 暂缓/不相关 | 不服务本次结果或只有刻板猜测，说明理由即可，不凑疑问数量 |

可在原蓝图中用“候选疑问—依据/角色—当前回答—去向—影响”一行记录。若所有疑问都没有改变内容、定位或补件，检查预演是否只是重复主张。正式责任复盘不擅自改成资源协调会。

## 按时长重新分配任务

用户要求30秒、3分钟或10分钟时，先确定不能丢的判断、决定性依据、行动与条件，再决定展开深度、顺序和举例。不要按比例删除每段文字。短版与长版共享同一版本事实和单位，不能将可能改成确定；必要风险不能全部挪入听众不会看到的备查页。独立阅读版需自足，现场讲述版可用备注解释次要细节。

留一份简短去向差异：哪些合并、移入Backup、暂缓，理由是什么；给真实的讲述时间预算，词数/速度只能是注明口径的估计，不能宣称实际演练。真实排练才记录测得时长。

PagePlan0.2 可用 `main_path` 明确主线，`backup_links` 的标签写听众问题、`target` 指向实际存在页；`notes` 存对应页讲述安排。JSON只使用当前渲染器已定义字段，策略记录放蓝图/笔记。实际验证进入Backup后返回原主线位置、目录/页点/hash同步及打印/阅读全部；UI存在不证明路线合理。无浏览器只声明路径结构已查。

## 独立检查与停止

审计先看实际短版/长版和真实入口，再对照原资料及可选蓝图：核对事实与强度、必要条件、问题定位和返回状态。无生成笔记不妨碍检查成品；没有真实听众反馈时不宣称沟通成功。重要疑问已安排或缺口明确即可停止，新增问题只是换词时不继续扩张。
