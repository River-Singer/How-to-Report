# SWE-03 系统边界、数据路径与承接

版本：0.3.0。核对：2026-11-12。可选软件工程卡；仅在有效许可覆盖本卡及相关来源时读取，不扩大既有授权。

## 判断问题与输入

“本地”“内网”“平台复用”到底覆盖哪些链路，交付边界是否支持技术承诺。

必要输入：实际组件/部署、外部服务、接口与传输字段、开发/运行依赖、日志监控备份去向、接入约束和运维承接；已有架构图/配置优先。

## 实际操作

1. 按具体用途还原输入、处理、存储、输出及跨边界调用，标明各组件实际部署和责任，开发工具链与运行链分开。
2. 沿敏感字段和关键服务追到日志、监控、备份、第三方与人工操作，分清已确认与待核路径；一个组件本地不代表全链无外传。
3. 比较拟复用能力与真实需求、接口和容量，列能直接复用、需适配和未覆盖部分；同名能力不证明兼容。
4. 核上线后的服务责任、接收条件、故障处理与退出/迁移安排，将边界缺口落实到请求或承诺强度。

## 产物、限制与停止

交回可复查的系统/数据边界说明、复用差异和承接条件；文字图或清单即可，不强制架构平台。它不是安全认证或全部代码审计。

缺关键调用或存储信息时向用户索取相关架构/配置或逐项说明；缺失记录不证明链路不存在。安全控制问题另按已授权SEC-01检查。

汇报人负责完成这些分析并组织为可理解的内容；挑战者用同一知识按真实职责检验最强的目标相关阻断，实质输出仅问句，不给答案或修法；独立审计核实际内容、来源与执行，不按方法名称判通过。角色与派发规则见[委派契约](../references/agent-delegation.md)。

## 短应用与误用

合成例：推理在内网，错误日志发到外部监控；只能说推理本地，不能说数据全链不出内网。误用：看到“私有部署”字样就排除外部开发、插件和日志路径。 以上均为合成教学例，不是用户项目事实或固定问题模板。
