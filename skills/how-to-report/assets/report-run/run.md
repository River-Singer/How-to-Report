# 汇报工作区说明

本文件是初始化模板；本次 Run 身份、模式、已登记来源和工作状态以同目录的 `run.json` 为准。
手动使用时替换 Run ID，按实际请求选择 `create`、`revise` 或 `analyze-first`。
`revise` 必须登记待修改报告为 Source，并标记 `role: revision_target`；它尚不是本次采纳的产物。

若使用 `report_run.py init`，仅明确传入的本地文件会被复制到 `inputs/`，
`ref` 与 SHA-256 绑定保存的快照；`origin` 仅记录原路径和文件名。
`revision: 1` 只表示本 Run 的登记版本，不能推断原材料的业务版本或最新状态。
手动复制模板本身不表示快照已建立或哈希已计算；按真实完成的操作登记文件和来源。
快照保存不代表内容已阅读、核验或被采纳，也不代表获得任何额外 Knowledge、画像或目录读取授权。

按本次真实请求补充：

- 请求、汇报人、对象、场合与交付形式：待记录。
- 已知约束、待澄清事项和明确排除范围：待记录。
- 当前可用输入、缺失材料与来源限制：待记录；不得从空模板推断已提供证据。
- 下一步：先核对实际输入和当前请求，再确定需要的分析或交付工作；仅登记实际完成的结果与检查。

初始 `artifacts` 和 `checks` 为空，工作状态为 `in_progress`。
本模板未创建报告、Blueprint、图、任务、审计结论、授权事件或已确认画像。
简单任务可保留简洁记录；需要附加记录时再根据真实工作创建，并登记对应指针。

恢复工作时先只读检查现有文件或执行 `report_run.py inspect`，不要重新初始化已有目录。
检查结果只说明结构与声明引用的一致性，不执行来源脚本，不自动继续任务，不选择业务当前版本，
也不把 `completed`、空检查列表或退出码 0 当作内容正确、来源最新或交付已获接受。
原文件后续变化不改变保存的快照；本工具不回读原路径来发现或判断业务变化。
目标或材料变化需要由实际执行者按当前请求另行登记版本、判断影响和复核，不能静默刷新旧哈希。
