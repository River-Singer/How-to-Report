# Report Audit

从原资料和待审产物重新判断内容是否成立、是否遗漏重要内容、表达是否失真。单独使用本 Skill 即可审查外来报告；没有生成侧图或 Blueprint 不是拒绝入口的理由。

## 输入与范围

取得用户要求、待审产物及可访问的原始材料，锁定版本和审计范围。缺失材料时继续可执行的检查，明确哪些无法评估。Audit-only 只写自己的审计结果，不修改原件或生成侧图。用户明确要求修复时，区分审计发现与随后获准的修订。

## 独立性与多图检查

如宿主允许，使用新上下文，只接收必要的原始资料、要求和实际产物。说明真实的上下文继承、原资料访问、是否预见生成计划，以及数值复核方式。新 Agent、换模型或另一文件夹都不能单独证明独立。

先重建读者能从产物得到的判断与关系，再对照来源与可选生成图。生成图中的 `verified`、`supports` 或 Task `completed` 都是待审声明。可以提出遗漏的竞争解释、反证、证明义务和修复任务，写入自己的报告；不能因图内部自洽就通过。

核对实际产物追求的目标与原要求是否一致，潜在效果是否被写成个人动机，用户选择是否被当作事实证明。发现值得考虑的新方向时区分建议与必需修复；不因审计者更喜欢另一目标就判定原报告失败。

分别检查论证关系、执行前置与版本依赖。图和日志只保存可审阅对象、证据与理由摘要，不要求私有推理链。

## 交付

按 [审计判断与反证](references/audit-judgment.md) 先区分已证实缺陷、证据缺口与可选建议，再记录位置/版本、观察、影响、依据及可执行建议。对实际依赖的引文核准来源文件/版本与消息或段落定位；严重程度不能代替处置类别。当前缺陷数不混入可选建议或撤回意见；缺证不直接等于造假，建议修复不等于已经修复。

收到新证据或更正后，同步更新当前结论、问题清单和检查的 `method/scope/status`，将旧判断及撤回理由单列为历史；不能只在末尾追加更正而保留互相矛盾的当前摘要。撤回错误指控不自动证明原主张通过。

已知未解决 P0 → `blocked`；无 P0 但本次必要检查无法完成 → `not_assessable`；已评估但结论可用性仍依赖明确的修复、限定或前置条件 → `conditional`；无上述情形且本次必要检查完成、无未解决 P0/P1 → `pass`。可选建议、P2 标签或范围外历史缺件不单独构成附加条件；轻微真实错误仍须列明，按实际使用影响判断是否限制通过。同时披露范围、阻断和未知，不能缩小必要范围来取得通过。

有文件能力时，按 [审计 Run 操作](references/audit-run.md) 建立自己的记录；交付前对**审计自己的 Run 目录**运行 `audit_run.py check`，报告该目录、Run ID 和实际结果，不能以被审生成目录的校验代替。失败时修正自身记录并重检，保留真实的失败/未评估项；无 Python 执行能力时按随包模板人工核对，披露自动自检未运行。工作完成、审计内容结论和结构 `valid=true` 分别报告；结构通过不证明事实、论证或视觉通过。没有真实渲染时，布局保持未验证；没有独立计算时不声称已独立复算。
