# PM-01 活动、交付、验收与偏差

版本：0.1.1。核对：2026-10-26。可选项目管理卡，仅在许可覆盖本卡时读取。

## 何时用、需要什么

用于进度、里程碑、交付或验收主张。输入以实际材料为准：约定范围与基线版本、截至日期、完成记录、验收条件及结果。纯文字修订或没有项目状态问题时不用。没有基线时可报告现状，不能编造偏差。

## 执行动作

1. 找出读者本次需要判断的交付事项，将“做过的活动”“已有产物”“经何种检查”“由谁按何条件接受”分别对应到记录。不要凭最后一个任务完成推得全部交付已验收。
2. 对影响判断的事项比较约定与现状：范围、质量或时间的哪个部分改变，出处和日期是什么；区分实际结果、当前预测及预测前提。原基线和后续批准变更分别保留。
3. 遇到笼统百分比，追问其计算对象与规则；无法复现时改成可核对的完成项和未完项。只调查会影响此次判断的缺口。
4. 对需要关注的偏差说明后果、可选处理及接收者能做的事。没有决策请求时保留同步目标，不制造审批动作。

## 交付与独立审计

交付带来源的状态判断、尚未满足的验收条件、关键偏差及必要请求。它们可形成 Finding、Obligation 和 Blueprint 内容单元，不必建立完整项目台账。

审计从原记录反查“完成/验收/按期”的范围和基线：是否把测试通过当业务接受，是否用活动量代表进度，是否漏报影响交付的未完项。不能因生成者已有 pass 而通过。

停止于能诚实描述当前状态；验收记录缺失时保留未确认，不把缺证写成失败，也不凭本卡替组织签署验收。
