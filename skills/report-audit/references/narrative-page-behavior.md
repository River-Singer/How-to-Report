# 叙事、逐页内容与表达的可观察检查

创建路线、制作页面或修改已有产物时，按实际触发条件执行下列动作。沿用已有 Blueprint、页面计划、来源和检查记录；不为编号另造一套流水线，不要求每页填满所有项目。先完成动作和必要修复，再记录结果。核心方法自足，不需要联网或读取可选 Knowledge。

记录只保留检查ID、对象/版本、实际依据、缺陷影响、修复层次与重查结果，不记录私有推理链。Markdown行为记录可写 pass、fail、blocked、not_assessable、not_applicable；不适用须说明原因，未评估不能当通过。写入Run时仍遵循原Check状态 `not_run|pass|fail|not_assessable`；blocked是工作阻断，不是新增Check枚举，不适用留在范围说明中，不伪装pass。偏好与事实/可读性约束分别判断。

## 先检查整条路线

- **N01 结果与内容双向追踪。** 创建或实质重构路线时，从已确认结果逐项找必答问题及承担模块，再从主线模块反查其职责。正式要求、必要背景与用户明确的个人表达诉求可以各有职责，不能互换。证据留在Blueprint的目标—问题—模块对应与缺口中。缺必答或出现无依据的新结论时，修路线或补证；过渡语不能补论证，核心目标变更仍由用户决定。
- **N02 比较有实质差别的路线。** 只有存在会改变主张、主次或结尾的合理分歧时，比较少量路线的起点、关键疑问、结束状态、证据负担和取舍，留下简短对照。换SCQA/STAR名称或章节措辞不算区别；目标清楚的短任务可不比较。若候选只是同一目录，合并它们或回到真实分歧，不按数量凑方案。
- **N03 串读判断并反查结尾。** 路线形成或重大改版后，只读核心判断序列；对突兀转接说清上一段解决什么、下一段为何必要，再从最终结论/请求反查支持。保留必要转接与来源定位。封面、导航和演示操作不强制结论标题。若发现缺背景、缺证据或缺目标相关性，回到对应层修复；“接下来”或时间先后不建立因果。

## 页面任务与内容先于空间

- **P01 定义页面任务。** 新建内容页或改变职责时，先写本页问题、期望理解/判断、必要前置与支持内容，再决定共同观察、逐步展开或拆页；一两句即可。若只有“做甘特图/六张卡”的布局答案，回到问题与关系，重定义、合并或拆分，不先优化页数。
- **P02 补齐细节并保持强度。** 填正文、注释、讲稿或Backup时，区分事实、解释、推断、计划、限制与行动，给关键主张最小支持来源和未满足的证据请求。比较标题、正文、讲稿的确定程度；必要限制须在判断发生处可见。空泛状态、缺范围或“有望”变“显著”须补可核验内容或降格；独立阅读版另查上下文自足。
- **P03 记录重要内容去向。** 删减、合并、移入备份或重构旧稿时，检查重要内容进入主线、必要备注、Backup、待证实或经说明删除，保存蓝图差异/处置说明。共享事实用引用复用，不包装成多项独立证明。排版丢限制、漏必讲或一处更新多处过时，须恢复、清理重复并检查实际受影响处。

## 先证明表达有用，再选择实现

- **V01 比较表达的理解价值。** 选主要视觉时，先明确读者是查值、比较、看变化/构成、追踪流程、理解层级还是核实操作；判断文字/表格是否已足够，图形新增什么。留一句理由和内容/数据引用；复杂或高风险页才有必要比较两种表达。因空白加图、见“体系”画金字塔或用无关系卡片替代真实结构时换表达。装饰可支持风格，但不充当证据。
- **V02 核对定量编码适配。** 有数据图时，核对对象、指标、单位、期间、基线、聚合、缺失与结论，精确数值来自可追溯结果，由程序映射坐标。两点可展示两期变化，不能自动证明持续趋势；重叠集合不作互斥份额；分解保留负项/交互/未解释且不自动等于因果；计划/实际/预测日期分开；长度编码检查基线。用实际数据/公式/图表规格留证。证据不足时请求数据、改图或缩小结论，不能补观测，也不能因此禁止合法定性图。
- **S01 区分SVG技术与内容答案。** 生成/导入SVG或调用SVG渲染器前，先判定数据图、关系图、实物证据或装饰。正文/表格通常保留HTML；关系图先核节点/边含义，数值图按真实数据编程生成，截图/视频不以绘图伪造。核箭头、循环、宽度和收窄的含义，示意与已实现状态分开。实际看viewBox、比例、标记/连线/阴影/文字裁切及可访问文本；比例属性正确不证明完整可读。不可信SVG不直接注入脚本/外链。错误回到关系模型或渲染修复，不以美化遮掩。
- **M01 核对多视图共同意义。** 同页多图/拓扑时，为每视图绑定子问题和所支持的判断，核跨图对象、期间、单位、基线、筛选、聚合和数据状态是否一致或明确不同。证据是视图对应及数据上下文；单图都真不证明联合结论。口径错配、重复无增量或暗示未证因果时，统一口径、显式区分、拆页或删无用组件。

## 用真实内容与真实状态检查成品

- **L01 先验容量再精修。** 固定画布先放真实标题、最长标签、必要来源/限制，预留页眉页脚控制区，按内容责任分配空间，面积不直接等于重要性。保存粗排/真实渲染、尺寸及可读性判断。占位短字、仅容器无溢出或CSS属性不能证明通过。失败依次考虑重分空间、去无用装饰/重复、更合适表达或标签、分步/分层、拆页；不删限制、不无限缩字、不破坏必要同屏比较。
- **L02 逐页逐支持状态实测。** HTML实现/修复后实际激活每页，等字体与图表/媒体就绪再测量截图；检查DOM边界、滚动、裁切和SVG/Canvas内部标签。隐藏页进入或容器变化后检查有效尺寸和调整结果。覆盖实际画布/窗口、最长标签/正文/脚注；只有声明支持的语言、展开、全屏、筛选、打印等状态才纳入。保存实际浏览器/窗口/指纹/截图与原始输出；没有浏览器标未验证。截图稳定不证明首版正确，不能只查第一页。
- **A01 同时查过度表达与表达不足。** 初稿/修复后看首要视觉是否服务预期注意力；试去掉组件，说明损失什么；检查比较、依赖、层级是否被过度简化到让读者自行拼接。用截图、组件职责和具体问题留证。装饰抢证据、同权卡片、随机换图或结构缺失时重新强调、分组、对齐/表达关系；审美分歧可交用户选择，不用图形数量/面积配额或模拟“第一眼”冒充人类实验。

## 独立反读与范围内修复

- **A02 先看成品，再对照。** 重要/高风险页与交付审计先仅看实际页面，记录核心含义、关系和确定程度，再看计划/原资料/证据；披露已暴露的上下文。分别定位计划不清、图形误导、实际读不清、原结论缺证，返回最早出错层。不能预读答案后声称独立反读，不能由计划齐全推出页面通过。
- **R01 修改沿真实影响回归。** 用户反馈或数据/标题/受众/目标变化时，锁定授权范围与版本，沿真实引用检查计算、图表、标题、单位、结论及必要限制。重大目标变化回查N01–N03；仅间距修复不重启目标发现或增加业务成果。保存实际变更/未改范围、受影响对象及重测结果；新检查绑定新版，保留旧记录，不继承旧通过。

最低要求是关键事实/数值不失真、必要内容不遗漏、假设不升级、关键成品真实可读、没做的检查不冒充通过。工具与字段能约束确定性错误；路线、意义和审美仍需结合材料与实际成品判断。这些方法的存在不是模型行为已改善的证据。

## 具体使用路径

N02出现真实路线分歧时，先交短路线草案再精修；用本次目标、证据负担和代价比较，不用无依据打分。P02/P03的疑问和短长版本分工按[会议表达](meeting-expression.md)实施。L01/A01的主题提炼、复杂与简洁代表页、真实整稿缩略图及反馈归因按[视觉编辑](visual-editing.md)实施。默认一个主标题，关键条件留在判断处；不以删除限制来减少页眉行数。
