# 审计判断与反证

在拟报缺陷、解释争议或审阅替换句时使用。这里处理一项意见是否成立及应如何处置；读取顺序、总体结论门槛和交付更正统一由[审计主工作流](audit-method.md)负责，不另开一条全稿流程。

## 固定实际主张和有效要求

回到实际对象版本与必要上下文，辨明事实、引文、概括、条件推论、职责、计划、建议或未知声明。不要用最不利读法代替原句，也不要先替作者弱化再核验。确有多种合理读法时说明歧义，不能把审计者选择的一种当作已知事实。

要求来自当前用户指令、正式规则及其适用修正。助手建议、未采用的候选目标和审计偏好不自动成为要求。对遗漏，指出缺少哪个回答、它服务的已采用目标或关键判断；不因原稿没有对应句子就无法审查，也不把每个新角度都变成必讲项。

## 对疑似问题定点双向查证

明确的同口径算术或单位错误可简短复算。依赖来源、版本或要求的意见，再按疑点执行以下动作，不要求每句都做长表或重读所有历史：

1. 找支持原主张的材料，也找会改变它的相反证据和限制。引用核准到**文件/版本＋消息或段落**，涉及归属时核对说话者；另一文件的相同消息号不是同一证据。用户确认了意图，不等于证明现实效果。
2. 对“无来源”“违反要求”等意见，检查相关后续纠正与实际约束，不能停在首次搜索命中。关键词零命中只说明搜索结果，不证明语义支持不存在；结论限于实际取得且已查阅的范围。
3. 比较对象、时点、范围、条件和强度。概括不必逐字匹配某一原句；概括新增的完成状态、普遍性、因果、权限或数量保证仍需依据。多个事实分别有出处，也不证明它们能按当前归属与关系合并。
4. 说明差异怎样影响本次理解、决策或交付。只有偏好的措辞变化列作建议；必要依据无法取得则指出具体缺口。缺少反证不补出支持，缺少独立验证也不抹去已取得的当事人陈述。

保留简短、可核对的理由：实际主张/要求、关键支持与反证、差异及影响。无需输出私有推理链或凑问题数。引用错位首先是可追溯性错误，可在已授权材料内找正确定位；不能因此直接判事实为假，也不为找支持扩大读取权限。

## 版本不同是否真的冲突

先辨认产物声称的是某版逐字引文、某时点现状，还是跨材料综合。分别可追溯且兼容的条件可以归纳；但兼容性也须检查，不能只凭未发现冲突就认定可合并。

后续明确撤回早期判断、计划写成实绩、异时或异口径事实混绑、助手提案写成用户确认，均需指出具体差异。仅页面措辞变化不自动撤回所有早期事实；明确事实纠正、条件撤销或要求使用最新原句，则按其范围执行。词语不同既不证明冲突，也不证明同义。数量先辨认计数对象，分类、步骤和页面数不必相等。

## 合成反例：先查含义，再改句子

以下是按需教学，不是每次审计必填的表，也不是对某个项目的描述。

| 情况 | 应检验的区别 |
|---|---|
| 记录只给了联调启动日，正文说联调受阻 | 启动日不能自动成为停滞起日；发现复述新增这个时间，先撤回自己的新增含义，再查真实阻碍与影响 |
| 正文列了外部批准与测试人员安排两项条件，审计归纳成“只待批准” | 先补回审计者在复述中漏掉的条件，不能拿自己的简化指控正文漏讲；条件齐全也不证明足以按期完成 |
| 来源只支持“确认安排后评估剩余工作”，正文写“确认后就能给出可承诺日期” | 原句新增了足够作出承诺的依据。建议回到有据的评估动作；不能加速交付日期、发明兜底责任或只换连接词便算修好 |
| 正文写“只有获得批准，才能开始实施” | 这可以只声明必要条件，不自动保证批准后必然实施。结合上下文核对，不见“才能”就报承诺，也不把整段中的实际承诺先改弱再接受 |
| 当前包没有完整收益记录 | 可说明当前无法量化，不能改写为项目从未记录；反过来，也不能据缺件证明收益已经实现 |
| 一组团队投入与另一组阶段成果分别有出处 | 核对范围和归属后才可合并成某团队在某期限完成的成果；对应关系不明时分别表达，不靠末尾待确认抵消正文混绑 |
| 职责写“负责系统安全”，另一处声称“安全已验证” | 前者可为责任，后者需验证依据。真实协作也不自动支持“每一步／全部环节”的范围扩张 |
| 项目组提出做法可能复用 | 有出处的判断不等于已证明普遍适用；保留归属和有据条件，可以讨论用途，不必删除所有价值分析 |

替换句沿用[材料提炼与含义保真](semantic-structuring.md)的标准；重点核对原本要修的差异是否消失，以及是否引入另一个主体、承诺或范围变化。无需把内部核对清单贴进替换正文。

数值争议用[数字与计算证据](numeric-evidence.md)的实际定义、舍入层级、条件和执行证据；不能用任意替代口径证明原数必错。缺附件用[最小证据交接](evidence-handoff.md)辨认提供范围；需要时可用[计算说明](../assets/review/calculation-note.md)或[证据清单](../assets/review/evidence-inventory.md)，不强制每次另建附件。

## 将观察归入合适的处置

| 查证结果 | 处置 |
|---|---|
| 已证实事实、计算、引用、权限或必要条件错误，或遗漏影响重要判断 | 登记缺陷并说明影响；轻微真实错误不因主结论成立而消失 |
| 必要判断缺少实际依据 | 记录证据缺口和最小补件，不直接断言原主张为假 |
| 正文新增依据未支持的确定性、时段、频率或归属 | 定位过强表达并提出收窄；事实本身未知可以同时成立，不能只列待补件而放过越界 |
| 现有表达有合理支持，只是另有偏好的说法 | 可选建议，不混入缺陷数量 |
| 旧指控被证据否定或不足以支持 | 撤回或收窄该项意见，再判断原主张是否已获支持；不自动改成通过 |

P级表示影响优先级，不代替上述类别。总体结论和当前/历史同步回到[主工作流](audit-method.md)，采用Run时按[审计Run](audit-run.md)维护实际字段；不在本专题另定义通过门槛。
