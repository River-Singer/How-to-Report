# 审计判断与反证

在拟报意见被反驳、价值依据或条件关系不清，或自己的解释和修法加入新断言时使用。选对应部分处理当前意见；“是否讲够、是否重复”看[解释是否足够](#解释是否足够)，条件与承诺混淆看[连续修订示例](#连续修订示例)。读取顺序、总体结论门槛和交付更正由[审计主工作流](audit-method.md)负责，不另开一条全稿流程。

## 固定实际主张和有效要求

回到实际对象版本与必要上下文，辨明事实、引文、概括、条件推论、职责、计划、建议或未知声明。将被质疑的原句连同有效限定读完整，再与自己的转述比较；转述超出正文支持的时序、排他性或确定性先撤回，不用它证明原稿有错。确有多种合理读法时说明歧义，不默认最不利读法，也不替作者弱化实际承诺。

例如来源只记“团队提议先测低压功能，尚待讨论”，稿件写“团队建议先测低压功能，高压功能不纳入本轮”。初审说“没写待讨论，已把建议说成决定”。复核时，“建议”统摄两分句，该指控不成立；即使本次正是范围协调，也不能用事项重要为它保留轻微等级。

先拿掉旧指控，再只看剩下的来源问题：本轮是否仅指先行低压试测？排除高压是否也出自团队？若只做低压试测，后半句可能相容；若本轮包含后续阶段，就可能新增排除。材料未定义边界，当前可交给作者的意见是：

> “已写成决定”的意见撤回；整句仍是建议，再补“待讨论”是可选措辞。另需确认本轮测试边界，以及高压暂不纳入是否也属于团队的提议。

此时当前缺陷清单不再保留那项状态指控；待核项应索取范围和提议依据，补标签不能解决它。不能从没记载推断团队从未提出，也不能把一种相容读法当作已核实关系。若后文声称排除已执行，而执行记录明确本轮也测了高压，再指出这项实际冲突；仅有不同方案或提议并存，不按执行冲突处理。

要求来自当前用户指令、正式规则及其适用修正。助手建议、未采用的候选目标和审计偏好不自动成为要求。对遗漏，指出缺少哪个回答、它服务的已采用目标或关键判断；不因原稿没有对应句子就无法审查，也不把每个新角度都变成必讲项。

## 对疑似问题定点双向查证

明确的同口径算术或单位错误可简短复算。依赖来源、版本或要求的意见，再按疑点执行以下动作，不要求每句都做长表或重读所有历史：

1. 找支持原主张的材料，也找会改变它的相反证据和限制。引用核准到**文件/版本＋消息或段落**，涉及归属时核对说话者；另一文件的相同消息号不是同一证据。用户确认了意图，不等于证明现实效果。
2. 对“无来源”“违反要求”等意见，检查相关后续纠正与实际约束，不能停在首次搜索命中。关键词零命中只说明搜索结果，不证明语义支持不存在；结论限于实际取得且已查阅的范围。
3. 比较对象、时点、范围、条件和强度。概括不必逐字匹配某一原句；概括新增的完成状态、普遍性、因果、权限或数量保证仍需依据。多个事实分别有出处，也不证明它们能按当前归属与关系合并。拆开同一句中的准确事实与无据推断，避免一处错误牵连全部内容：已录入90条、尚余60条，支持当前录入总量90与条目占比60%；若项目还含复核和验收，这些数值不支持“整体完成60%”。应指出总体口径错配，不反过来把准确的90条也指为虚假或称它必然意味着全部录入完成。
4. 说明差异怎样影响本次理解、决策或交付。分清“原文使人得出错误判断”和“另一种写法更易懂”；后者可建议，不假定标题与自己的选择不同就失真。必要依据无法取得则指出具体缺口；缺少反证不补出支持，缺少独立验证也不抹去已取得的当事人陈述。

保留简短、可核对的理由：实际主张/要求、关键支持与反证、差异及影响。无需输出私有推理链或凑问题数。引用错位首先是可追溯性错误，可在已授权材料内找正确定位；不能因此直接判事实为假，也不为找支持扩大读取权限。

## 保留有依据的价值与贡献

以下是合成例：来源记载业务分析师提出按产品配置核对价差，工程师实现对照功能；目前可将配置及报价并列查看，未提供使用效果测量。正文说“可先分清配置差别，再确定值得查的价差；本次由业务侧提出比较规则、技术侧实现对照”。这解释了操作用途及实际分工，没有声称已经降本或保证判断正确。审计不能因缺ROI就把它删成“功能已实现，价值待确认”。若本场是试用选择，这项用途可以成为选择理由，实际可用性与是否减少误查仍按相应证据判断。

同一材料若写“我解决了成本失控，已大幅降本”，则从作用、归属和已实现效果分别查缺口。可改回有据的比较规则和分工；用户希望体现个人价值时，保留他实际提出或推进的工作，而非一律隐藏第一人称。若原稿只有功能名称、听众无法据此作试用选择，反馈应指出缺少的比较关系及其用途，帮助写出来，不要求加“赋能”等词。只补本场需要的内容，不把审计新想出的功能或成果编入替换句。

## 解释是否足够

以下为合成材料。本次给首次填写备料清单的同事说明填写依据：甲、乙批次各到货8件，甲已验收8件，乙已验收3件、另5件待验收；本次规则是按已验收数量填写备料清单。原稿只有：

> **到货和验收分开管理**
>
> 分类统计到货与验收，明确物料状态，加强备料管理。

标题指出了话题，正文仍未告诉读者怎样据此填写。审计应定位这段缺少“哪项数量进入清单”的连接及给定样本，影响是读者无法据稿完成当前任务；不是笼统批“页少、没有厚度”。来源已有所需事实，可建议替换为：

> **到货数量相同，备料清单的数量不同**
>
> 甲、乙各到货8件；甲的8件已验收，乙只有3件已验收，另5件待验收。本次清单按已验收数量填写，因此甲填8件、乙填3件。

替换增加了数量、状态、规则与填写结果之间的关系，没有证明实际已减少错填。若来源未提供验收数量，修法应请求对应记录，不能为了把例子讲完整而补造3件或5件。

这份解释与标题围绕同一差别，却承担不同责任，不应按重复删除。反向看，若标题写成“两批均可按8件备料”，正文的8与3已能指出概要失真，不能靠正文正确就放过标题。若本次仅向熟悉规则的同事同步乙的状态，“乙已验收3件，另5件待验收”可能已经足够，无需照搬教学篇幅。库房流程史、更多状态分类或每句前的粗体概括，只有解决本场具体疑问才有加入理由。

据此区分：来源已有而正文未讲清，补必要连接；必要事实未提供，指出最小补件或收窄结论；内容足够、只是审计者偏好更详细，作为可选建议。反馈指出读者具体不能理解、核查或使用什么，并检查补充后的正文是否实际解决它。不能用“还有更多可讲”证明存在缺陷，也不能以最终推荐未变为由删掉理解它的必要前提。

## 版本不同是否真的冲突

先辨认产物声称的是某版逐字引文、某时点现状，还是跨材料综合。分别可追溯且兼容的条件可以归纳；但兼容性也须检查，不能只凭未发现冲突就认定可合并。

后续明确撤回早期判断、计划写成实绩、异时或异口径事实混绑、助手提案写成用户确认，均需指出具体差异。仅页面措辞变化不自动撤回所有早期事实；明确事实纠正、条件撤销或要求使用最新原句，则按其范围执行。词语不同既不证明冲突，也不证明同义。数量先辨认计数对象，分类、步骤和页面数不必相等。

## 连续修订示例

以下是自造设备上线案例，展示怎样重写一项审计意见，不是项目事实或每次必走步骤。

**材料与原稿。** 记录只有：工程师周五可参与检查；设备异常的处理工期尚未估算；其他上线准备尚未完成；本次未附完整上线计划。原稿写“只要安排工程师检查，就能下周上线”。

**先查充分性。** 原句把安排检查当作足以支持下周上线的条件。人员安排妥当而异常处理仍需更久，是与已知材料相容的情境，足以说明这项保证没有得到支持；它不是设备实际会延期的新事实。反馈应保留人员可用，指出剩余工期尚不支持日期，不能把“其他准备未完成”扩大为“均未做”。

**改成必要条件后，重核关系。** 作者改为“只有安排工程师检查，才可以承诺下周上线”。它把检查安排列为作出这项承诺的必要条件，没有说安排好了便能上线，也没有说已经承诺。将“安排了检查仍不能承诺”作为反例，检验的是充分性，不能推翻这条必要条件。应核适用规则是否要求这项检查，或在相同适用范围内，能否不安排它而仍有正当依据承诺下周上线。若有这种情境，必要性不成立；未找到这种情境也不证明规则成立。缺规则依据时保留这一缺口，不继续指控已作交付保证。“能上线”与“可以承诺上线”是不同结果；对某一日期的条件也不能扩大为对一切承诺的条件。

必要条件句本身不证明日期可及。若本次还需判断下周上线是否可行，再查相应工期与安排；不能仅因这句话提到日期，就认定它作了可行性预测。存在适用规则或有依据的条件估计时按其范围核对，不一律删除条件句或预测。

**从被撤理由改到当前整项意见。** 假设初审错称“新句仍保证下周上线”，影响写“其他准备均未做，属于无计划上线”，又建议“先完成工期估算才能安排检查，计划尚未制定”。复核只撤第一句，把“未制定”换成“尚未确定”，再说其余意见不变，仍保留了三个无据判断：零进展、估算是检查前置、计划未定。它们不会因新替换句没再重复而失效。

当前应替代这一整项问题、影响和修法，例如：

> 我把必要条件误读为交付保证；此前关于零进展、计划未制定及先估算才准检查的判断也没有依据，均撤回。以下作为本项当前意见。
>
> 新句仍需处理的是“必须安排这项检查才可以承诺下周上线”的规则依据。现有记录不能支持这一必要性；据此安排工作，会把未经确认的条件当成项目约束。材料只说其他上线准备未完成、本次未附完整计划，不能据此判断准备均未做或计划尚未确定。
>
> 建议核实确有依据的承诺规则；若只是想提出下一步安排，可改为：“工程师周五可以参加检查。建议协调检查内容和安排，并结合异常处理的工期估算及后续安排，评估是否能在下周上线。”这里提出评估建议，不保证日期，也不规定估算与检查的先后。若本次不需要讨论上线日期，可省去该项建议。

这份当前意见保留了有据事实与必要性依据缺口，没有用撤回清单代替修复。同步当前总结，旧报告只留作历史。若拟给的替换又写“安排工程师后即可检查”，仍需查人员可用是否足以开展指定检查，不能把无据的充分性从上线移到检查。已查清就交当前改法，不继续罗列假想错误。关于局部更正及后续推论的研究边界，可按需查[离线方法札记](method-sources/sources/judgment-led-editing.txt)。

## 其他初读偏差

条件示例不替代当前正文的实际关系。遇到下列疑点时，仍回到原句与[含义保真标准](semantic-structuring.md)：

| 情况 | 当场修正 |
|---|---|
| 记录只给联调启动日，复述却写成受阻起日 | 撤回自己增加的受阻日期，再核真实阻碍及影响 |
| 正文有批准与人员安排两项条件，复述写成“只待批准” | 补回遗漏条件，再判断两项条件是否支持原结论；不指控作者漏写 |
| 正文只列各方职责，复述却写成一次性串行流程或“模型不能主动调用” | 撤回无据的顺序、频率及否定，再检查职责本身；不要求作者证明审计补出的运行方式 |
| 正文明确甲方确认范围，后文另有测试安排，复述把两项均交给甲方 | 只保留已明确的责任归属；句子相邻不自动共用责任人 |

数值争议用[数字与计算证据](numeric-evidence.md)的实际定义、舍入层级、条件和执行证据；不能用任意替代口径证明原数必错。缺附件用[最小证据交接](evidence-handoff.md)辨认提供范围；需要时可用[计算说明](../assets/review/calculation-note.md)或[证据清单](../assets/review/evidence-inventory.md)，不强制每次另建附件。

## 将观察归入合适的处置

| 查证结果 | 处置 |
|---|---|
| 已证实事实、计算、引用、权限或必要条件错误，或遗漏影响重要判断 | 登记缺陷并说明影响；轻微真实错误不因主结论成立而消失 |
| 必要判断缺少实际依据 | 记录证据缺口和最小补件，不直接断言原主张为假 |
| 正文新增依据未支持的确定性、时段、频率或归属 | 定位过强表达并提出收窄；事实本身未知可以同时成立，不能只列待补件而放过越界 |
| 现有表达有合理支持，只是另有偏好的说法 | 可选建议，不混入缺陷数量 |
| 旧指控被证据否定或不足以支持 | 明确撤回或收窄，余下内容按上面各类重新判定；范围未知、可选补词与确定冲突不能沿用同一缺陷身份和数量。再核原主张是否获支持，不自动改成通过 |

同一口径错误造成数字、标题和结尾同时过强时，可合并为一项并列出受影响位置；若另有独立错误仍分别保留，不以合并掩盖它。P级表示影响优先级，不代替处置类别。总体结论和当前/历史同步回到[主工作流](audit-method.md)，采用Run时按[审计Run](audit-run.md)维护实际字段；不在本专题另定义通过门槛。
