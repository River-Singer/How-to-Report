# 审计判断与反证

在把观察列为缺陷或复核旧意见时使用。目标是给出与证据强度相称、会影响本次判断的结论；不追求固定问题数，也不因避免误报而取消真实错误、重要遗漏或证据缺口。

## 先固定被审主张

回到实际产物的对象版本和段落，读足以确定含义的上下文，用一句话说明它让读者相信什么；涉及请求时再说明请谁做什么。区分事实、引文、概括、条件推论、职责、计划、建议和未知声明，不能选最不利读法替代原句。原稿明确是建议或尚未验证时，不指控为实施事实；若仍有越界，定位增加的那层含义。源句本身有多种合理读法时，保留歧义，不把审计者选中的一种解释当已知事实。

核对适用要求的来源与有效范围：当前用户要求、正式规则及后续明确修正优先；旧要求未被更改的部分仍有效。助手建议、审计者偏好和未采用的候选目标不自动成为要求。检查权责时，区分“调查后由某人确认”与“某人无需证据即可决定事实”。

对重要遗漏，定位缺少回答的问题及它服务的已采用目标、正式要求或关键判断；不因原稿没有对应句子就放弃审查。潜在新方向可以建议，不能全部变成必讲内容。

## 对拟提出的问题做双向查证

检查深度随争议而定。明确的同口径算术或单位矛盾可直接定位并给出简短复算；“无依据”“违反要求”“版本冲突”等依赖上下文的判断，才需要定点补查相关材料。不为明显问题制造长表或完整历史检索。

1. 找支持原主张的证据，也找与它冲突或限定它的证据。对实际依赖的引用回到**该文件/版本 + 消息或段落**核准内容，涉及归属时核对说话者；另一文件的相同消息号不是同一证据，行号只能辅助定位。区分用户明确陈述、助手推测与实际观测；用户确认某意图不等于证明现实效果。
2. 对“无来源”“不符合要求”或版本争议，核对相关材料中的后续用户纠正和当前约束，不能停在第一次命中。精确关键词用于定位；零命中不证明语义依据不存在。以实际查阅范围说明结论，不声称穷尽未取得的历史。
3. 比较证据实际支持的对象、时点、范围、条件和强度。合理概括无需与某一处原文逐字相同；若概括增加了已完成状态、普遍性、因果、权限或数量保证，增加的部分仍需依据。
4. 说明为什么这个差异会改变本次读者的理解、决策或正式交付。若只是更喜欢另一种措辞，列为可选建议；若无法判定而该项确有必要，留下可定位的证据缺口及最小补件需求。

记录简短的可审阅理由即可：**实际主张与要求 → 支持/相反证据 → 差异与影响 → 当前判断**。没有反证不等于已有支持；项目代表身份也不补出其尚未提供的事实。反过来，缺少独立验证不抹去已经取得的当事人陈述。无需每句建图、输出私有推理链或填固定数量条目。

发现引用错位时，在已授权材料内寻找正确定位；这首先是可追溯性错误，不自动证明主张为假。找不到而该依据确属必要时，保留对应缺口；不要求为每句重读全库、计算哈希或扩展读取权限。

## 判断版本与语义是否真的冲突

跨材料或跨版本综合不是天然缺陷。先判断产物是否自称某个版本的逐字引文、某时点的现状，还是对多处材料的归纳；再查来源间是否存在会改变结论的冲突。可分别追溯且兼容的条件可以综合，不必要求它们在单条消息中共同出现。

若后续材料撤回早期判断、计划被改写为已实现、不同口径或时点的事实被当作同时成立，或把助手提案归为用户确认，应指出具体冲突。页面用词更新本身不代表所有早期判断被撤回；但用户明确纠正事实、撤销条件或要求沿用最新原句时，须按其范围执行。仅有词语变化不能证明冲突，也不能证明同义；依据上下文检验其含义。核对数量时先识别计数对象，不能默认分类数量等于图层、步骤或页面数量。

例如两版分别说明规则固定、来源可追踪，可兼容地概括两项条件；后版明确撤回规则固定，则不能仍称当前已固定。兼容性需要材料支持，不能因为没查到冲突就默认可合并。

## 用实际含义区分相近说法

以下为合成教学对照，按遇到的疑点使用，不逐项套表，也不靠出现某个词判定。

- **条件与承诺：**“两项安排确认后核实剩余工作、更新排期”给出下一步；“两项确认后就能给出可承诺日期”还声称条件足够。若剩余工作未评估，后句即使没用“保证”也越界。通知备用方案与请听众当场批准启动，也不能仅按事项数量判断一致。
- **资料与历史：**“当前材料不足以量化收益”说明取得范围；“项目从未记录收益”新增历史事实。缺资料不是发生过的证据，也不是从未发生的证据。可以修正这项断言，同时保留真正的数据缺口。
- **分别成立与合并成立：**两个月的小队投入、一个季度的模块成果各有来源，仍不能未经核对写成“小队两个月完成这些模块”。分别表达即可立即去除过强归属，未知对应关系再补查，不靠文末待确认抵消正文混绑。
- **职责与效果：**“后端负责架构合理和系统安全”在职责段可以是工作责任；“系统安全已获验证”需要验证依据。双向协作关系也不证明“从启动起每一步都如此”；去掉无依据的频率即可，不另编“关键节点”或追加整段安全警句。
- **有出处与普遍成立：**“项目组认为这种做法可复制”有明确判断来源；它不等于已证明跨团队通用。核对归属、理由和适用范围，不把项目方判断说成无来源，也不删掉所有价值讨论。

数值争议按 [数字与计算证据](numeric-evidence.md) 绑定实际定义、条件及执行证据，不用任意替代口径证明原数必错。缺附件或历史材料时按 [最小证据交接](evidence-handoff.md) 判断：本包未提供不等于原工作区未保存，也不等于主张已被证实。可用 [计算说明](../assets/review/calculation-note.md) 和 [证据清单](../assets/review/evidence-inventory.md) 记录必要补件；无需为简单审计填满全部模板。

## 给出与证据一致的处置

| 查证结果 | 当前处理 |
|---|---|
| 有具体证据说明事实、计算、归属、引用定位、权限或必要条件错误，或遗漏影响重要判断 | 登记缺陷，按影响定级；轻微真实错误仍保留，不能仅因主结论成立而抹去 |
| 实际依据不足，必要判断无法完成 | 登记证据缺口；对应检查用 `not_assessable`，不直接断言原主张必假，也不代替核对正文是否已越界 |
| 正文增加了依据未支持的确定性、时段、频率或归属 | 登记可定位的过强表达，建议收窄；事实本身未知另记边界，不能只等补件或以无反证改作可选建议 |
| 当前表达有合理支持，另有更清晰或更精确的表达 | 作为可选建议，不计作必须修复的错误 |
| 旧指控被证据否定或证据不足以支持该指控 | 撤回或收窄该指控，分别判断原主张是否已有足够证据；不自动改成 `pass` |

交付前检查拟列缺陷是否能指明具体错误、违反的有效要求或影响，而不只是“还可以更清楚”。缺陷、必要证据缺口与可选建议分别列出和计数，P 级仅表示优先级，不替代处置类别；无需新增机器字段。

按入口的结论门槛处理：仅有可选建议不能使 `pass` 变成 `conditional`；后者须说明影响本次结论使用的具体剩余条件。范围外历史缺件不自动成为该条件，范围内必要检查也不能被悄悄排除。真实 P2 错误可保留待修而不阻断通过，取决于实际使用影响。不要为产生“更严格”的审计强留问题，也不要为提高通过率隐藏证据不足。

## 更正时保留可读的当前状态

当前摘要、有效问题及数量、总体结论、Run 说明和检查记录应描述同一次最新审查。补充证据改变方法或范围时，同步更新标准 `method/scope/status` 与实际详情引用；保持目标的精确版本，审查新版时按契约登记相应版本。工作完成状态、检查状态、总体内容结论分别说明。

将原判断、当时证据边界、补充证据的取得阶段、撤回/降级/维持理由及定位另列为**历史判断与更正**，不冒充首次审计已经知道的新证据。不得仅靠自定义追加字段或文末勘误覆盖仍在生效的旧标准字段。历史可保存在同一文件的明确章节，不强制新建机器字段。

最后按 [审计 Run 操作](audit-run.md) 对最新记录自检。结构校验只检查记录结构及引用等可机器判断的事项，不能替代这里的语义裁决。
