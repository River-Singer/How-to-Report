# 独立审计方法

从实际内容和当前任务入手，分别判断说得是否成立、是否回答了本次问题。不靠作者自评、清单齐全或固定问题数取得通过。数据格式按需查[工作区契约](workspace-contract.md)，复杂关系查[多图模型](graph-model.md)，普通内容无需先补图或记录。

## 重建而非接受自评

先借目录、标题或边界定位正式正文，只读取听众实际会接收的区域。文件开头若是作者取舍、边界声明或自评，先跳过，不能把通读整份方案当成正文先读。简述正文让人理解或相信什么、关键关系与条件；有请求时才说明请谁做什么。无需逐句重抄或保存私有推理过程。

随后开放原要求、源资料与作者说明，对照刚才读出的意思。作者说“已保留条件”，但结尾仍让人相信“安排确认就能按期完成”，应查结尾的推论。作者说明也可能澄清合理读法，不能为了维持初判忽略它；正文需要的解释仍不能仅靠作者笔记代偿。已接触这些材料或无法分离时如实披露，不宣称盲读，无需新文件或Agent。

独立访问可用原资料与实际计算凭证。生成侧摘要可作为线索，但其省略、引用和 `verified` 标签仍需检查。外来报告缺少原资料时，仍可检查内部矛盾、夸大措辞、遗漏限制和引用可定位性，同时保留证据不可评估项。附件与历史的范围按 [最小证据交接](evidence-handoff.md) 识别，不把本包缺失反推成原工作区没有。

## 核对实际目标与内容责任

按 [叙事与内容检查](narrative-page-behavior.md) 独立核对目标与内容双向覆盖、路线实质差异、标题串读与结尾支持、理解任务、细节强度与内容去向。检查真实产物和来源，不因生成者填满编号就通过；没有生成笔记仍可审查成品，不能凭缺表制造缺陷。

从原请求、正式要求和已取得的情境材料重建当前目标、受众权责及关键未知，再对照产物实际要求读者理解、相信或采取什么行动。按需用 [目标发现准则](goal-discovery.md) 检查来源与可达性，但不替用户选择新目标。

定位主线是否被偷换、正式必答是否消失、个人诉求是否只有推测、角色是否被赋予不存在的权力。AI与用户已谈明白的内容不等于听众已知。分别判断“用户选了目标”“事实前提成立”“正文已交付”“听众真的改变判断”，不能互相代证。

检查目标是否进入实际内容：必要判断、证据、限制和结构是否匹配；新目标是否只换了标题。若仅缺生成侧 Blueprint，直接从外来产物和原要求完成这一检查，不拒绝审计，也不强制生成一套图。

候选结果是否真正改变证据、结构或结尾，可从产物与公开决定核对，不能只看数量。检查诱导提问、按职位猜动机和继续优化被否认的诉求；新证据通常先改变主张、条件或办法，不自动重选目标。输入已明示的歧义，只证明响应过该提示，不能作为主动发现潜在目标的证据。

有依据的新沟通机会可以建议，只有影响已采用目标、正式要求或读者关键判断时才构成必修遗漏。信息同步和客观复盘可以完成于理解与判断，不强制资源争取、行动请求或能力展示。

## 分别判断准确与有用

准确性核对事实、范围与推论；有用性核对本次关键问题是否获得回答。正文没有假话，却只列“待确认”，仍可能没有完成判断；正文流畅有建议，却把必要条件写成完成保证，仍须修正。指出少了哪个回答或重要区别及其影响，不用“不够深入”代替判断。

缺收益数据不等于不能解释用途，只有一个实践也不妨碍分析已知条件与迁移假设；合理用途不证明收益，条件分析也不证明普遍可复制。禁止编推广门槛，不是禁止分析适用条件。审查是否形成有依据的有限判断、取舍或下一项有价值的核对，不强制自造人数、周期和阈值。

## 挑战解释结构

从原资料里的异常、矛盾、范围和关系寻找可能被遗漏的解释，而非只逐项赞同生成者候选表。需要时用 [解释探索准则](insight-discovery.md)：

去掉标题后，候选是否仍回答不同问题？相关指标可以提供不同信息，反命题则可能是同一问题的竞争答案。新颖方向若不改变本次理解或选择，不算洞察；假设情境用于检验区别，不是项目证据。竞争解释需要能区分它们的观察，材料不足时不强选顺畅故事。

回看抽象、类比与跨路径综合所用的定义、时点、条件和交互：局部判断各自成立，不保证能够直接拼接；源场景的关系也未必适用于新场景。反查候选进入正文时是否被写成成果、预算停止是否被写成穷尽。缺事实时指出所需材料，不继续堆候选。

只提出能影响本次判断的挑战与最有价值的下一项证据，不用额外观点数量评价洞察。审计可以建立自己的局部候选和义务，不能覆盖生成侧图或把新建议冒充原用户要求。

## 查事实、推理与遗漏

重组过的复杂材料按[语义组织](semantic-structuring.md)反向还原角色、状态、数量、关系与条件。叙事先后不等于工作串行，多个前置不等于充分依据，明确声称不等于已独立证实。影响不能随意加强为前置，无因果支持也不自动支持相关。缺少桥梁时可保留独立事实，不靠顺畅转接补依据。

- 数值：按 [数字与计算证据](numeric-evidence.md) 核对原定义与可复现方法、舍入层级和条件；区分实际执行、同脚本复跑与独立路径核验。未取得原方法不等于替代口径证明原值错误。
- 推理：材料最多支持哪种强度；说明是否被当作证据，相关或顺序是否被升级为因果；主张是否遗漏条件与竞争解释。
- 增量：多项支持是否同源重复；是否遗漏有依据的重要价值、必答问题、反证或风险；审计不只找说错的内容。
- 多图：候选被选中是否偷偷成为事实；任务完成是否被当作知识通过；内容或页面是否脱离其依据；计划缺少哪些实际工作。
- 版本与定位：检查与结论绑定的对象版本是否仍是实际交付版本；实际引用的来源文件/版本与消息或段落是否配对正确，必要时核对说话者。修订须保留限制且只影响应改部分。
- 表达与身份：按[观众成稿编辑](audience-copy.md)核对实际句意与发言人，简化是否丢掉具体分工、双向关系或必要条件。局部改一句话时，附在正文外的长解释和无用选择题仍增加负担。少了重复预测声明、内部编号不构成缺陷，必要限定仍需由正文表达。

不以固定框架字段齐全、问题数量、图节点数或总分代替有效判断。明确指出哪条关系或主张有问题，并提供可区分解释的下一项证据。

## 问题与结论

定为缺陷前，按 [审计判断与反证](audit-judgment.md) 核对实际主张的性质、适用要求、支持与相反证据及实质影响；相关后续纠正、合理概括和跨版本综合都须按语义判断。维持对真实冲突、过强表达和重要遗漏的检查，不用逐字匹配或问题数量代替裁决。

先确定处置类别，再决定优先级。缺陷记录包含 issue ID、对象/版本/定位、观察、影响、依据和修复建议：P0 是会使关键事实、权限或发布判断失真的阻断，P1 是需要修复或明确限定的重要缺陷，P2 可用于不改变关键判断的轻微真实错误。小算术错误、引用错位仍是错误，不因影响小就改称偏好。

可选建议不计入缺陷数，也不单凭建议限制通过。证据缺口说明影响的必要判断与最小补件，范围外未评估项仅说明边界；无用空分组可省略。事实关系尚待核对与正文已过强可以同时成立：先建议拆开未经支持的合并表述，无需等补件后才能修。不可评估是检查状态，不把它降成轻微问题。

结论依入口门槛给出，分别说明准确性与任务完成情况、实际范围、来源、执行工具、独立性及未评估项。可读性通过不代替事实核对，每句有出处也不证明重要问题已回答。只查到资料不足不凭空判假，缺依据的确定性也不能因“无反证”而通过。

审计和修订分开：没有修复授权时保留原文件，写自己的报告；有明确范围时修复对应产物，并对新版重新检查受影响内容。检查旧版通过不自动传递给新版。

被审 Run 含 `version_state` 时，按 [工作区契约](workspace-contract.md) 核对选版历史、精确目标检查及材料变化。生成侧接纳标签不是独立审计结论，基础结构校验也不验证此扩展；未提供生成工具时直接核对实际记录和来源。审计不得替原 Run 选择或接纳版本。

采用Run时将实际检查写入自己的记录；更正时同步更新当前结论、方法、范围和状态，把旧判断及更正依据单列为历史，再按 [审计 Run 操作](audit-run.md) 校验该审计目录。被审稿的结构检查、审计记录自身的结构检查和内容判断分别留证；自检失败只修自身记录，不改被审原件，也不删除内容 `fail` 来取得结构通过。

按[思维方法](reasoning-methods.md)核对实际概念差异与证据桥梁，不以方法名齐全证明执行。按[会议表达](meeting-expression.md)核对疑问去向、短长版事实与强度、备查定位；需要请求时区分告知、征询和请其决定是否一致。模型复述不是听众试读，短稿不能丢决定性条件，长稿不应只多出重复说明。

使用[私有经验](report-experience.md)时检查确认、来源版本、适用与不适用条件及观察状态；检索命中不证明适用，一次成功不成为通用规则。审计只写自己的记录，不自动修改被审者画像/经验。
