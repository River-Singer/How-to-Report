# 独立审计方法

从本次任务真正需要的检查入手，避免形式化地检查所有维度。数据格式见 [工作区契约](workspace-contract.md)，不同关系的含义见 [多图模型](graph-model.md)。

## 重建而非接受自评

先记录实际产物传达的关键判断、比较、因果、范围与行动建议。若要做视觉语义往返，先看实际页面再看计划；已接触计划时如实说明。源码阅读不能代替看见页面。HTML及页面检查按 [实际页面审计](page-audit.md) 留下先反读、后对照及真实浏览器证据。

独立访问可用原资料与实际计算凭证。生成侧摘要可作为线索，但其省略、引用和 `verified` 标签仍需检查。外来报告缺少原资料时，仍可检查内部矛盾、夸大措辞、遗漏限制和引用可定位性，同时保留证据不可评估项。附件与历史的范围按 [最小证据交接](evidence-handoff.md) 识别，不把本包缺失反推成原工作区没有。

## 核对实际目标与内容责任

按 [叙事与页面行为](narrative-page-behavior.md) 的N01–N03/P01–P03独立核对目标—问题—模块双向覆盖、路线实质差异、标题串读/结尾支持、页面任务、细节强度与内容去向。检查真实产物和来源，不因生成者填满编号就通过；没有生成笔记仍可审查成品，不能凭缺表制造缺陷。

从原请求、正式要求和已取得的情境材料重建当前目标、受众权责及关键未知，再对照产物实际要求读者理解、相信或采取什么行动。按需用 [目标发现准则](goal-discovery.md) 检查来源与可达性，但不替用户选择新目标。

定位主线是否被偷换、正式必答是否消失、个人诉求是否只有推测、材料中的角色是否被赋予不存在的权力。分别判断“用户选了目标”“其事实前提成立”“报告已交付”“听众实际发生变化”；任何一个都不能替另一个提供通过证据。

检查目标是否进入 Blueprint 和实际内容：必要判断、证据、限制和结构是否匹配；新目标是否只换了标题。若仅缺生成侧 Blueprint，直接从外来产物和原要求完成这一检查，不拒绝审计，也不强制生成一套图。

大纲前的候选结果是否真正改变证据、结构或结尾，也可从当前产物与公开决定核对；不能只看是否列满候选数。检查是否以诱导问题、人物职位或项目拟人化替用户设定目标，是否在用户否认诉求后仍暗中优化。已明确客观复盘时不要求追加资源争取或能力展示。

有依据的新沟通机会可以作为建议。只有它影响已采用目标、正式要求或读者关键判断时，其遗漏才构成相应缺陷；不把所有可能目标都列为必讲，不把合法的信息同步强改成说服或财务收益汇报。

## 挑战解释结构

从原资料里的异常、矛盾、范围和关系寻找可能被遗漏的解释，而非只逐项赞同生成者候选表。需要时用 [解释探索准则](insight-discovery.md)：

- 去掉标题比较完整判断，识别换词重复与被误合并的机制；删除测试不能删掉必要反证。
- 为有实质竞争的解释指出区分观察；证据尚不能区分时标明未知，不强选更顺畅的故事。
- 核对抽象是否丢掉关键条件，类比是否只复制表面属性，源场景关系是否在目标场景仍成立。
- 对跨路径综合回看相关原证据，核对定义、时点和交互；局部结论各自成立不保证可以直接相加或拼接。
- 新方向应对应独立问题、可区分观察与可能改变的判断/行动；若用两个旧表示相同的假设情境说明差异，核对它们符合约束且明确是假设。反命题是同问题的竞争答案，相关指标不因此同义；新颖但无任务关系不能充数。
- 反查解释进入内容时是否丢失限定，是否从未经检验的候选直接跳到页面成果。若因预算停止，是否保留未解决/未探索范围，而非宣称穷尽。

只提出能影响本次判断的挑战与最有价值的下一项证据，不用额外观点数量评价洞察。审计可以建立自己的局部候选和义务，不能覆盖生成侧图或把新建议冒充原用户要求。

## 查事实、推理与遗漏

- 数值：按 [数字与计算证据](numeric-evidence.md) 核对原定义与可复现方法、舍入层级和条件；区分实际执行、同脚本复跑与独立路径核验。未取得原方法不等于替代口径证明原值错误。
- 推理：材料最多支持哪种强度；说明是否被当作证据，相关或顺序是否被升级为因果；主张是否遗漏条件与竞争解释。
- 增量：多项支持是否同源重复；是否遗漏有依据的重要价值、必答问题、反证或风险；审计不只找说错的内容。
- 多图：候选被选中是否偷偷成为事实；任务完成是否被当作知识通过；内容或页面是否脱离其依据；计划缺少哪些实际工作。
- 版本与定位：检查与结论绑定的对象版本是否仍是实际交付版本；实际引用的来源文件/版本与消息或段落是否配对正确，必要时核对说话者。修订须保留限制且只影响应改部分。
- 表达：文字、箭头、分组、尺度、颜色或同屏布局是否暗示未被支持的关系；缺失值是否被画成真实零，标签是否仍可区分。

不以固定框架字段齐全、问题数量、图节点数或总分代替有效判断。明确指出哪条关系或主张有问题，并提供可区分解释的下一项证据。

## 问题与结论

定为缺陷前，按 [审计判断与反证](audit-judgment.md) 核对实际主张的性质、适用要求、支持与相反证据及实质影响；相关后续纠正、合理概括和跨版本综合都须按语义判断。维持对真实冲突、过强表达和重要遗漏的检查，不用逐字匹配或问题数量代替裁决。

先确定处置类别，再决定优先级。缺陷记录包含 issue ID、对象/版本/定位、观察、影响、依据和修复建议：P0 是会使关键事实、权限或发布判断失真的阻断，P1 是需要修复或明确限定的重要缺陷，P2 可用于不改变关键判断的轻微真实错误。小算术错误、引用错位仍是错误，不因影响小就改称偏好。

可选建议单列，可不标 P 级；沿用 P2 时明确“可选”，不计入当前缺陷数，也不单凭建议限制通过。证据缺口另列其影响的必要判断及最小补件；范围外未评估项仅说明边界，不自动升级为必需补件。没有必要时可省略空分组。不可评估是检查状态，不把它降成轻微问题。

结论依入口中的门槛给出，同时列明审计范围、实际读过的来源、实际执行的工具、独立性、缺陷和未评估项。发现反证可以要求降格主张或重开假设；只查到资料不足则提出义务，不凭空判假。

审计和修订分开：没有修复授权时保留原文件，写自己的报告；有明确范围时修复对应产物，并对新版重新检查受影响内容。检查旧版通过不自动传递给新版。

被审 Run 含 `version_state` 时，按 [工作区契约](workspace-contract.md) 核对选版历史、精确目标检查及材料变化。生成侧接纳标签不是独立审计结论，基础结构校验也不验证此扩展；未提供生成工具时直接核对实际记录和来源。审计不得替原 Run 选择或接纳版本。

将实际检查写入自己的 Run；更正时同步更新当前结论、方法、范围和状态，把旧判断及更正依据单列为历史，再按 [审计 Run 操作](audit-run.md) 校验该审计目录。被审稿的结构检查、审计记录自身的结构检查和内容判断分别留证；自检失败只修自身记录，不改被审原件，也不删除内容 `fail` 来取得结构通过。

## 新方法的镜像核对

按[思维方法](reasoning-methods.md)核对成品实际保留的概念差异、前提、交互和证据桥梁；没有生成检查表不构成缺陷，方法名称齐全不代表发生了检查。价值遗漏和过强主张双向核对：有依据的重要用途不应消失，潜在用途不写成已实现收益。论证编辑须有实质关系变化，不只改形容词。

按[会议表达](meeting-expression.md)核对疑问去向、短长版事实/强度、Backup定位与返回，区分模型候选问题和真实反馈。按[视觉编辑](visual-editing.md)检查真实代表页与整稿，单标题不等于删掉决定条件；无浏览器不得宣称渲染通过。

使用[私有经验](report-experience.md)时检查确认、来源版本、适用与不适用条件及观察状态；检索命中不证明适用，一次成功不成为通用规则。审计只写自己的记录，不自动修改被审者画像/经验。
