# 按判断缺口调用思维方法

先说明哪个具体判断受到什么困难，再选所需方法，不依次遍历四张卡。卡片处理局部概念、前提、条件与推断，不另建生成流程、Agent或必填Graph。

| 困难 | 方法 | 应得到什么 |
|---|---|---|
| 同词异义、状态或分母混淆 | [概念与状态](method-concepts.md) | 足以改变当前判断的明确定义 |
| 方案依赖假设、手段被当目的 | [前提与约束](method-premises.md) | 被支持或待核的前提、可行替代及影响 |
| 局部优化相互制约、条件变化 | [条件与交互](method-conditions.md) | 具体权衡或交互，不能靠折中抹平事实冲突 |
| 事实跃迁到效果、价值或承诺 | [主张与依据](method-argument.md) | 有据判断、限定或有辨别力的补件 |

只保留解决结果和必要依据摘要，不交完整私有推理或四法执行表。没有当前困难就跳过；缺事实时转去取证，不能靠循环自问变出证据。方法结果交回调用者的主工作流，模型自纠不等于独立复算、外部证据或真人反馈。

跨候选的新增区分由[解释探索](insight-discovery.md)处理，来源的归并与改写比较按[含义标准](semantic-structuring.md#含义保真的共同标准)。[离线来源](method-sources/index.md)是背景，不是本项目事实或效果认证。
