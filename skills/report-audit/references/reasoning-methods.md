# 按判断缺口调用思维方法

先说明哪个具体判断受到什么困难，再选所需方法，不依次遍历四张卡。卡片处理局部概念、前提、条件与推断，不另建生成流程、Agent或必填Graph。

| 困难 | 方法 | 应得到什么 |
|---|---|---|
| 同词异义、状态或分母混淆 | [概念与状态](method-concepts.md) | 足以改变当前判断的明确定义 |
| 方案依赖假设、手段被当目的 | [前提与约束](method-premises.md) | 被支持或待核的前提、可行替代及影响 |
| 局部优化相互制约、条件变化 | [条件与交互](method-conditions.md) | 具体权衡或交互，不能靠折中抹平事实冲突 |
| 从事实形成有用判断、贡献或选择，或既有推断跳步 | [主张与依据](method-argument.md) | 价值机制、可归属贡献、选择理由及必要条件 |

只保留解决结果和必要依据摘要，不交完整私有推理或四法执行表。没有当前困难就跳过；缺事实时转去取证，不能靠循环自问变出证据。方法结果交回调用者的主工作流，模型自纠不等于独立复算、外部证据或真人反馈。

跨候选的新增区分由[解释探索](insight-discovery.md)处理，来源的归并与改写比较按[含义标准](semantic-structuring.md#含义保真的共同标准)。[离线来源](method-sources/index.md)是背景，不是本项目事实或效果认证。


领域方法从[Knowledge目录](../knowledge/index.md)按当前要作的判断选择：必要性/替代、费用组成/资金、资源可行性/瓶颈/组合、系统/控制/数据用途，以及市场/产品定位/采用/销售购买/传播效果分别处理。目录中的问题是调用入口，不是每场必查轴或词语题库。先核本卡及相关来源是否已在有效授权内；复用同范围许可，不扩大范围。

要让受众看见本人真实价值、形成专业认可或愿意交付后续责任，直接用核心[主张与依据的正向构思](method-argument.md#正向构思个人价值与可信责任)：相关能力、实际判断/行动、作用与合作归属、受众用途和迁移条件。它不是一张新领域卡或个人营销Agent；用户否认个人展示时不暗中采用。

先查已有资料并执行可行分析，再把真正缺少的最小事实和用途明确交给用户；不要把尚未分析或没有工具掩成缺件。汇报人用方法完成判断并写成内容，挑战者用同一知识形成针对确认目的/职责的纯问句，审计核实际正文与依据。三者职责不相互替代；挑战/审计须遵守[真实委派](agent-delegation.md)，本目录不另建执行流程。方法调用的证据是分析及内容变化，不是命名、读文件或填满表格。
