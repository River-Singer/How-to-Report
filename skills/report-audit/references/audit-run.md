# 审计 Run：创建、记录与自身校验

用于确需持久追溯、续接或机器引用的审计记录。普通内容审查可直接交Markdown结果，不因有文件能力而强制建Run；选择Run后才执行下列初始化与自身校验。完整字段遵循 [Run 契约 0.1](workspace-contract.md)。Run 放在 Skill 安装目录之外的新目录，原报告保持只读。外来报告无需生成侧 Run、语义图或任务图。

## 有 Python 执行能力

使用本包 [审计 Run 工具](../scripts/audit_run.py)，需要 Python 3.10+ 标准库，不需要网络或服务。以下占位路径须替换为实际路径；脚本可从任意当前目录调用：

```text
python "<本Skill目录>/scripts/audit_run.py" init "<新审计目录>" --target "<本地报告文件>" --run-id "<本次审计ID>"
```

`init` 只接受现有本地报告和未存在的输出目录，输出目录的父目录须已存在，不覆盖旧 Run。它从随包模板建立 Run 0.1，记录目标文件的实际路径和 SHA-256；初始 `work_status=in_progress`、内容检查 `not_run`，不声明语义阅读、独立性或审计通过。`--target-id` 默认 `audit-target`，`--target-revision` 默认 `1`，表示本 Run 的登记版本；已知对应版本时显式传入，不从文件名推断业务版本。外部版本说明写入 `version_note`。

输出路径在创建前按 [共享写入边界](workspace-contract.md) 预检：自身及祖先带安装标记的其它 Skill 包、链接/reparse、UNC/设备路径均拒绝；目标报告也不接受 UNC/设备路径。只检查目标祖先和已知安装根，不全盘扫描；原报告始终只读。

按实际审查填写报告和来源，保持 `sources`、`artifacts`、`checks` 为数组。每项检查使用已登记对象的精确 `target` 和受支持的 `status`；详情指向本 Run 内实际文件。尚未执行用 `not_run`，无法评估用 `not_assessable`；只有实际完成且有方法、范围及支持详情时才用 `pass`。上下文继承、读取范围与复算方式由实际工作记录，工具不替你完成这些检查。计算原始输出与整理分析按 [数字与计算证据](numeric-evidence.md) 分开标识，不将整理后的表当作工具原样输出。

完成记录后，校验**当前审计目录**：

```text
python "<本Skill目录>/scripts/audit_run.py" check "<本次审计目录>"
```

`check` 只读复用 [Run 校验器](../scripts/validate_run.py)，并要求 `mode=audit`。输出包含 `audit_directory`、`run_id`、`run_record_sha256`、`valid` 和 `errors`，将结果绑定到本次审计记录。退出码 `0` 表示结构接受，`1` 表示记录无效，`2` 表示调用或读取失败；这些都不是内容审计结论。工具不会自动改记录、完成工作或把检查改成通过。

将实际校验输出作为交付凭据；失败时指出文件/字段和未解决项，只修自身记录后重检。不要改被审原件、放宽契约、伪造哈希或删除内容失败来消除错误。修订 `run.json` 或其引用内容后重新校验；旧结果只适用于当时检查的记录与文件。

## 无 Python 执行能力

在新目录中使用随包 [run.json](../assets/audit-run/run.json)、[run.md](../assets/audit-run/run.md) 和 [audit.md](../assets/audit-run/audit.md) 三份模板，依实际资料替换 Run ID、目标路径、ID/版本和说明。没有文件写入能力时交付可复制内容，并声明未持久保存。模板仅为起点，不能作为已审计的结果。

按 [工作区契约](workspace-contract.md) 人工核对必需数组、精确引用、受支持状态和真实详情文件。未计算哈希就省略 `content_hash`，不要填占位字符串；章节写入 `locator` 或正文，不拼进文件名。保留未执行/不可评估项，并明确“自动结构自检未运行”；无需为此联网或安装服务。

## 补证与更正已有审计

先按 [审计判断与反证](audit-judgment.md) 确定哪些判断被新证据改变，再更新**当前**记录：

- `audit.md` 首页结论、当前缺陷/证据缺口/可选建议及各自数量、方法/范围/未评估项，与 `run.md` 的当前说明保持一致；可选建议和已撤回问题不计入当前缺陷。建议是否保留不单独决定通过条件。
- 对受影响检查更新标准 `method/scope/status` 和 `detail_ref`，详情说明真实采用的方法、补证及结果。新增证据按实际来源/版本登记；必要时更新产物版本与 `uses`。核对的是新版对象时，不能沿用旧版目标假称已检查新版。
- 原判断、当时方法/范围、补证取得阶段及更正理由放入明确标记的历史章节或实际历史文件。不能只追加自定义裁决字段，让标准字段继续声称过时方法是当前依据；也不能把后补证据写成首次审计已有。
- 撤回 `fail` 的错误依据后，原主张仍缺证时用 `not_assessable`；未执行仍是 `not_run`。只有实际核验支持时才可 `pass`。工作 `completed` 不代表全部内容通过，不改历史指纹来掩盖文件变化。

以上是现有字段和自然语言详情的维护规则，不增加 Run 必填字段。最终记录和引用内容改完后再运行自身 `check`；历史回执只代表历史记录，结构通过不能证明更正裁决正确。

## 交付时分别说明

- 本次工作是否完成，以及实际审计范围与内容结论。
- 审计自己的目录、Run ID、自检结果和剩余错误；自动自检未运行时直接说明。
- 原件版本、尚未核验的内容及真实独立性。被审生成目录通过不能作为本审计目录的通过凭据。
