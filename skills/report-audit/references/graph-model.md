# 多图模型与跨图映射

两个 Skill 是用户入口。实际图属于本次 Run 的工作资产，包只提供方法和共享契约。允许一个轻量语义索引承载多个视图；不要求每图独立文件、服务、Agent 或固定阶段。

| 视图 | 对象与关系 | 生成侧职责 | 审计侧职责 |
|---|---|---|---|
| Goal / Audience / Context | 要求与目标来源、受众知识/权责、候选、手段/目的、冲突与用户选择 | 从材料与可能效果双向发现目标，操作化为必答问题，随新证据重议 | 核对目标偷换、角色臆测、潜在效果与动机混淆及选择越权 |
| Hypothesis | 候选解释、竞争解释、未知、区分条件 | 开放发现与修正候选 | 从资料挑战遗漏、锚定和无依据解释 |
| Evidence / Argument | 来源、观察、主张；支持、反驳、限定与推理前提 | 建立适当强度的论证 | 检查支持是否充分、同源重复、反证和条件 |
| Obligation | 使主张或正式要求成立还缺什么 | 请求最有价值的资料，必要时派工作 | 新增遗漏的证明义务；不把清单完成当充分 |
| Task | 实际工作、输入、完成条件、执行前置、结果 | 按真实依赖使用宿主工具/Worker | 检查是否执行、输入是否适用、结果能否被接纳 |
| Content Blueprint | 问题、内容单元/模块、主线与备份 | 收敛为完整判断和有依据的关系 | 检查离题、跳步、遗漏与结构损失 |
| Narrative / Page | 认知先决、讲述顺序、共同观察、页面元素 | 安排听众理解过程与表现形式 | 从实际产物重建含义，检查视觉新增的暗示 |
| Version dependencies | 对象使用哪些精确版本 | 识别局部影响并重新核查 | 阻止旧检查被误贴到新产物 |

能力选择决定当前需要哪种方法；Context Assembly 为规划、执行、综合和审计选取必要资料；宿主负责真正运行。它们不因有一张架构图就成为已实现的自动服务。

## 三种关系分开

- `links` 是语义关系：支持、反驳、限定、回答、竞争、先后等。可交叉、循环或未决，不自动成为因果、执行前置或可信度分数。
- `uses` 是版本有效性依赖，方向为消费者 → 所用输入的精确版本。重要反证/限定若影响判断，也应纳入依赖或明确影响范围。它不替代“为什么支持”的解释。
- Task `prerequisites` 是当前执行快照中的前置工作，须无环。Task `input_refs` 是其明确输入版本依赖。完成一项工作只产生工作结果，不自动改变假设或主张的证据状态。

不同视图可引用同一对象。避免一份事实在几张图里分别编辑；正文、机器状态与版本各保留唯一权威位置，详见 [工作区契约](workspace-contract.md)。

## 跨图接纳

目标、问题表示与证据之间允许反馈，不是一张单向工作流。新解释可提出新目标建议；用户选择改变内容职责和必要证据；反证可迫使前提和表达重审。[目标发现](goal-discovery.md)与[解释探索](insight-discovery.md)提供具体操作。

Goal 被采用、Claim 在限定范围内核验、Task 完成、沟通效果实际发生互不替代。目标决定可以保存在可定位笔记；需要版本影响查询才登记相应版本化对象并建立 `uses`。不新增强制目标状态，不以证据 `verified` 代替选择。

1. 候选解释形成待审主张时，保留候选状态、适用条件与证据义务。
2. 义务只有确实需要工作才能解决时才派生 Task；已有材料的简单核对不需大型任务图。
3. Task 输出先核对来源、版本、口径、方法和限制，再接纳为可用证据。没找到数据、工具失败或任务完成都不直接证明/反驳假设。
4. 证据和论证进入内容、叙事、页面时，保留强度、反证和限定；内容与页面允许多对多。
5. 审计依据原资料和实际产物提出自己的判断，可以挑战任何层、增加新义务，不覆盖生成图来制造一致。

## 有界更新

数据/口径变化通常影响相应观察、主张和表达；目标/受众变化影响取舍与顺序；仅改布局未必需要重算数据。使用明确依赖定位候选影响，再判断需要哪种复核。没有足够细粒度引用时保守标记相关产物，不虚称精确到某页。

包内校验器只提供只读影响集合。它不会监视输入变化、决定哪份业务数据最新、更新记录或执行重算。简单任务可以仅用自然语言描述这些关系；关键数值、比较/因果、风险与必答义务仍应能追溯。
