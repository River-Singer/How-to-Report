# 从零散记录到有内容的概括

本方法负责来源提炼、关系辨认和含义保真，不负责整场叙事或执行顺序。记录多而杂、概括缺少解释、同主题状态不一或压缩可能改义时使用。简单清楚的句子直接编辑。

## 找出本次问题需要的记录

围绕已采用的听众问题，辨认谁对什么做了什么、现在是什么状态、相对什么参照，有哪些解释、条件或请求。按意思辨认，不按标点拆句，也不要求每条填满字段。保留可回取的材料定位；材料未说、相互冲突和范围不明都不能改写成确定事实。

对聊天、改稿和多版材料，核原句的说话者、活动对象、适用范围与后续更正。历史“我”不自动是当前汇报者；工具名、旧稿署名或角色代言不证明实际职责。编辑图稿与管理图中机制是不同活动，前轮模型建议也不因换业务代表就成为“技术侧提出”。切换身份只改叙述侧重，不增加亲历、转移归属或恢复旧职责。已有个人判断、推进与协作作用应保留；身份确实影响个人贡献页且资料不能确定时才问，其他地方可用有据的团队或职能表述。

来源声称的关系、当前推测与已经核验的关系有不同身份。原文写因果只证明它这样声称；缺乏关系支持时不要自动降格成“相关”或“可能影响”，因为二者仍声称关系。可分别写事实；确有假设则保留其假设身份。

## 跨记录归并，再写统摄句

先问这些记录共同回答什么：覆盖了哪些对象、哪项工作到了什么状态、阻碍是什么、采用了什么做法，还是哪个选项更合适？同词出现不等于共同回答；同一事项散落不同段落也可以归并。

1. 找出可共享的背景，合并重复记录；保留会改变判断的对象、状态、例外和条件。
2. 用统一的问题或比较标准组织一组信息。为听众补出资料已支持的对应关系：什么输入经过谁的处理成为何种结果，哪些选项按同一标准比较，或哪项未决影响哪项安排。事实、条件和请求可以共同回答“下一步如何推进”，不必为分类纯净拆散；但不得把工具、活动和预期收益伪装成同级已实现成果。
3. 用自己的话写这组材料共同说明什么，再回查每个组成部分。概括可以是原文没有的统摄句，但其含义必须由已有材料支持；不能借“重新组织”新增事实。
4. 保留支撑或区分概括所需的细节，移走不服务本次问题的分类。细节可以是一项操作、一次对照或一个关键例外，按本次问题选，不是只保留异常、亮点或数字；少数例子也不代表穷尽全部类型。是否已让听众理解，由主工作流用实际成稿检验。

例如“一线访谈已完成、规则清单仍在定稿”可以归为需求工作进展，不能缩成“需求已确认”。“积极开展调研”只是抽象标签；覆盖谁、发现什么、哪些还未定，才构成有内容的概括。一次访谈与一项规则不是同一计数单位，不按行数或共有主题相加。

删除前检查该信息是否支撑后续判断，或使听众能够理解、核查、使用它。可以删无关明细，不能只因最终建议不变就删掉必要解释。标题、表头可以承担共有对象和期间；内容被独立摘出或转成口头稿时，要补回缺失的上下文。连续过程见[合成教学](content-decisions.md)。

## 把概括展开为可理解的关系

“实现数据协同”“支持变更”可能是概括，却还没告诉听众具体怎样工作。沿当前判断找尚未回答的必要问题，再回资料取出对应关系。流程解释交代输入怎样变化、谁处理、何种结果可用；差异解释交代同一对象在什么条件下为何不同；采用建议交代可用范围、证据及仍需满足的条件。按实际困难选，不给每段套全套项目。

具体化时用一个有来源的对象或实例把关系走通，再说明它支持哪部分判断。若资料只给出设计，就解释设计和待验证处；给出观察记录，才据其范围说明观察到了什么。一个案例可以澄清规则，不代表全部案例都适用；更多细节不能弥补缺失证据。与听众理解无关的对象属性、历史和术语不为显得专业而加入。

子问题有据的依赖要连起来，不能把规则、实例与结果留给读者拼接；只有记录日期先后，就按发生次序叙述，不补成全链前置。检查日志要说明哪项观察支持哪个判断、适用哪个版本，整表照搬不能代替这层解释。一项比较可以包含多个对象，必要过程也可分段展开。见[丰富资料的短长对照](../assets/examples/report-depth-proposals.md)，页组位置由[会议表达](meeting-expression.md)决定。

## 概括不等于判断已经成立

概括回答“材料合起来说了什么”；推断回答“据此能判断什么”。前者有记录支持不保证后者成立。完成了访谈不等于范围已经批准，问题关闭数量不等于剩余风险不重要。

先保留忠实概括，再将新增解释、用途、建议及其条件交给[论证方法](method-argument.md)；主动新增区别的检查与深化由[解释探索](insight-discovery.md)承担，两种检验不互相替代。不要为了贴合预先目标而删反证，也不要因尚无收益数据丢弃有依据的用途说明。

## 含义保真的共同标准

生成、编辑和审计共用以下对读方法，用于重要的新概括、改动或疑点；顺序由主工作流负责，不逐句建账。

1. **定位两端。** 取实际稿中要判断的完整句及必要上下文，再取支撑它的原记录片段，包含说话者、适用版本和后续更正。多记录合成要看关系怎样连上，不能因专名、数字或来源编号相同就通过。
2. **找出多说或少说的部分。** 比较主体在做什么、何时做到哪一步、对象与范围、条件和关系。若有疑点，尝试“来源仍真，这句话却可能为假”的情形；它定位的是新增断言，不是本项目新事实。省掉决定性条件也会改义。
3. **直接改这句话。** 保留支持的意思，删去无据部分，或将确为建议的部分写成建议；缺事实就缩小断言或请求具体记录。不要只添加出处、口径标签或尾部警句。改完再对原记录，检查修复是否又说了相反事实，并同步同一断言的受影响表述。已正确的句子可保留，不为显示核对而制造改动。

对读时按实际变换使用下列标准；不要求每句走全表。有据解释、带假设的预测与明确建议均可保留，困难推论用[概念](method-concepts.md)或[论证方法](method-argument.md)。

- **对象与归属**：保留行动者、活动对象及组件边界；当前代表不增加历史成员，职责更正不合成新角色。观察、设计与建议跟着对应版本和原说话者，不因出现在旧稿中成为已实现事实。
- **状态与范围**：保留完成、进行、拟议、预测、待答复，以及数量、期间、部分/全部和频率。区分缺资料与未做：未附记录不证明未测，未获答复不证明未安排，未完成不排除已开始；禁止正面断言也未确认相反事实。完成终点有验收要求时，提交或记录齐备不能改成验收完成。
- **比较与计量**：保留单位、基线、定义和相同所修饰的对象；费用项目相同不说明预算足够，容量不证明实际覆盖。两个正确数字不自动可合计；数值与待定状态不能统称同类数值。日期差不自动是工作量或历史估算；按[数值方法](numeric-evidence.md)核算有定义的量。
- **关系**：方向及依据须匹配。时间先后不证明依赖或因果，角色列表不说明执行频率或流水线顺序，两个前提并存不说明互为前提。已知阻碍不必是唯一原因，“增人不能替代批准”也不等于“与工作量无关”。已有且影响行动的依赖应保留，不能删成互不相干的状态；相关也不是同义。
- **条件与强度**：分别核必要性和充分性，“满足后就能”与“全部完成后才能”都需依据。预测、用途与职责分别不变承诺、实绩与结果保证。例子或局部检查不扩为全体能力；机制说明不变效果证明。可以按适用假设提出估计，不因尚未完成而禁止估计。
- **请求与意见**：知悉、建议、批准请求与已授权行动有不同含义。共用期限约束的余项仍保留；收到答复、条件满足、计划可执行与备选触发分别核据。新增跟进可以是建议，不能冒充原请求的前置或权限。来源意见也不变作者独立验证。

保留影响本次判断的反证和正式必答。上层标题和结尾应受下层内容支持，流畅和句式平行不证明含义未变。不要求逐字保留，也不禁止正当专业词。发现问题修最早出错的归并、关系或概括，不用末尾免责声明替正文纠错。叙事/详略由[会议表达](meeting-expression.md)负责，措辞由[观众编辑](audience-copy.md)负责。

归并思路的来源和研究限制见[阅读与摘要研究](method-sources/sources/reading-synthesis.txt)。它提供编辑启发，不是中文汇报或本Skill效果已获验证。
