# 用本场职责提出定向挑战

本方法服务生成主线B：在目的与[真实角色](stakeholder-roles.md)确认、当前主张已有依据后，由主 Agent按[委派契约](agent-delegation.md)派发挑战。新的完整汇报要对重要未解判断进行相关角色挑战；局部改句或已解决范围不重跑全量。没有真实能力时说明该环节未完成，不用自查替代。

## 挑战者：寻找能阻断已确认目的的问题

局部目标是用本次事实和逻辑寻找最强的相关阻断：为什么这位真实角色可以在其职责内不接受当前请求、评价或解释？目标可能是批准、认可、行动或正确理解，不能擅自缩成费用审批、财务收益或进度问责。承认成立的有利事实；不预设反方必胜，不以质疑数量证明深度。

第一次派发取得目的及优先级、场合、分配角色与实际权力/影响、本场需要形成的认识/判断/行动、当前主张或请求及其实际强度、相应原资料和已知限制。交清本场要支持哪一步，哪些后续实施事项尚未承诺。尚无页面可挑战候选论证，明确对象版本。原资料与当前稿供挑战者独立核对，预设反对答案、整段创作历史和通过标签留在派发范围之外。

### 先选择会阻断本场目标的路径

从该角色已确认的本场职责出发，沿“本场必要认识、判断或行动 → 支撑它的当前主张 → 必要前提 → 适用证据”定位候选断点。将一个候选异议暂按成立处理，检查哪项本场必要判断会因此失去依据，以及其余成立的理由能否继续支持目标。对方会学错关键机制、作错当前选择、接受无据承诺或无法执行本次请求，都可能形成相关阻断。局部理由被否定时，按它对整体回答的实际影响确定处理范围。

再对照本场阶段与当前主张强度核证明责任。经验交流可以形成有条件的适用认识和下一步待核事项，试用决定可以有真实可行的接受条件，正式优选、验收或系统接入则需支撑相应承诺。当前稿若把候选类比写成已验证迁移、把示例计算写成稳健优选，或把待建条件写成现成能力，应追到这项升级的必要依据。交流中的错误类比若会让听众学错主要做法，同样值得深入。细节进入挑战的依据是它对本场判断的必要作用。

挑战者也要核自己的前提。引用规则、专业标准或既有检验时，先核对象、版本、适用范围与本次用途。新增验证、发布或接受门槛须有本场要求、真实职责或当前关键主张的必要依赖作为依据。担忧误读时，定位实际措辞与合理的误读路径，再核其是否会改变本场关键认识。按[含义保真的共同标准](semantic-structuring.md#含义保真的共同标准)保留来源明确给出的观察和已确认授权范围，分别检查由此增加的推论及真实反证。

从仍成立的断点中选择一条或少量最强路径，再按判断问题选用已授权[专业知识](../knowledge/index.md)及[思维方法](reasoning-methods.md)，实际比较范围、拆解成本、核依赖或检验推断。每深入一层，都核答案能改变当前哪项判断、承诺、重要条件或必要理解。同一角色内共享必要前提与失败后果的问题合并追问，独立后果仍分别保留。已经足以判断该路径时收束，后续实施细节按其实际用途留待对应阶段。知识用于分析操作，项目参数和制度仍来自本次资料。运行期保持本地授权资料范围，不联网寻找反对材料。逻辑反例只检验推断充分性。上述选题在内部完成，返回沿下节的仅问句契约。

## 返回只有实质问题

每项以“？”结尾，可在问句内带必要原句或来源定位。不给诊断结论、分析表、修复步骤、推荐结构、参考答案或补件指令，不把建议改成疑问语气。主 Agent必须自行面对问题、选方法、查算和修改。

- 可以问：“两份报价的服务期不同，为什么能直接比较总额认定乙更便宜？”
- 不可问：“你是不是应该统一口径并加一张比较表？”——这是修法。
- 未提供测试记录时可以问：“本次性能承诺依据哪次、何种条件下的验证？”不能问“为什么从未测试？”——后者偷塞未证事实。

成功完成指定分析且无仍成立问题时返回空问题集合，不凑填充问句。空回复、失败、未读输入或无法完成不能解释成成功空集合；执行状态由宿主和主 Agent核对。空集合不保证真实听众接受。此问句限制不适用于独立审计意见。

## 主 Agent：先独立回答，确实缺事实才求助

收到问题先按上节的目标路径检验阻断效力，并核角色、原句及问题自身的前提。若异议成立，它会使哪项本场必要认识、判断或行动失效？当前稿的强度、已明示条件及其他充分依据是否已经处理了该影响？规则适用域、想象的误读和新增门槛同样需要依据。前提错误、与目标无必要关系或已被证据化解的，说明理由并排除。局部事实或措辞错误按[共同对读](semantic-structuring.md#含义保真的共同标准)就地修正，后续实施事项按实际阶段记录，将仍影响当前目标的缺口纳入回应与求助。

对成立的问题，先查已授权原资料、适用更正及附件，再用已有事实完成可行分析。保留来源明确给出的样本观察、用户授权和有根据的积极结论，在其实际范围内表达。尚未阅读或计算由主 Agent完成；工具、方法或专业核验能力不足时交清尚未完成的范围。

已有资料与适用分析仍不足以回答时，**必须向用户明确求助**，用能直接提供的记录或口头说明描述最小缺口：哪个角色问题尚答不了、已知什么、最小输入或可接受替代是什么、将支持哪个判断、不补时暂不能支持什么。不要笼统要求用户“补一份经济性分析”；分析由主 Agent完成。多角色共享同一输入合并问一次，先问最能改变本次判断的缺口，后续问题由新事实触发。

| 当前问题 | 最小输入或替代 | 主 Agent实际完成的分析 |
|---|---|---|
| 新增金额增加在哪里 | 原/新范围、费用项、数量单价、服务期；可先给报价或估算依据 | 对齐期间与范围，复算差额，分清数量、价格和范围变化；总价不能证明合理 |
| 数据是否越出系统边界 | 实际服务、部署位置、字段、日志/备份去向；已有图/配置或逐项说明 | 还原实际路径，分开确认和待核链路；“本地部署”不替代全链路判断 |
| 两项目能否共用能力 | 两项目交付、现有可用能力和接入约束 | 比较复用部分、适配与新增成本，不预设合并必优 |
| 增人能否按期完成 | 剩余工作、依赖、技能、实际可用时段和确认窗口 | 核时段/技能/前置可行性，不将人数直接折成工期 |
| 本人价值或效果依据是什么 | 本人关键判断/行动、协作分工、实际结果或作品；可先具体口述 | 连清作用、归属及受众用途，不替用户编收益或独占团队成果 |

必要事实待补时继续其他独立内容，明确该缺口影响哪一项判断。缺口不能降成“可选深化”或靠措辞消解；只有不影响当前结论成立的增强输入才是可选机会。本场允许附条件或分阶段决定时，比较这类安排是否仍能服务用户目的：哪些已有依据足以支持当下决定，哪些条件会改变范围、金额或授权，哪些仅是实施前置。不能要求所有未知先清零才能申请，也不能因已有负责人或后置条件就宣称未知无影响、不会等待。用户未知、拒绝或暂不能补时不反复催问，保留可用内容与未决，讨论可行安排，不自行替用户改变目的。

## 回到材料，有界复查

回答须改变或支持实际判断：充分支持则保留或展开，反证则修正/撤回，有条件则把必要条件写到相关正文。已获额度不自动等于已获全部支用授权；两项费用申请的实际流程以本次批复和请求为准。不做、最低限度、共用、分期是适用时比较的候选，不是每场必填表；分析深度随决定影响、不确定性和不可逆程度而定。

补件先核版本、对象及冲突，只解决已覆盖部分，其余继续未决。复查由**受影响的判断**触发，对比送查版与当前版的主张、理由、金额/范围、条件和请求。改变这些内容时，即使附件相同，也将实际变化与仍适用原资料交回相关真实挑战者。含义相同的措辞或间距调整沿用已有范围。

复查先读当前修订后的主张，检验原异议是否仍妨碍本场目标。异议被证据排除，或无据承诺撤回、主张收窄到有支持的范围后，重新看原目标及其余依据能否成立。若改变了用户目的或所求结果，回到用户确认。条件确会改变当下决定的，仍须回应；已有依据足以支持符合本场已确认目的的阶段性结果时，结束该路径。修复直接引入的新疑点也先经过目标影响检验，再决定是否追问。

只返回剩余成立的目标相关问题，共享前提由主 Agent合并分析与补件，其他独立阻断继续保留。旧返回绑定原版本与范围，未执行的新复查明确未完成。范围或预算耗尽时如实保留重要未决，主 Agent自查与挑战者实际复核各记录真实结果。

回到生成B/C时，按听众需要重新组织回答：先讲有据的意思，再用具体机制、比较或贡献解释为什么有用，把会改变判断的条件留在相应位置。已经得到回答的问题融入理由，不逐题照抄；内部问答过程与重复自证留在作者记录，必要未知交清而不铺满页面。协调真实冲突时交清选择后果及有权决定者，不用多数票或要求所有挑战者返回空集合作为结束条件。最终请求单独读仍应完整保留上限、条件与再次确认路径。仅记录可审阅的依据与未决，不输出私有思维链或新建必交挑战报告。
