# 宿主能力与声明边界

按当前任务要使用的能力检查，而非根据产品品牌假定。记录实际观察：工具不存在、未授权、未实现适配、执行失败、执行成功或尚未检查。不要为简单任务探测全部能力。纯内容交付不要求浏览器或前端能力。

| 能力 | 实际可用时 | 缺失/未验证时 |
|---|---|---|
| 文件与可见工作区 | 保存实际产物，需要追溯时建立 Run，返回真实位置 | 交付可复制文本/宿主附件，明确未持久保存 |
| 计算执行 | 保存输入版本、代码/公式、实际结果、口径和校验 | 交付方法与待执行状态，不伪造已算结果 |
| 子代理/并行任务 | 对独立问题实际派发、等待结果，由主代理核据整合 | 同一工作流串行完成；不把角色模拟说成多agent执行 |
| 独立上下文 | 提供原资料、用户要求和实际产物，记录继承情况 | 可做有限自查，不能声称盲审或完全独立 |
| 本地方法/领域资料 | 核心方法、知识卡和本地来源文字随包提供；按许可和缺口读取相关段落 | 原网址仅溯源；不要求联网，不读取拒绝/未回应/撤销的正文 |
| 外部新证据 | 仅在任务明确需要、真实有网络能力且获准时取得并记录 | 记录缺口或请用户提供材料，不假称已检索；离线核心工作仍继续 |
| 画像存储 | 在明确私有位置保存、查看、修正已确认条目 | 不假称跨会话记住，不写入安装包 |

规划一项任务不等于工具已授权。Skill 指令和许可事件只是工作协议/记录，不能代替宿主权限隔离。日志未记读取也不证明读取从未发生；需要时对照真实工具记录。

首次运行可先做一个必要的小操作，观察真实结果再声明能力。工具成功与结论成立分开；同代码复跑与独立复核分开；两包独立安装与审计上下文独立分开。云端持久化、取消运行中的工作、并发恢复等能力均需独立证据。

安装包不自动安装另一个 Skill、不联网补共享文件、不更改全局配置。升级包不应覆盖用户 Run、输入、输出或画像。具体记录格式见 [工作区契约](workspace-contract.md)。

知识来源的下载与更新属于开发维护，不是使用 Skill 的前置步骤。包内文字明确区分已归档网页正文与原创摘要，包含实际获取范围和来源条款。只有本地方法不足不能被当成允许联网、读其他卡片或上传材料的授权。

## 可选并行协作

长材料含多个可独立核实的问题，且真实宿主提供子代理工具时，可在原工作流内并行。一个标题或明确短同步直接完成；没有工具或执行失败就串行继续，不安装平台、不调用额外模型API来满足形式，也不要求用户先配置多agent。

主代理先确定共享任务边界和当前资料版本，再只拆分真正独立的问题。例如材料中的两种目标是否会改变路线、某项重要判断是否有原始依据、当前解释遗漏了什么会改变听众选择的区别；按需要选择，不固定角色或数量。依赖目标结论的问题应等目标明确后再派，不能把相互依赖的整段流程同时开工。

每项委派说明具体问题、必要原资料/定位、已确认约定、可用范围和停止条件；只给完成该问题所需的上下文。不要求完整私有推理，返回可审阅的结论、依据位置、条件/未知及其对当前内容的影响。子代理不递归扩队、不同时改写同一份成稿，也不越过原任务的数据/写入授权。规模、时限和调用预算按实际任务控制，达到边界就停止并保留未核项，不无限追问或重复派同一问题。

主代理汇合前等待已派工作的结果或确认其已停止；无法确认终止时记录仍在运行的工作，不宣称全部完成。按原资料检查冲突、共同前提与跨分支依赖，决定哪些结论采用、收窄或继续取证。多数意见、任务完成和工具成功均不使主张自动成立。最终主线、当前版本与成稿由主代理统一维护；无须交多份同义报告。

并行分析不自动是独立审计。需要正文首读时，使用未接触作者计划的独立上下文，先只给实际正文及必要边界，首读后再提供任务、来源和作者说明。宿主继承历史、不能隔离或曾参与生成的，要如实说明暴露范围；同一代理换角色只算自查。记录真实派发与返回情况即可，不靠模型自报证明独立或已执行。
